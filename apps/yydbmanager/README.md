# yydbmanager

Windows x64向けDBクライアントの初期実装です。提案全体の進捗は
[設計書](../../docs/proposal/22-dbmanager.md)に記録しています。

## 起動とビルド

リポジトリ直下から実行します。既存yyシリーズとは別のCargoワークスペース・lockfileです。

WindowsのビルドにはVisual Studio 2022のC++ビルドツールを使用します。固定しているDuckDB 1.4.1の同梱fmtは、Visual Studio 2026で削除された`stdext::checked_array_iterator`を使用するため、専用CIも`windows-2022`を指定しています。DuckDB側の[修正](https://github.com/duckdb/duckdb/pull/23261)を含む版への更新と検証後に、新しいツールチェーンへ移行します。

```powershell
cargo build --manifest-path apps/yydbmanager/Cargo.toml --release -p yydbmanager --locked
./apps/yydbmanager/target/release/yydbmanager.exe
```

SQLiteとDuckDBは静的リンクしており、別途DBサーバー・CLIを導入せず使えます。
同梱フォントは他のyyシリーズと同じUDEV Gothicです。
アプリアイコンも共通のYYデザインを使い、青緑の背景とデータベースの記号で識別できます。

## ヘルプ

「ヘルプ」メニューまたはF1で、使い方、実行計画の読み方、Oracleの権限、Db2の収集モニター準備、実測取得のトラブル対処を確認できます。説明は実行ファイルに同梱し、未接続・オフラインでも閲覧・選択コピーできます。Db2の準備SQLはヘルプとSQLタブで同じ内容を表示します。本文は [help/help.md](help/help.md) で作成し、他のyyシリーズと同じ埋め込みMarkdown・共通プレビューの別ウィンドウ表示です。目次と見出しへの移動、コピー、Esc／Ctrl+Wで閉じる操作に対応し、WebView2が使えない環境ではテキストに切り替えます。YAMLの全項目・列挙値・制約・完全なサンプルは「ERモデルYAMLの仕様と読み込み」から確認できます。

## 現在の操作

SSMSを基準に、上部にメニューと主要操作のアイコン付きツールバー、右にオブジェクト エクスプローラー、中央にSQLタブ、下に結果／実行計画を配置しています。

1. 右側のオブジェクトエクスプローラーの「新規接続…」、またはツリーの右クリックから接続先を登録します。接続名とDB種類を指定し、SQLite／DuckDBはファイルパス、外部DBはドライバー・サーバー・ポート・DB名・ユーザー・パスワードを項目ごとに入力します。保存した接続名をダブルクリックすると接続します。
2. 接続先の編集・削除・接続、接続中DBのオブジェクト一覧再取得はツリーの右クリックメニューから行います。接続文字列を主画面に常時表示せず、パスワードと詳細接続文字列は設定画面でも伏せて表示します。旧版の暗号化設定も読み込めます。
3. SQLを入力し、F5または「実行」を押します。範囲を選択した場合はその範囲を実行します。「ファイル → SQLを新規作成」で編集タブを増やせます。現在は同じ接続セッションを共有します。
4. SQL実行結果は下の「結果 1（○行）」などのタブで切り替えます。選択したタブが表示・エクスポートの対象です。結果がない間はタブを表示しません。ホイールで縦方向、Shift＋ホイールで列方向に移動します。結果は一時ファイルに保持します。
5. 接続後に右側のツリーへスキーマ・オブジェクト種別・名前を表示します。テーブル／ビューは展開時に列を取得し、ダブルクリックでSELECTを新規SQLタブへ入力します。SQLは自動実行しません。ツリーの右クリックメニューの「オブジェクト一覧を更新」で一覧を取得し直します。
6. 計画図はCtrl＋ホイールでマウス位置を中心にズームし、ホイールで縦、Shift＋ホイールで横に移動します。空白のドラッグ・スクロールバーで移動でき、右下の＋を押している間はミニマップを表示します。右クリックで倍率指定・全体表示・検索・原文表示／保存を選べます。ノード／線をクリックすると右側にプロパティを表示し、プロパティのダブルクリックで値の全文を開きます。ER図のホイールはズームです。
7. 「実行計画」メニューで推定／実測取得、SQL ServerのShowplan XML（`.sqlplan`）や保存した`.yyplan`の読込、生計画を含むモデルの保存を行います。実測取得はSQLを実際に実行します。
8. 「表示 → ER図 → DBからER図を取得」で7DBのER図を作成します。表をドラッグして配置し、空白ドラッグで移動、ホイールでズームします。「表示する表を選択」で表・ビューを絞り込み、F2または右クリックで表／列の論理名を編集できます。物理名／論理名／両方、表名／主キー／列／型の表示を切り替えられます。
9. ERモデルは`.yyer.yaml`で配置・論理名・表示対象・キー情報を保存し、メニューまたは起動引数から再読込できます。SVG／yydrawは図の出力用です。「クエリ」メニューにはCOMMIT／ROLLBACKを格納しています。

「表示 → ER図 → モデルを編集」で表、列、主キー／一意キー、索引、リレーションを追加・編集・削除できます。列は物理名・論理名・型・NULL許可・既定値のSQL式を編集します。複合キーと索引は構成列を選んだ後に列順を指定し、リレーションは参照先キーの各列へ参照元列を対応付けます。列名・表名の変更は関連定義へ追従します。使用中の列・キー・表の削除はエラーになります。

ERの編集と配置変更は最大32操作まで元に戻す／やり直しが可能です。ER領域へフォーカスがあるときのCtrl+Z／Ctrl+Y、またはERメニューで操作します。SQLエディタのUndoとは別の履歴です。保存は独自YAML形式（コンテナー1・内部モデル4）で、定義・主要項目・論理関係・配置・サイズ・表示状態を保持します。旧JSON形式1～3も読み込みます。

「DDLをSQLタブへ生成」はモデルのDB方言でCREATE TABLE・主キー・一意キー・外部キー・CREATE INDEX・既定値・NOT NULLを出力します。参照先の表は非表示でも含めます。SQLiteは外部キーを表定義内へ置き、DuckDBは親から順に作成し、自己参照／循環はエラーにします。外部5DBは表作成後にALTER TABLEで外部キーを追加します。生成時にDBへSQLを送信せず、新規SQLタブに表示します。逆生成したモデルは型の桁数、生成列、既定値、照合順序、CHECKや既存索引を完全には保持していないため、元DBの完全な複製用DDLではありません。生成SQLの注記と定義を確認して利用します。

ERの表カードはPK／UQ／FK、型、NOT NULL（`*`）を表示し、キーと一般列を分けます。リレーションは構成列の先頭へ接続し、○は任意、棒は1、三つ又は多を表します。複合キー全体の対応は右のプロパティで確認できます。親に対応する子の最小件数はDB制約だけでは保証できないため0とし、一意キーと列のNULL許可から基本的な多重度を判断します。SQL Server／Oracleの無効・未検証の外部キーは描画対象から除外します。

実行計画は白背景の演算子アイコン、左向きのデータフロー、SQL Serverの推定コスト比率、各DBの推定／実測行数、警告とツールチップを表示します。コスト比率は実測時間の比率ではありません。`.sqlplan`／`.yyplan`を起動引数に指定すれば、DBに接続せず保存計画を開けます。PostgreSQL／MySQLではループ平均時間・行数・ループ回数、DuckDBでは演算子時間・行数も表示します。MySQL 8のJSON v1/v2推定計画とTREE実測計画、Oracleの述語・推定秒・bytes・パーティション、Db2の述語・timeron、SQLiteのSCAN/SEARCH/一時B-treeを共通の図で確認できます。統計の単位と取得範囲は[DB別の検証](../../docs/verification/yydbmanager-cross-database-plans-2026-10-21.md)を参照してください。SSMS・A5:SQL Mk-2との到達点と不足は[比較検証](../../docs/verification/yydbmanager-ssms-a5-2026-10-21.md)を参照してください。

Oracleの実測は同一接続で`statistics_level=ALL`を一時設定し、終了後に元へ戻します。`V_$SESSION`・`V_$PARAMETER`・`V_$SQL_PLAN_STATISTICS_ALL`の参照とALTER SESSION権限が必要です。SQL_ID・child番号で実行カーソルを識別し、行数・starts・経過時間・バッファ・ディスク・メモリ統計を表示します。

Db2の実測は既存の稼働中の`YYDBMANAGER_ACTIVITY`イベントモニターとEXPLAIN表を使います。「実行計画 → Db2実測収集の準備SQL」でDB管理者向けSQLを新規タブへ開けます。準備SQLは自動実行しません。接続単位の収集設定を一時変更して復元し、EXPLAIN_FROM_ACTIVITYが返したキーで演算子の実測行数を取得します。演算子時間は取得しません。[権限・準備・検証](../../docs/verification/yydbmanager-oracle-db2-actual-2026-10-21.md)を参照してください。

接続設定は`%APPDATA%/yydbmanager/connections.dat`にWindows DPAPIで暗号化して保存し、同じWindowsユーザーで復号します。別ユーザー／別PCへの持ち出し用の接続設定ファイルではありません。試験時は`YYDBMANAGER_CONNECTIONS_FILE`で保存先を分離できます。

ツリーはSQLiteのmainスキーマ、Oracleの現在のスキーマ、MySQLの現在のDB、その他のDBのアクセス可能なユーザーオブジェクトを対象にします。テーブル・ビュー・インデックスと、DBに応じて関数・プロシージャ・シーケンス・トリガー等を表示します。接続ユーザーの権限によって表示範囲が変わります。

SQLの編集・Undo/Redo・選択・IME・ハイライト・描画はyyeditorの共通資産、結果の描画はyysheetの格子、ER・計画はyydrawの図モデルと描画を利用しています。

## 性能分析SQLをメニューから開く

性能分析のSQLを自分で書かずに始める場合は、右側の接続先を右クリックし「性能分析SQL（DB名）」から選択します。全7DBに対応し、そのDBで利用できる監視SQLを必要権限の説明とともに新しいSQLタブへ表示します。内容を編集・確認してから対象接続先へ接続し、F5で実行してください。既存のSQLは上書きせず、メニュー選択だけでは実行しません。詳しい指標・権限は「ヘルプ → DB別の性能分析ビュー…」で確認できます。

## 他の環境の実行計画ファイルを開く

「実行計画 → 実行計画を開く…」で、DB接続やODBCドライバーなしで表示できます。SQL Server Showplan XML、PostgreSQL EXPLAIN JSON、MySQL EXPLAIN JSON／TREE、DuckDB JSON、Oracle PLAN_TABLE CSV、Db2の指定8列DEL、SQLite EXPLAIN QUERY PLAN CSV／JSON、全DBの`.yyplan`に対応しています。UTF-8またはBOM付きUTF-16、32MiB・1万ノードまでです。

DBごとの取得SQLとCLIの操作は「ヘルプ → 実行計画ファイルの形式と取得方法…」にあります。[持ち込み用サンプル](../../demo/yydbmanager/plans/README.md)も接続なしで開けます。`yydbmanager.exe --open-plan "C:\plans\mysql.txt"`による起動にも対応します。画面をコピーした罫線付きテキスト等は対象外です。

## ER図をゼロから作成する

1. 「ファイル → ERモデルを新規作成…」で対象DBを選びます。DB接続は不要です。
2. 空の図を右クリックし「テーブルを追加…」で物理名・論理名を入力します。最初のid列と主キーは自動で追加されます。
3. 表を選び、右クリック →「モデルを編集」で列・キー・索引・リレーションを追加・編集します。
4. 表をドラッグして配置し、「ファイル → ERモデルを保存…」で `.yyer.yaml` に保存します。
5. SQLが必要な場合は「表示 → ER図 → DDLをSQLタブへ生成」で出力します。DBに反映するには、接続先と生成SQLを確認してから実行します。

## 主要項目・論理リレーション・設計書

- 表を選択し、右クリック →「主要項目を選択…」で主要項目をまとめて指定できます。列の編集画面にも主要項目のチェック欄があります。フラグは `.yyer.yaml` に保存し、列名変更・Undo／Redoに追従します。
- ERメニューの「表示水準 → 主キー・外部キー・主要項目のみ」、または図の右クリックの同名項目で絞り込みます。論理関係の接続列と参照先列も残します。PK／FK／LF（論理関係）／★（主要項目）を区別します。
- 参照元の表を選び「論理リレーションを追加…」で参照先の任意の列と対応する参照元列を指定できます。複合列も扱います。主キー・一意キー・外部キー制約のない列同士も登録でき、紫の破線で表示します。論理関係の存在・件数はDBでは保証されず、DDLには外部キー制約として出力しません。既存の「リレーションを編集／削除」から論理関係も編集・削除できます。
- 「名前から論理リレーションを推薦…」は物理名、論理名、`customer_id` と `customer.id` のような表名付き列名を照合します。参照先候補はキー列または主要項目とし、型の整合を確認します。裸の `id`・`name` 等だけでは推薦しません。既存の列対応を除外し、最大200件を未選択で表示します。曖昧な同名候補も自動確定せず、人が意味を確認して選択・登録します。
- 「ファイル → Markdown設計書をエクスポート…」で、表示対象テーブルの一覧と各設計書へのリンク、Mermaid ER図、全列の物理名・論理名・型・NULL許可・PK／FK／LF・主要項目・既定値、キー・索引・関係を1つの `.md` に出力します。設計書は全列を保持し、ER図は表示水準によらず主キー・外部キー・主要項目・関係の接続列に絞ります。Mermaidの実線は外部キー制約、破線は論理関係です。

MermaidのER構文は[公式仕様](https://mermaid.js.org/syntax/entityRelationshipDiagram.html)に基づき、同梱Mermaidで実際に描画して検証しています。

## ERモデルのYAML保存・読み込みとサイズ変更

- 「ファイル → ERモデルを保存…」で `.yyer.yaml` に保存し、「ERモデルを開く…」または起動引数で復元します。`.yaml`・`.yml`・旧JSONの `.yyer` も読み込めます。
- 非表示の表・列を含む全モデル情報、主要項目、物理／論理関係、複合列の順序、配置・サイズ・表示設定、DPI基準の倍率・表示位置・選択中の表を保持します。未知の項目や未対応バージョンは、黙って欠落させず読み込みエラーにします。形式の完全な仕様と読み込める例は埋め込みヘルプに記載しています。
- 箱の右下ハンドルをドラッグ、または右クリック →「テーブルのサイズを指定…」で手動変更します。ドラッグ中は枠を表示し、離したときに内容と線を更新します。Escで取り消せます。
- 「コンテンツにサイズを合わせる」「すべての表をコンテンツに合わせる」で、名前・列・型の長さと列数に追従する自動サイズに戻します。文字の大きさは変更しません。自動／手動の指定もYAMLに保存されます。

## インポート・エクスポート

「ファイル → データをインポート／結果をエクスポート」を選ぶと、ファイル形式の設定画面が開きます。区切り文字は「任意区切り」、文字コードは「COBOL固定長」の場合だけ編集できます。「ファイルを選択…」でデータファイルを選び、固定長の場合は続けてコピー句を選びます。キャンセルした場合は処理を実行しません。エクスポートの対象は主画面の結果タブで選んだSQL実行結果です。

| 形式 | 現在の仕様 |
|---|---|
| CSV | UTF-8、見出しあり、CRLF、RFC 4180の引用・エスケープと項目内改行 |
| TSV | タブ区切り、CSVと同じ引用規則 |
| 任意区切り | 形式の右隣の欄でUnicodeの1文字を指定。引用符・改行は指定不可 |
| Parquet | Arrow／Parquetで読み書き。十進数をDECIMALとして保持。混在型はエラー |
| COBOL固定長 | データファイルに続いてコピー句を選択。右の文字コード欄はMS932、CCSID930等。現在のGUIは区切りなし・単一レイアウト |

CSV等では未引用の`\N`をNULL、引用された`"\N"`を同じ文字列として区別します。
NULLマーカーはRFC自体が定める意味ではなく、このアプリの交換規則です。
固定長は変換不能文字・桁あふれ・小数桁切り捨てをエラーにし、NULLの暗黙変換はしません。
ファイル出力は一時ファイルを経由し、失敗時には既存ファイルを保持します。

取込先は現在、入力ファイル名から作る新規テーブルです。SQLite／DuckDBでは列を文字列として作ります。外部DBでは数値のメタデータを利用し、文字列には上限があります。既存表がある場合はエラーとし、上書きしません。外部DBの取込は専用接続で行い、SQL編集側のトランザクションをコミットしません。作成DDLが暗黙確定するDBでは、投入失敗時に空のテーブルが残る場合があります。

## 検証

```powershell
cargo test --manifest-path apps/yydbmanager/Cargo.toml --workspace --locked
cargo clippy --manifest-path apps/yydbmanager/Cargo.toml --workspace --all-targets --locked -- -D warnings
./apps/yydbmanager/target/release/yydbmanager.exe --smoke-test target/yydbmanager-smoke
./apps/yydbmanager/target/release/yydbmanager.exe --ui-smoke-test target/yydbmanager-ui-smoke
./apps/yydbmanager/tests/windows-shell.ps1 -Executable ./apps/yydbmanager/target/release/yydbmanager.exe
```

`--smoke-test`は同梱エンジン、SQL、精度、Parquet、計画を試験します。
`--ui-smoke-test`は非表示のネイティブウィンドウを起動し、接続・SQLタブ・結果・計画・ER・ツリー・列展開・3サイズでの再配置／再描画を検証します。`windows-shell.ps1`はメニュー、接続の保存／削除ダイアログ、暗号化設定の再読込、最大化／復元を操作して画像と結果を保存します。接続設定は試験用フォルダーに分離します。GUI試験はWindows専用です。

`YYDBMANAGER_PLAN_FIXTURE`へ`tests/fixtures/sqlserver-hash-sort.sqlplan`の絶対パスを設定すると、UI試験で複合計画のズーム・選択・プロパティ・ツールチップ・パン・ミニマップ・検索も確認します。シェル試験は`-PlanFile`で同じファイルを指定できます。専用CIにも組み込んでいます。

通常のUI試験ではERの選択・関連線を伴うドラッグ・保存再読込・表示切替・整列も検証し、`edited-er.yyer.yaml`を出力します。シェル試験へ`-PlanFile target/yydbmanager-ui-smoke/edited-er.yyer.yaml`を渡すと、表選択と論理名編集の実ダイアログも検証します。500表・2,000関連の描画測定は明示的に`cargo test --manifest-path apps/yydbmanager/Cargo.toml --release -p yy-db-core --lib er_viewport_performance -- --ignored --nocapture`で実行します。

外部DBの実接続試験は[Docker検証](tests/docker/README.md)を参照してください。通常テストではこの試験を明示的にignoreとし、未実行を接続成功と扱いません。

2026-10-20に外部5DBの実接続・SQL・型付き投入・CSV／Parquet往復・推定計画を確認済みです。実測計画とプラットフォームごとの範囲は[検証記録](tests/docker/results/2026-10-20.md)に記載しています。

## 残る実装

- PostgreSQL／MySQLの専用プロトコル接続（現在はODBC経由）、複数DBへの同時接続、SQLタブごとの専用セッション。
- 方言別の完全なスクリプト分割（GO、PL/SQL、DELIMITER）、補完、現在文実行、実行履歴、更新可能な結果。
- Db2の演算子別実測時間、実行計画の比較・自動シナリオ分析・SQLとの選択連動・全演算子の個別アイコン。
- ER逆生成時の完全な型修飾・既定値・生成列・CHECK・索引情報、DBコメントの論理名への取込、ページ印刷、他の表を避ける配線、削除規則や遅延制約等の編集。
- 入出力プロファイルと列マッピング、文字コード・NULLのGUI設定、COBOLマルチレイアウト、Parquetの日時・入れ子型の完全な型対応。
- 結果の逐次表示、ODBC実行中の取消、ファイル変換の取消、手動トランザクション状態表示、大規模性能評価。

現在の「停止」はSQLite／DuckDBの実行取消と行取得時の取消確認です。ODBCのサーバー実行中取消とファイル変換の中断は未対応です。DuckDBはエンジン側が結果を実体化するため、結果全体に対するメモリ上限はまだ保証していません。

専用CIは`.github/workflows/yydbmanager.yml`、配布物名は`yydbmanager-windows-x64`です。


ER図のテーブルを選択し「列定義をまとめて編集…」を開くと、yysheet共通のグリッドで物理名・論理名・型・NULL許可・既定値・主要項目を一括編集できます。Excelとの矩形コピー／貼り付け、Tab／Enter移動、行の追加・削除・移動、Undo／Redoに対応します。適用時に参照整合性を検証し、列名変更はキー・索引・物理／論理リレーションにも反映します。操作方法はアプリ内ヘルプを参照してください。


ER図はSQLクエリと同じ文書タブ列の「ER図」タブで作図します。SQL入力・結果・実行計画の画面と切り替えて使用でき、図の定義、配置、選択、表示位置、ズームとUndo履歴を保持します。SQLのバックグラウンド完了でも編集中の図を保持します。型定義は個別・一括編集のどちらもDB種類別の編集可能なプルダウンで選択でき、桁数の直接入力とExcelとのコピー・貼り付けも可能です。
