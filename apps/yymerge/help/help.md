# yymerge ヘルプ {#top}

yymergeはYYシリーズ共通のUDEV Gothicとエディターを使う、ファイル比較・3方向マージツールです。GUIはWindows専用、CLIと比較コアはWindows / Linuxに対応します。

## はじめに {#start}

`yymergew.exe`を起動し、[ファイル] → [2方向比較を開く] でLEFTとRIGHTを選択します。入力は読み取り専用です。黄色の行は変更、薄赤はLEFTのみ、薄緑はRIGHTのみ、灰色の行は対応する行がない表示上の空白です。変更行の中では、共通の前後を除いた相違範囲をさらに強調します。改行だけの違いは行の背景で示します。右側の差分一覧を選ぶか、F7 / Shift+F7で移動できます。マウスホイールで縦スクロール、Shift+ホイールで横スクロールします。

比較は文字の正規化をせず、改行（CRLF / LF）、終端改行、BOM、文字コードも対象にします。表示上同じでもBOMや文字コードだけが違う場合は「相違あり」となります。

LEFTとRIGHTは対応する行が同じ高さになるように整列し、縦・横スクロールが連動します。空白は表示だけのもので、原文・コピー・保存内容には入りません。ドラッグまたはShift+矢印で範囲を選び、Ctrl+Cで原文をコピーできます。Page Up / Page Downで画面単位、Ctrl+Home / Ctrl+Endで文書の先頭・末尾へ移動します。長大行は既存エディターと同じ表示セグメントに分割し、内容を切り捨てません。差分の位置へは一覧またはF7で移動できます。

3方向マージではBASEを基準にLEFT・RIGHT・RESULTの4ペインを整列し、縦・横スクロールが連動します。各ペインの行番号は、それぞれの原文の行番号です。高さの異なるペインでも末尾を揃えて読めるよう、最後の行を上端までスクロールできます。表示上の空白はファイルには入りません。セッション保存は未実装です。

RESULTを手動編集すると、そのペインの整列を一時解除し、入力が約350 ms止まってからバックグラウンドで再計算します。再整列は本文、選択、Undo履歴、競合の解決状態を変更しません。古い編集状態での計算結果は破棄します。ステータスに「整列を更新中」と表示されている間も編集・保存できます。

整列計算の上限を超えた場合は、RESULTまたは全ペインを個別表示し、ステータスに「整列は未完了」と表示します。自動マージの成功や競合の解決を意味する表示ではありません。[比較] → [3方向マージの整列を更新] で再実行でき、[停止]で計算を中止できます。祖先基準の整列は100万行までです。

## 3方向マージ {#merge}

1. [ファイル] → [3方向マージを開く] を選択します。
2. BASE（共通祖先）、LEFT（自分側）、RIGHT（相手側）の順にファイルを指定します。空のBASEも有効ですが、存在しないBASEはエラーです。
3. 独立した変更と両側の同じ変更は自動統合します。同じ場所への異なる挿入や削除対変更は競合です。変更境界の挿入も保守的に競合とする場合があります。
4. 右側の競合一覧で対象を選び、[マージ] メニューでLEFT / RIGHT / BASE / 両方を採用します。「両方」はLEFT→RIGHTの順です。
5. RESULTを直接編集することもできます。未解決の競合が残る手動編集では、[マージ] → [手動編集の完了を確定] を明示的に選択してください。マーカーを消すだけでは解決済みになりません。この操作は人が内容を確認したという宣言です。残ったマーカーも確認してください。
6. [結果を保存]（Ctrl+S）で入力とは別のファイルへ保存します。未解決の競合があれば保存できません。

[マージ操作を取り消す / やり直す] は競合の選択・手動編集開始・完了確定を戻します。RESULTでのCtrl+Z / Ctrl+Yはテキスト編集の取消・やり直しです。手動編集後に競合選択へ戻るには、先に[マージ操作を取り消す]を使います。編集内容が自動生成で消えないための制限です。

マージ操作の履歴には内容の合計64 MiBの上限を設け、古い履歴から破棄します。1操作だけで上限を超える場合、その操作のマージ履歴は残りません。これはRESULT内のテキスト編集履歴とは別の上限です。

入力と出力の保存直前の内容を再検査し、一時ファイルを同じディレクトリーに書いてから置換します。入力自体への保存やリンクへの出力は拒否します。保存先が他プロセスで変更されていたら中止します。ただし再検査と置換の間で第三者が書く競合を完全に排除するものではありません。

## 文字コードと制限 {#encoding}

BOM付きUTF-8 / UTF-16 / UTF-32を認識し、BOMなしはUTF-8として開きます。CP932等はCLIの`--encoding CP932`で明示します。GUIにも起動時の同じ指定が使えます。エンコード→デコードで元のバイト列に戻らない入力、不正文字、NULを含むバイナリーは拒否します。保存時に表現できない文字を置換せずエラーにします。マージでは3入力の文字コードとBOMを揃えてください。保存にはBASEの文字コードとBOMを使います。

初期版の上限は各テキストと保存出力32 MiB、比較する2入力の合計100万行、厳密比較の追跡400万セルです。上限超過は「比較未完了」のエラーです。近似結果でマージを続行しません。[停止]で比較を取り消せます。ファイルの読み込みと比較は画面とは別のスレッドで処理します。OSのファイルI/O待ちの中断時間は保証しません。巨大入力のディスク索引・ストリーミング表示は今後の実装です。

## CLI {#cli}

```powershell
yymerge diff left.txt right.txt
yymerge diff left.txt right.txt --format json --report changes.json
yymerge diff left.txt right.txt --format unified --report changes.patch
yymerge diff left.txt right.txt --format html --report review.html
yymerge diff old.txt new.txt --encoding CP932
yymerge merge --base base.txt --left ours.txt --right theirs.txt --output merged.txt
yymerge merge --base base.txt --left ours.txt --right theirs.txt --output conflict.txt --conflict-markers
yymerge folders before after --recursive --format json --report folders.json
yymerge gui --left left.txt --right right.txt --wait
yymerge gui --base base.txt --left ours.txt --right theirs.txt --output merged.txt --wait
yymerge --help
yymerge merge --help
```

既存出力を置き換えるには`--overwrite`が必要です。競合のあるCLIマージは既定で出力を変更しません。`--conflict-markers`を指定したときだけBASEを含む競合マーカー付きファイルを出力し、終了コードは1です。CLIは対話入力を要求しません。

UnifiedはUTF-8、BOMなし、LF改行だけが対象で、ファイル全体を1ハンクとして出力します。ヘッダーの名前は固定の`a/left` / `b/right`です。別の改行や文字コードのファイルにはJSONレポートを使ってください。JSONの行番号・範囲は0始まり、範囲の終点は含みません。

| 終了コード | 意味 |
|---|---|
| 0 | 完全一致、競合なしの保存完了、または待機なしGUIの起動成功 |
| 1 | 相違あり、または未解決競合 |
| 2 | I/Oエラー、未対応形式、比較未完了 |
| 64 | 引数の誤り |
| 130 | GUIマージを保存せず終了、または取消 |

`gui --wait`は画面を閉じるまで待ちます。マージを未保存で閉じると130、保存後に閉じると0です。比較画面は一致0 / 相違1です。`yymergew.exe`にも`gui`を除いた同じオプションを渡せます。

## フォルダー比較 {#folders}

GUIでは[ファイル] → [フォルダー比較を開く]から左右のフォルダーを選択します。子フォルダーも含めてバックグラウンドで比較します。[停止]で取り消せます。ファイルの書き換えや同期は行いません。

一覧には「一致」「内容が異なる」「左のみ」「右のみ」「種類が異なる」「未比較: リンク」「未比較: 読み取り失敗」を表示します。両側にあるフォルダー自体の行は、その配下の内容の一致を保証しません。配下の各行を確認してください。ファイルの読み取り失敗はその行の「未比較」として残り、選択するとエラーの詳細が下部に表示されます。ディレクトリーの走査に失敗した場合や停止した場合は、部分的な一覧を確定結果として扱わず破棄し、「未完了」と表示します。

両側にある通常ファイルをダブルクリック、Enter、または[比較] → [選択したファイルを比較]で別ウィンドウに開けます。テキスト比較の文字コード・32 MiB上限・バイナリー非対応の条件が適用されます。片側だけの項目、フォルダー、リンク、読み取り失敗の項目は開きません。空ファイルとして扱うこともありません。

一覧は1ページ2,000項目で、[前へ] / [次へ]で切り替えます。長いパスは横スクロールで確認できます。[比較] → [フォルダー比較を再実行]で再走査します。再走査の開始時に以前の結果を消去します。[ファイル比較に戻る] / [フォルダー比較の結果に戻る]で表示を切り替えられます。元のファイル比較の未保存結果は保持します。

CLIの`folders`もファイルの内容をチャンク単位でバイト比較します。更新日時やサイズだけで「一致」と判定しません。`--recursive`で子フォルダーも調べます。隠しファイルも含めます。読み取り不能はエラーです。シンボリックリンク、Windowsのジャンクション等のリパースポイントは追跡せず、比較未完了（2）を返します。1ツリー10万項目、深さ128階層が上限です。レポートは比較対象の外へ保存してください。走査中のツリー全体の整合性を固定するスナップショット機能はありません。GUIのフォルダー比較を表示して終了する場合も、一致0 / 相違1 / 未比較・エラー2 / 処理中・取消130です。未保存マージが残る場合は130です。

### 祖先付き3方向フォルダー比較

[ファイル] → [3方向フォルダー比較を開く]でBASE（左右の変更前の共通祖先）、LEFT、RIGHTの順にフォルダーを選びます。フォルダーの内容を変更する操作はありません。CLIでは次のように実行します。

```powershell
yymerge folders LEFT RIGHT --base BASE --recursive --format json
```

同じ相対パスの項目を、バイト単位で比較します。移動・リネームの追跡は行いません。祖先のない追加、祖先にあって片側だけで削除された項目、空ファイルは別の状態として扱います。ディレクトリー自体の判定はコンテナーの種類と存在だけを比較するもので、配下の一致や安全に削除できることを保証しません。配下の各行を確認してください。

| GUI表示 | JSONのstatus | 意味 |
|---|---|---|
| 祖先から変更なし | `Unchanged` | 3側で同じ内容・種類 |
| 左の変更 / 右の変更 | `LeftChanged` / `RightChanged` | 片側だけが祖先から変更（種類の変更も含む） |
| 両側で同じ変更 | `SameChange` | 祖先と異なるが左右は同じ |
| 両側変更: 内容のマージで判定 | `BothChanged` | 両側が異なる内容へ変更。行単位のマージで自動統合できる場合もある |
| 左で追加 / 右で追加 | `LeftAdded` / `RightAdded` | 祖先になく片側だけに存在 |
| 両側に同じ項目を追加 | `SameAddition` | 祖先になく、左右は同じ |
| 衝突: 両側に異なる内容を追加 | `AdditionConflict` | 祖先のない同じパスへ別々の内容を追加 |
| 左で削除 / 右で削除 | `LeftDeleted` / `RightDeleted` | 一方が削除し、もう一方は祖先のまま |
| 両側で削除 | `BothDeleted` | 祖先の項目が左右ともに欠落 |
| 衝突: 削除と変更 | `DeleteModifyConflict` | 一方が削除し、もう一方が祖先から変更 |
| 衝突: 項目の種類が異なる | `TypeConflict` | 両側変更の結果、ファイルとフォルダーなどの種類が異なる |
| 未比較 | `SkippedLink` / `Error` | リンク・リンク配下・読み取り失敗 |

項目を選択すると下部に各側の種類または欠落と、読み取りエラーの詳細を表示します。3側とも通常ファイルの場合、ダブルクリック／EnterでBASEを引き継いだ3方向ファイルマージを別ウィンドウに開きます。保存先はそのウィンドウで指定します。祖先がない、または通常ファイルではない場合、左右の通常ファイルだけを2方向の読み取り専用比較で開きます。削除された入力を空ファイルとして補完しません。片側が欠落している項目の内容比較・削除の確定・フォルダー全体のマージ保存は未対応です。

JSONでは`path`、`status`、`base`、`left`、`right`、`detail`を返します。種類は`File` / `Directory` / `Link`、欠落は`null`です。リンクを走査していない側の配下は実際の存在が不明でも`null`となるため、`SkippedLink`の行を削除と解釈しないでください。リンクとその配下を未比較として返し、別の側にある項目を削除扱いにはしません。読み取りエラーや相互の比較に矛盾がある場合も未比較です。未比較があれば終了コード2、それ以外の祖先からの変更があれば1、全項目が変更なしなら0です。未比較の行を含むJSONも返すため、終了コードを必ず確認してください。走査自体の失敗・取消では一覧を返しません。レポートの保存先はBASEを含むすべての入力フォルダーの外に指定します。

## 同期計画と実行 {#sync-plan}

フォルダー比較を開いた後、[同期計画]メニューから方式を選択します。入力を再走査・バイト比較して、コピー・置換・削除等の候補を一覧にします。ファイルのコピーや削除は実行しません。2方向フォルダーでは方向指定の4方式、3方向フォルダーでは祖先付き統合を選択できます。

| メニュー | CLIのmode | 内容 |
|---|---|---|
| 左 → 右: 追加・更新 | `update-right` | 左にある項目を右へ追加・更新する候補。右だけにある項目は維持 |
| 右 → 左: 追加・更新 | `update-left` | 上の逆方向 |
| 左 → 右: ミラー | `mirror-right` | 左にある項目の追加・更新に加え、左にない右の項目は削除候補 |
| 右 → 左: ミラー | `mirror-left` | 上の逆方向 |
| 祖先付き: 左右の統合 | `merge` | 祖先を基準に片側だけの変更を反対側へ反映する候補 |

方向指定では送り元を基準にするため、送り先が独自に変更されていても置換候補になります。祖先による競合判定を必要とする場合は、3方向フォルダーを開いて`merge`を選択してください。方向指定モードと`--base`は併用できません。

項目を選択すると下部に操作の種類、コピー元・操作対象のフルパス、根拠を表示します。「左／右」は操作対象の側です。左右に通常ファイルがある行はダブルクリック／Enterで内容比較へ進め、祖先が通常ファイルなら3方向マージを開きます。片側の欠落を空ファイルで補いません。[同期計画をJSONで保存]で一覧全体を保存します。[フォルダー比較の結果に戻る]と[同期計画を表示]で切り替えられます。[前へ]／[次へ]で2,000件ごとに移動します。

作成とJSON保存はバックグラウンドで実行し、[停止]で取り消せます。作成途中の計画は表示・保存しません。再作成のたびに入力を比較し直します。比較結果に戻った場合は元の比較結果を表示するため、入力の変更後は[フォルダー比較を再実行]を選択してください。入力のロックや、走査中のファイルシステム全体の整合性固定は行いません。

### 保留する候補

- 両側変更は「内容のマージが必要」、両側への異なる追加・削除対変更・種類の衝突は「要確認」として残します。計画の中でテキストを自動統合しません。
- リンク・リンク配下・読み取り失敗は「未比較」とし、コピーや削除の候補にしません。
- 大文字小文字だけ異なる相対パスは保守的に衝突とします。Windowsの名前のすべての制約を検証する機能ではありません。
- 配下に維持・変更・未比較の項目があるフォルダーの削除を保留し、未解決の親パスを前提とする子の操作も保留します。
- ファイルとフォルダーの置換は自動提案しません。ルートが同一、または互いの内部にある場合は計画を作成しません。祖先付きではBASEも含む3ルートすべてが独立している必要があります。

一覧は、親フォルダーの作成、ファイルのコピー／置換、ファイル削除、子から親へのフォルダー削除、維持／要確認の順に並びます。これは候補の表示順であり、実行された順ではありません。

### CLIとJSON

```powershell
yymerge sync plan --left LEFT --right RIGHT --mode update-right --output sync-plan.json
yymerge sync plan --left LEFT --right RIGHT --mode mirror-right
yymerge sync plan --left LEFT --right RIGHT --base BASE --mode merge --output merge-plan.json
```

常に子フォルダーを含めます。`--output`を省略するとJSONを標準出力へ出します。保存先はすべての入力ルートの外に指定します。既存ファイルを置換する場合だけ`--overwrite`を追加します。GUIでは置換確認が表示されます。保存は共通の一時ファイル・置換処理を使い、ファイル出力は32 MiBまでです。保存に失敗した場合は既存のレポートを保護します。

JSON形式1の主な項目は次の通りです。

| 項目 | 意味 |
|---|---|
| `version` / `preview_only` | `2` / `true`。計画の作成・保存自体は入力を変更しない |
| `mode` | `UpdateRight` / `UpdateLeft` / `MirrorRight` / `MirrorLeft` / `Merge` |
| `base` / `left` / `right` | 入力ルートの絶対パス。祖先なしの`base`は`null` |
| `items[].path` | 入力ルートからの相対パス |
| `items[].action` | `CreateDirectory` / `CreateFile` / `ReplaceFile` / `DeleteFile` / `RemoveDirectory` / `Keep` / `NeedsMerge` / `Conflict` / `Uncompared` |
| `items[].source` / `destination` | コピー元と操作対象の絶対パス。不要な側は`null` |
| `items[].direction` | 操作対象の`Left` / `Right`、対象未定なら`null` |
| `items[].comparison` | 祖先付きの比較状態。祖先なしでは`null` |
| `items[].kinds` | BASE・LEFT・RIGHTの順の種類。祖先なしの先頭は`null`。種類は`File` / `Directory` / `Link` |
| `items[].reason` | 操作候補または保留の根拠 |
| `summary` | `operations`（操作候補）、`review`（要確認）、`uncompared`（未比較）、`kept`（維持）の件数 |

終了コードは、要確認・未比較がない計画の作成成功が0、要確認ありは1、未比較・I/O等のエラーは2、引数誤りは64、取消は130です。操作候補があっても0であり、同期を実行したという意味ではありません。GUIは同期計画を表示して閉じた場合にこの状態を返します。未比較があってもJSONを出す場合があるため、終了コードと件数を確認してください。

要確認・未比較がない計画には `fingerprints` を含めます。入力ルートと全項目の種類・ファイル識別子・権限、通常ファイルのサイズ・更新時刻・BLAKE3ハッシュを記録します。フォルダーの更新時刻は子の作成・削除で変わるため指紋に含めません。要確認・未比較がある場合は `null` となり実行できません。旧version 1の計画も実行できません。計画ファイルを手で編集する使い方には対応しません。入力変更や保存後の改変を検出したら、計画を作成し直して確認してください。

### 計画の検証・実行・復元

GUIでは、計画の一覧を確認してから[同期計画] → [計画を確認して実行]を選びます。退避先の親フォルダーを選ぶと、新しい実行記録フォルダー名を自動生成します。方式、左右のフルパス、新規・置換・削除の件数、退避先を確認して実行します。実行はバックグラウンドで進みます。[停止]は以後の操作を止めますが、すでに行った操作を自動で戻すものではありません。下部に処理結果と実行記録の場所を表示します。実行した計画の再利用はできません。結果を比較するには[フォルダー比較を再実行]を選びます。

CLIでは、保存計画を次の順で扱います。

```powershell
yymerge sync plan --left C:/work/left --right C:/work/right --mode update-right --output C:/review/plan.json
# 再比較して検証するだけ。入力は変更しない
yymerge sync apply C:/review/plan.json
# run-dir は存在しない新規フォルダーを指定
yymerge sync apply C:/review/plan.json --execute --run-dir C:/review/run-001
# 完了した実行・途中で停止した実行を逆順に復元
yymerge sync rollback C:/review/run-001 --execute
```

GUIの復元はフォルダー比較を開いた状態で[同期計画] → [実行記録から復元]を選び、`run-001`等の実行記録フォルダー自体を指定します。途中で止まった復元も同じ操作で続けられます。復元済みの操作は繰り返しません。

同期を止めた位置から続ける場合は[同期計画] → [実行記録から同期を再開]を選び、同じ実行記録フォルダーを指定します。記録にある方式・左右のパス・全体の操作数を確認します。CLIでは次のように指定します。

```powershell
yymerge sync resume C:/review/run-001 --execute
```

再開前に、完了済み・未着手・退避済みでコピー反映待ちの状態を記録とファイル識別子から判別し、その混在状態と全入力の指紋を照合します。完了済みの操作を繰り返さず、残りを同じ記録へ追記します。最後の操作が反映済みで完了記録だけ書かれていない場合も判別します。完了済みの記録をもう一度再開しても入力は変更しません。

入力への新規ファイル追加、実行済み結果や元データの編集、退避データ・準備済みコピー・保存計画の変更を検出した場合は再開を拒否します。復元を開始した記録から同期に戻ることもできません。その場合は復元を続けるか、確認後に新たな計画を作成します。中断位置を人が編集する操作には対応しません。再開前に記録の末尾にある不完全な1行だけを除去し、操作前に残っていた未記録の準備ファイルは`abandoned/`へ退避して作成し直します。退避データを削除・上書きしません。

今回の版から保存計画のチェックサムを `PlanHash` として記録します。これを持たない以前の実行記録は復元だけに対応し、再開できません。チェックサムは意図しない計画変更を検出するためのもので、電子署名ではありません。自分で作った信頼できる記録だけを使用してください。

実行直前には再比較して保存計画全体と指紋を照合します。コピーは一時ファイルへ準備し、元の内容を再検査してから反映します。置換・削除の元ファイルは`backups/`へ移動して保持します。意図の記録をディスクへ同期した後、送り先を上書きしない移動で反映します。フォルダー削除は空の場合だけ行います。実行終了時にも全入力を検査します。同じ実行記録を複数のプロセスが同時に操作することはロックで拒否します。

実行記録フォルダーの構成:

| ファイル・フォルダー | 内容 |
|---|---|
| `plan.json` | 実行時のversion 2計画・全入力の指紋 |
| `journal.jsonl` | version 1の記録。Header、保存計画のPlanHash、操作前のIntent、実行完了のFinished、復元開始のRestoring、復元済みのRevertedを1行ずつ追記し同期 |
| `backups/番号` | 置換・削除前の元ファイル／空フォルダー。番号は計画itemsのインデックス |
| `staging/番号` | 反映前の候補。中断後に残る場合がある |
| `abandoned/番号-時刻` | 再開時に退避した、Intentに未記録の準備ファイル |
| `undone/番号` | 復元時に退避した同期結果。削除せず保持する |
| `lock` | 同じ記録を同時実行しないためのOSロック |

復元はファイルの識別子・ハッシュ等が実行結果と一致する場合だけ行い、実行後のユーザー編集を上書きしません。バックアップが変更されていても停止します。元ファイルを移動した直後や復元中のプロセス中断も、記録と実際の配置を照合します。最終行の途中で切れた記録は、次の復元時にその未完の行だけを除きます。エラー後は表示された実行記録と対象フォルダーを確認してください。記録・退避データを自動削除する機能はありません。

### 同期実行の範囲と制限

- 実行・復元はWindowsとLinuxの通常ファイルシステムが対象です。記録は作成した端末・元のパスで利用してください。
- 左右と退避先は同じファイルシステム上とし、退避先はBASEを含む全入力の外に置きます。既存の実行記録フォルダーは上書きしません。途中のマウントポイント等で移動できない場合も停止し、既に退避した内容を保持します。
- リンク・ジャンクション・特殊ファイル、型衝突、未比較、未解決マージがある計画は実行できません。実行は1計画10,000操作、保存計画・実行ログはそれぞれ32 MiBまでです。内容の指紋は64 KiBずつ読むため、大きいバイナリーファイルもコピーできます。
- 内容・通常の権限・ファイル更新時刻を扱います。ACL、所有者、監査情報、代替データストリーム、拡張属性、ハードリンク関係、疎ファイル属性の複製は保証しません。新規フォルダーの権限は退避先の既定値を継承します。厳密なメタデータ複製が必要な用途には未対応です。
- フォルダー全体を一度に確定するトランザクションではありません。変更検出時にも実行済み分は残り、明示的な復元が必要です。実行・復元中は他のアプリによる編集を止めてください。悪意ある同時のパス差し替えや、電源断・ディスク故障・破損したネットワーク共有からの完全復旧までは保証しません。
- 記録にはフルパス、指紋、元ファイルを含みます。自分で作成した信頼できる記録だけを読み込み、内容を書き換えずに保持してください。

正規表現等の高度な比較規則、表・構造化データ・画像・バイナリー比較、ZIP / SFTP / Office / PDFは未実装です。未対応コマンドは引数エラーとして扱います。

## Gitの外部diff／mergeツールとして使う {#git-tool}

Gitから渡されるLOCAL／REMOTEを2方向比較へ、BASE／LOCAL／REMOTEを祖先付きマージへ対応させます。Git用画面は必ず閉じるまで待機し、別の比較への切替を無効にします。通常のyymerge画面は従来どおり利用できます。Windows GUIには`yymerge.exe`と`yymergew.exe`の両方が必要です。

### 設定例を作る・登録する・解除する

`git-tool config`は設定例を標準出力に表示するだけで、Gitの設定を書き換えません。PowerShell 7で、実際に配置したyymerge.exeから設定例を生成する例です。Git設定ファイルの保存先は存在する専用フォルダーにしてください。

```powershell
& 'C:/Tools/yymerge/yymerge.exe' git-tool config |
    Set-Content -Encoding utf8 'C:/Tools/yymerge/yymerge.gitconfig'
# このリポジトリで使う場合だけ、利用者が明示的に登録する
git config --local --add include.path 'C:/Tools/yymerge/yymerge.gitconfig'
git difftool --tool=yymerge --no-prompt
git mergetool --tool=yymerge --no-prompt
```

`git-tool config --executable C:/Tools/yymerge/yymerge.exe`で実行ファイルのパスを指定することもできます。実行ファイルのパスはGitが使うシェルとGit設定の両方に合わせて引用します。空白・日本語・アポストロフィを含むパスも対象です。`$LOCAL`等の変数はGit側で展開させる必要があるため、設定例を手で引用し直すことは避けてください。

解除は、登録したものと同じスコープとパスで行います。他のinclude設定を一括削除しません。

```powershell
git config --local --fixed-value --unset-all include.path 'C:/Tools/yymerge/yymerge.gitconfig'
```

生成した設定には`mergetool.yymerge.trustExitCode = true`と`hideResolved = false`を含めます。成功判定はファイルの更新時刻だけに頼りません。Git自体の`git mergetool`は、成功後に通常の動作として結果をindexへ登録します。yymergeアダプターはstage・commit・pushを実行しません。

### マージの保存と終了判定

Git用画面はLOCALを自分側、REMOTEを相手側、BASEを共通祖先、MERGEDを結果として表示します。左右の選択や手動編集の確定は通常の3方向マージと同じです。未解決0件で保存し、画面を閉じた場合だけ成功を返します。画面を開いた、競合マーカーが見つからない、ファイルの更新時刻が変わった、といった理由だけでは成功にしません。

画面を開いている間はGitのMERGEDを変更しません。保存済みの現在の結果と入力を検査し、正常終了した後でMERGEDへ反映します。途中でGitや他のアプリがMERGEDの内容変更・削除・新規作成を行った場合は、その変更を上書きせず失敗します。保存せず閉じた場合、未解決の場合、GUI起動失敗、読み取り・符号化・保存失敗の場合もMERGEDを変更しません。保存後にさらに編集した内容を破棄して閉じる場合も、今回のマージは成功にしません。GUIで保存した結果があるのに反映できなかった場合は、その結果を保持し、コンソールに`retained at`の復旧用パスを表示します。MERGEDと保存結果を確認してから利用してください。

生成設定は`--verify-index`を指定し、Git indexのstage 1・2・3に通常ファイルのBASE・LOCAL・REMOTEが存在することを確認します。add/add（祖先なし）、削除対変更、シンボリックリンク、submoduleはこの初期マージアダプターの対象外で、成功扱いにしません。Gitが祖先なしの代わりに空の一時BASEを用意しても、存在する空の祖先と混同しません。実際にstage 1にある空のファイルは有効な祖先です。

### GUIを使わない利用

`--headless`ではCLIの同じ厳密比較・祖先付きマージを使い、Linuxでも利用できます。自動統合できない場合は終了コード1でMERGEDを保持し、競合マーカーを出力する指定は設けていません。自動化用のGit設定例を作る場合は`git-tool config --headless`を明示します。

```powershell
yymerge git-tool diff --local=before.txt --remote=after.txt --headless
yymerge git-tool merge --base=base.txt --local=local.txt --remote=remote.txt --merged=result.txt --headless
```

Gitからの呼び出しには、生成設定と同じ`--verify-index`を使用してください。上の直接呼び出しは、利用者が明示的に揃えた3つの通常ファイルを扱う例です。存在しないファイルを空ファイルで補いません。diffでGitが渡す`/dev/null`（Windowsでは`nul`）だけは欠落の役割として受け取り、空の表示用文書を用意し、GUIとCLIで欠落を明示します。実在する空ファイルは欠落表示にしません。

| 操作 | 終了コード |
|---|---|
| `git-tool diff` | 0: 比較・閲覧が完了。相違があってもGit用アダプターでは成功。2: エラー、130: 中止 |
| `git-tool merge` | 0: 解決結果をMERGEDへ保存。1: headlessの未解決・対象外のindex状態、2: エラー、130: 保存せず終了／中止 |
| `git-tool config` | 0: 設定例を出力。引数誤りは64 |

通常の`yymerge diff`が差分ありを1で返す仕様は変わりません。Git用diffが0を返すのは、Gitの`--trust-exit-code`を使っても相違だけで閲覧を失敗と扱わないためです。入力上限32 MiB、文字コード・BOMの一致条件等は通常の比較・マージと共通です。

公式資料: [git-difftool](https://git-scm.com/docs/git-difftool)、[git-mergetool](https://git-scm.com/docs/git-mergetool)。


## 2方向の比較規則 {#comparison-rules}

既定は厳密比較です。通常の2方向比較では[比較規則]メニューの項目を選ぶと入力をバックグラウンドで再比較します。[厳密比較に戻す]で全規則を解除します。設定は現在のウィンドウ内で保持します。再利用する場合は後述のプロファイルを保存してください。通常の2方向比較で別のファイルを開くと規則を引き継ぎ、3方向マージを開く場合は厳密比較へ戻します。

| GUI／CLI | 対象 |
|---|---|
| 空白・タブを無視／`--ignore-space` | 各行のASCII空白（U+0020）とタブ。引用符の内側も対象 |
| 行末の空白・タブを無視／`--ignore-trailing-space` | LF／CRLFの直前、または改行のない最終行末のASCII空白・タブ |
| 大文字・小文字を無視／`--ignore-case` | Unicodeの小文字変換結果を比較。ロケール依存変換・完全なcase folding・Unicode正規化は行わない |
| LFとCRLFの違いを無視／`--ignore-eol` | LFとCRLFを同等に扱う。改行の有無や行数の違いは保持 |

空白無視で全角空白・改行・NBSPを消しません。行末空白無視で行内の空白は消しません。改行無視は単独CRを行区切りに変換せず、終端改行の欠落も同等にしません。空白だけの行をなくす機能ではなく、空ファイルと空白だけの最終行も区別します。`--ignore-space`と行末空白無視を併用した場合は、より広い空白無視が有効です。例えば`Ä`／`ä`は大小文字無視で同値になりますが、`ß`／`SS`は同値になりません。

```powershell
yymerge diff before.txt after.txt --ignore-case --ignore-trailing-space --ignore-eol
yymerge diff before.txt after.txt --ignore-space --format json --report comparison.json
yymerge gui --left before.txt --right after.txt --ignore-case --ignore-eol --wait
```

規則は原文と独立した行ごとの比較キーに適用します。表示・選択・コピーするテキストと行番号は原文のままで、原本や保存結果を正規化しません。無視した行対は青い背景と「≈ 規則で無視」の一覧に残し、F7／Shift+F7や一覧の選択で移動できます。一覧では実際の差分、無視した行対の順に表示します。

ステータスは次のように区別します。

- **元データ一致**: 文字コード・BOM・改行を含めて一致。
- **規則上は同値（元データは異なります）**: 指定した規則では同値だが元のデータには差がある。
- **相違あり**: 規則適用後にも差がある。文字コードやBOMの差もここに含む。

CLIは規則適用後に同値なら0、差が残れば1、読取失敗・上限超過等で判定が終わらなければ2を返します。0を返しても元バイトが一致しているとは限りません。JSONでは判定と適用規則を明示します。

| JSONの項目 | 意味 |
|---|---|
| `identical` | 元データの一致。規則で一致に変わることはない |
| `equivalent` | 規則上同値か。文字コード・BOMも一致する場合だけtrue |
| `status` | `Identical`／`EquivalentUnderRules`／`Different` |
| `rules` | `ignore_space`／`ignore_trailing_space`／`ignore_case`／`ignore_eol`の適用状態 |
| `ignored_line_pairs` | 元の行は違うが比較キーが一致した行対。`left`／`right`は0始まりの元行番号 |
| `diff` | 指定規則での比較。規則を使った場合のEqualは比較キーの同値を表す |

文字コードとBOMはこれらの規則では無視しません。無視した行対の数は、文字コード等のメタデータ差を含む「全ての元差分の数」ではありません。元の厳密な比較結果が必要な場合は規則を解除して再比較してください。

規則は通常の2方向表示専用です。3方向マージ、Git専用画面、フォルダー比較、同期の計画・実行・再開・復元は厳密な判定を継続します。規則を指定したGUIでBASEも指定すると拒否します。`merge`や`sync`コマンドへ無視フラグを渡すこともできません。正規化結果を適用可能なパッチと混同しないよう、`--format unified`と無視フラグの併用は拒否します。既存のレポートを置き換えることもありません。

原文32 MiB／ファイル、合計100万行等の既存上限に加え、比較キーも32 MiB／ファイルまでです。Unicode変換でキーが拡大した場合も上限を超えたところで未完了を返します。[停止]で中止できます。正規表現、空行の無視、数値許容差は未対応です。

## 比較プロファイル {#comparison-profiles}

通常の2方向比較で[比較規則] → [現在の規則をプロファイルに保存…]を選ぶと、現在の4種類の規則をJSONファイルに保存します。[比較プロファイルを読み込む…]で別の比較にも再利用できます。読み込み後はチェック項目が変わり、開いている入力をバックグラウンドで再比較します。入力を開く前にも読み込めます。保存先の拡張子は省略すると`.json`になります。既存ファイルは保存ダイアログで置換を確認し、現在比較している入力ファイルへの保存は拒否します。

規則は自動保存・自動読込しません。新しいウィンドウは明示指定がなければ厳密比較です。プロファイルは入力パス、文字コード指定、ウィンドウ位置、マージ結果を含みません。読み込んだ後でチェック項目を変えても、プロファイルファイル自体は変更しません。更新する場合は再度保存してください。

```powershell
# プロファイルの作成・検証
yymerge rules-profile save "review.json" --ignore-case --ignore-trailing-space --ignore-eol
yymerge rules-profile show "review.json"
# 既存ファイルの置換は明示指定が必要
yymerge rules-profile save "review.json" --ignore-eol --overwrite
# CLIとGUIで同じプロファイルを利用
yymerge diff before.txt after.txt --rules-profile "review.json" --format json
yymerge gui --left before.txt --right after.txt --rules-profile "review.json" --wait
```

`--rules-profile`と個別の`--ignore-*`フラグは併用できません（引数エラー64）。プロファイル内のfalseを含め、保存した設定全体を適用します。GUIホストへ渡す前にプロファイルを読み込み、解決済みの規則を渡すため、ウィンドウ起動後に元のJSONを書き換えても自動で設定が変わることはありません。`show`は検証した設定を標準出力へ表示するだけです。作成・検証の成功は0、読み取り・形式・保存失敗は2です。比較の終了コードとJSONの判定項目は[比較規則](#comparison-rules)と同じです。

形式はUTF-8のJSON、最大64 KiB、現在のバージョンは1です。手で作る場合も全項目が必須で、キーの重複・未知の項目・未対応バージョンはエラーです。

```json
{
  "version": 1,
  "rules": {
    "ignore_space": false,
    "ignore_trailing_space": true,
    "ignore_case": true,
    "ignore_eol": true
  }
}
```

不正なファイルをGUIで読み込んでも既存の規則・表示は変わりません。CLIは厳密比較にフォールバックせず2を返し、既存レポートも保持します。プロファイルを入力に指定したCLIでは、そのJSONファイル自身をレポートで上書きすることも拒否します。

プロファイルは3方向マージ、Git専用画面、フォルダー比較、同期には適用できません。厳密比較だけを保存したプロファイルも、BASEやGit専用フラグと同時にGUIへ渡すことはできません。無視規則が有効なプロファイルでのunifiedパッチ出力も拒否します。

## HTML比較レポート {#html-report}

通常の2方向テキスト比較を開き、[ファイル] → [2方向比較をHTMLレポートに保存…]を選びます。拡張子を省略すると`.html`になります。既存ファイルは保存ダイアログで置換を確認します。比較が完了した入力のスナップショットと適用規則を保存開始時に取り込み、バックグラウンドで生成します。[停止]で取り消せます。途中で別の比較へ切り替えても、生成対象は保存開始時の比較です。完了時に保存先を表示し、比較自体の終了コードやマージの保存状態は変えません。

CLIでは次のように指定します。`--report`を省略するとHTML全文を標準出力へ出します。既存の保存先を置換する場合だけ`--overwrite`が必要です。

```powershell
yymerge diff before.txt after.txt --format html --report review.html
yymerge diff before.txt after.txt --ignore-case --ignore-eol --format html --report review.html
yymerge diff before.txt after.txt --rules-profile review.json --format html --report review.html
```

レポートはUTF-8の単一HTMLファイルです。ブラウザーで開けるほか、ブラウザーの印刷機能から紙・PDFへ出力できます。CSSを同梱し、JavaScript、外部画像、外部フォント、外部サービスは使用しません。元の文字列・パスはHTMLとしてエスケープし、HTMLタグを含む入力も文字として表示します。フォントはローカルにあればUDEV Gothic、なければ等幅フォントを使用します。HTMLのブラウザー内編集やマージ操作には対応しません。

次の情報を記録します。

- 左右のフルパス、文字コード、BOMのバイト列、適用した規則。
- 元データ一致・規則上の同値・相違ありの判定、変更領域数、無視した行対数。
- 全行を左右に整列した原文と、それぞれの元の1始まりの行番号。
- 変更は黄、左のみは赤、右のみは緑、規則で無視した差分は青と「≈」で表示。
- 行末はLF・CRLF・改行なしで表示。対応行がない場所は「—」、空ファイルは0行として区別。

行の中身を正規化して保存する機能ではありません。行末空白とタブも原文から表示し、タブの見た目は4桁幅です。改行以外の制御文字（タブを除く）は`\u{XXXX}`として可視化します。表示用の折り返しは原文の行区切りではありません。行内の部分強調はなく、差分は行単位です。共有するHTMLには入力の全文とフルパスが含まれます。

終了コードは同値0、差があれば1、読取・出力・上限超過等の未完了は2、取消は130です。文字コード・BOMの差も1で、無視した規則での同値を元バイト一致として扱いません。HTMLは表示用のため無視規則にも対応しますが、unifiedパッチの生成制限は変わりません。

入力は従来どおり1ファイル32 MiB・合計100万行等の制限があります。HTMLもエスケープや行番号・タグを含めて最大32 MiBです。小さな原文でも、行数やHTML特殊文字の数によって上限に達する場合があります。上限を超えた場合、途中までのHTMLを成功として返さず、標準出力にも部分出力しません。ファイル保存前に入力を再検証し、入力変更・取消・生成失敗時は既存レポートを保持します。入力ファイル自身（CLIで指定した規則プロファイルも含む）への上書きは拒否します。

現時点のHTML出力は通常の2方向テキスト比較が対象です。3方向マージ、Git専用画面、フォルダー比較・同期計画からのHTML出力は未対応です。大規模HTMLをブラウザーで開く速度は、ファイルサイズとブラウザーに依存します。
