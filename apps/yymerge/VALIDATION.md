縮尺の回帰試験では、修正前に320×180の描画バッファーが1600×900への拡大後も残ることを再現しました。修正後は拡大・縮小と96 / 144 / 192 DPIで、描画バッファーの物理ピクセル数がクライアント領域に一致し、文字のDIP寸法が変わらないことを検証しています。実モニター間を移動する混在DPIの操作検証とは区別します。

## 初期性能測定

`tests/benchmark.py`でUTF-8の7,800,000 bytes、100,000行を作り、release CLIを各5回実行しました。ファイルの読み込み・デコード・比較・必要な入力再検査を含むプロセス全体の時間です。

| 条件 | 中央値 | 最大 | 終了コード |
|---|---:|---:|---:|
| 完全一致 | 52.13 ms | 160.13 ms | 0 |
| 離れた10行の変更 | 52.31 ms | 61.06 ms | 1 |
| 全行変更で追跡予算を超過 | 71.01 ms | 94.37 ms | 2（比較未完了） |

ローカルのキャッシュされたディスク上での観測値です。ピークメモリー、コールドディスク、GUIのp95、混在DPI、巨大入力の目標値は未評価です。提案書の性能目標を達成したという判定には使いません。

再実行:

```powershell
cargo test --manifest-path apps/yymerge/Cargo.toml --workspace --locked
cargo clippy --manifest-path apps/yymerge/Cargo.toml --workspace --all-targets --locked -- -D warnings
cargo build --manifest-path apps/yymerge/Cargo.toml --release --workspace --locked
python apps/yymerge/tests/benchmark.py apps/yymerge/target/release/yymerge.exe --workdir apps/yymerge/target/benchmark
apps/yymerge/target/release/yymerge.exe gui --ui-smoke-test apps/yymerge/target/ui-smoke --wait
```

`YY_HELP_TEXT_ONLY=1`を指定すると、同じスモークをテキストヘルプで確認できます。Windowsの一時ディレクトリーが制限された環境では、書き込める専用ディレクトリーをTEMP / TMPに指定してテストしてください。

GUIフォルダー比較のスモークは、一覧の生成・選択したパスと祖先による比較／マージの読み込み・ページ切替・実際のバックグラウンド走査の失敗と取消を検証しています。通常ヘルプ・テキストヘルプの両方でrelease版を確認しています。選択した項目から別プロセスのウィンドウを開く操作の自動検証は含みません。デモの手順は[demo/yymerge](../../demo/yymerge/README.md)に記載しています。

計画作成・保存は引き続き読み取り専用で、version 2には全入力のBLAKE3指紋を追加しました。`sync apply`の検証のみと明示実行、ミラー・追加更新・祖先付き統合の実行／復元を検証しました。計画の改変・入力変更・入力内の退避先・取消済みの実行要求を拒否し、ユーザーが変更した結果を復元時に上書きしないこと、退避した原本を保持することも確認しています。

実行ログは操作前のIntentと完了／復元済みのイベントをJSONLで追記し、各書き込みを同期します。通常ファイルの上書きをしない移動、同じ記録のOSロック、復元の繰り返し、候補反映前／原本復元前／復元済み記録前の中断状態、最終ログ行の途中切断を検証しました。中断は操作と記録をテスト内で所定の状態に置いて再現しています。実際の電源断・ディスク破損試験ではありません。

ネイティブGUIのバックグラウンド処理で同期・復元し、原本が戻ることと古い計画の再利用拒否を確認しました。確認ダイアログで人が選ぶ部分のクリック自動化は含めません。release版の通常／テキストヘルプで、従来の4ペイン整列・サイズ変更と併せて成功を確認しました。実行記録は`target/sync-resume-release-{normal,text}/`にあります。

方向指定の計画では左の目録と内容を祖先として二重に読み込まず、2側の目録と1回の内容比較を共有しています。指紋検査は実行前後に全体を走査し、操作時には関係するファイルと親を検査します。全体の指紋や計画を操作ごとに再保存する方式は使用しません。同期の大規模性能、悪意ある同時パス差し替え、ネットワーク共有・複数ボリューム、ACL等の完全複製は未検証・未保証です。

提案書のP0全体は未完了です。多形式比較、規則プロファイル・高度な規則、ディスク索引は[README](README.md)に残件として整理しています。

同期再開は6操作の各境界と3状態（操作前・退避後・反映後）、未着手・最終完了前を含めて試験しました。途中状態は記録とファイルの配置をテスト内で作って再現しており、プロセス強制終了・電源断を注入した試験ではありません。再開前の全入力照合、コピー候補・バックアップに追加された未知のファイルの拒否、完了済み操作の反復防止、復元開始後の再開拒否、PlanHashを持たない旧記録の拒否を対象としています。GUIでは全計画の左右のパス・方式・件数を再開前に表示し、実際の状態検証はワーカーで実行します。

Gitアダプターは通常ファイルの3方向マージに限定し、生成設定の`--verify-index`でGit stage 1・2・3を検証します。add/add・削除・リンク・submoduleのマージは未対応です。GUIホストの終了待機・引数の役割・失敗時のMERGED保持はコールバック試験で、実Gitからの設定／シェル／index／終了コードはheadless呼び出しで検証しました。実際のGit起動から人がGUIを操作して閉じるまでの全操作の自動化は含みません。GUI自体の完了判定は、通常／テキストヘルプの両方のrelease版ネイティブスモークで成功を確認しました。記録は`target/git-tool-release-{normal,text}/git-tool-smoke.txt`です。

WindowsのGit実連携テストは、サンドボックス内でMSYSシェルの名前付きオブジェクト作成が拒否されるため、通常権限の一時リポジトリーで実行しました。ユーザーのglobal設定や本体リポジトリーの履歴は変更していません。

比較規則は別の比較キーを厳密Myersへ渡す方式で、原文の索引を保持します。既定経路は従来の厳密比較のままです。コアの行比較部分を共有したため、既存の小規模全組合せの最小編集・原文再構築、マージ、Gitパッチ適用、同期・復元も回帰試験し、成功しました。新しい規則のキーに基づく同値は原バイト一致として扱いません。通常／テキストヘルプの両方でrelease版ネイティブスモークに成功し、`target/comparison-rules-release-{normal,text}/rules-smoke.txt`に記録しました。
