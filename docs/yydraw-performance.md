# yydraw の性能測定

2026-10-20、Windows x64、`AMD64 Family 25 Model 33 Stepping 2, AuthenticAMD`。
Rust の release ビルドで測定した値です。

```powershell
cargo run --release -p yy-draw --example perf
```

図形 2,000 個、直交接続線 5,000 本、1,280 × 720 px、白背景と格子あり。
40 列の規則配置で隣接図形を結び、接続先の一部を重複させています。
30 回、8 DIP ずつ横にパンして平均を取ります。

| 処理 | 実測 |
| --- | ---: |
| 全接続線の経路計算 | 14.84 ms |
| 経路探索の未解決数 | 0 |
| 初回の描画（解析・経路計算を含む） | 85.51 ms |
| キャッシュ使用時のパン描画平均 | 14.22 ms |
| 上記平均から換算した描画頻度 | 70.3 fps |

障害物の空間索引、経路の一括計算、解析済み描画ツリーの再利用、
画面外のパスの描画省略、格子のまとめ描きにより負荷を抑えています。
保存・出力・画面の画像生成はワーカースレッドで実行します。

これは描画中核の測定であり、Windows のウィンドウ合成、Direct2D への転送、
イベント処理を含めた表示フレームレートではありません。実際の操作速度は
図形の配置、交差の数、画像の複雑さ、表示倍率、機材によって変化します。
上記は基準ケースの記録で、すべての図での上限応答時間を保証するものではありません。
SVG と PNG の比較テストでは、日本語、クラウドアイコン、太い線、
画面外の要素、異なる表示範囲・倍率を含む描画の一致を検証しています。

## クラウドアイコンとドラッグの改善

```powershell
cargo run --release -p yy-draw --example perf_icons
```

公式カタログから 200 個を選び、20 列に配置した図を 1,280 × 720 px で描画しました。
各 SVG 画像にキャンバス全体の中間画像を確保する描画経路は平均 1,014.34 ms、
アイコンの表示領域だけを描く新しい経路のキャッシュ使用時のパンは平均 17.07 ms でした。
このケースでの比率は約 59 倍です。比較対象は解析済みの SVG ツリーを直接 resvg で描画し、
新しい経路は格子・背景・文書キャッシュを含むパン 30 回を平均しています。
異なる機材やアイコン構成にも同じ比率が当てはまるという意味ではありません。

図形の移動中は、背景と選択図形の画像を一度生成して Direct2D のビットマップを再利用します。
ポインター移動では位置と接続線・ガイドを更新し、毎回の文書全体の複製・SVG 解析・画像転送を避けます。
ドロップ時に全体の経路・アーチ・描画を確定します。操作試験では移動中に全体描画の版が変わらず、
新しいワーカーが起動しないことと、取消・Undo が元の状態を復元することを確認しています。
一覧のサムネイルも表示された項目だけバックグラウンドで生成し、直近 256 個をキャッシュします。

## 矢印と拡大縮小の追従

矢印を引いている間は背景を再解析せず、操作中の 1 本の経路と矢印を Direct2D で重ね描きします。
ドロップ後も全体の描画が届くまでその線を表示し、確定直後に一瞬消えることを防ぎます。
交差アーチは確定した全体描画で更新します。キャプチャ解除・取消では仮の線を取り除きます。

ホイールでの拡大縮小とパンでは、既存ビットマップの位置・倍率を変えます。
ズームは対数倍率を約16msごとに補間し、最後の入力から最大200msで目標倍率に到達します。
現在の文書座標と描画済み画像の座標を別々に保持し、カーソル位置を中心とするズームを維持します。
補間中にカーソルが動いたときも、現在の表示を保ったまま新しいカーソル位置へ中心を切り替えます。
補間が終わってから新しい倍率の画像をバックグラウンドで生成します。
連続したホイール入力ごとの文書複製・SVG 描画・画像転送を抑えます。画像の周囲96pxも描画して
縮小直後の余白を減らし、それを超えて表示外へ広がる領域には格子を表示します。
Direct2Dの描画完了時に垂直同期を待たず、UIスレッドの待ち時間を抑えます。

Windows の操作試験では、矢印操作中に全体描画の版や文書の接続線数が変わらず、
重ね描きだけで追従することを検証しています。連続ズームについても、表示中の画像を再利用し、
高精細画像の生成を操作後へまとめることと、カーソル下の文書座標が変わらないことを検証しています。
補間途中に複数の倍率を通ること、マウス移動時に表示が飛ばないことと、その後の追従も確認しています。

接続ハンドルは図形・アイコンごとに各辺5点、計20点です。表示はDirect2Dで重ね描きし、
ホバーの変化だけでは文書全体を再描画しません。従来の中央4点の識別子は維持しています。
追加した点を使う文書は保存版1.2、それ以外は従来の1.1で保存します。1.0・1.1の読込も継続します。

## 手動の折れ線と角の丸み

Shiftで現在の線分を上下左右へ投影し、Tabで折れ点を追加します。折れ点の後は直前の線分の
逆向きを除く3方向から選択します。Backspaceで折れ点を取り消せます。Shiftを離すと自由方向に戻ります。
方向固定中は、線分の軸を変えない接続点にだけ吸着します。指定した経路は自動ルーターを使わず保持します。

角の半径は接続線ごとに保持します。画面の操作中はDirect2Dの二次ベジェで描き、確定後と
SVG・PNGは共通のパス生成処理で同じ二次ベジェを生成します。角の切り詰めは隣接する線分の
長さの半分までとし、交差アーチも角を丸めた領域に重ならないように抑えます。
形と半径の設定には既存のプロパティ欄を使い、位置・サイズは2列にして欄を画面内に収めます。

丸角を使う文書は保存版1.3で、接続線IDと半径を必須CRNRチャンクへ保存します。
既存のDOCS構造は維持し、1.0～1.2の文書は尖角として読み込みます。
丸角がない文書は従来どおり追加接続点の有無に応じて1.1または1.2で保存します。
キー操作、3方向の制約、接続点への吸着、短い線分での丸みの制限、交差アーチとの共存、
SVG・ラスタ出力、ページ・コピー・Undo・保存復元を自動テストで確認しています。

## 描画経路の追加調査と改善

2026-10-20、上記と同じWindows x64環境で追加測定しました。

```powershell
cargo run --release -p yy-draw --example perf_interaction
```

| 対象処理・条件 | 改善前の処理 | 改善後の処理 |
| --- | ---: | ---: |
| 接続端点を変えながら1本の経路を更新（図形2,000個） | 索引を毎回再構築 0.2501 ms | 索引再利用・幾何の変更確認込み 0.0050 ms |
| 図形2,000個から1,000個を選択し、移動位置を更新 | 全要素走査と原本検索 0.6472 ms | 選択要素の索引を使う更新 0.0016 ms |
| 同じX範囲に並ぶ、交差しない線5,000本のパス生成 | 22.08 ms | 2.29 ms |

最初の2行は比較例に旧方式と新方式を残して同じ実行で測定しています。
移動の行には整列ガイド・接続線の再計算・GPU描画を含めていません。
最後の行は交差判定変更の前後で同じ例を実行した結果です。
いずれも個々の処理の時間であり、アプリ全体が同じ比率で高速になるという値ではありません。

通常の2,000図形・5,000接続線の基準ケースも再測定し、キャッシュ使用時のパンは
13.97 ms → 13.94 msでほぼ同じでした。初回描画は85.76 ms → 88.04 ms、
経路計算の未解決数は双方0です。今回の改善は、操作中の反復処理と不要な交差候補の削減が中心です。

変更内容:

- 接続線のプレビューで障害物の空間索引を再利用します。図形ID・形状・矩形の変更を確認し、
  移動・拡縮・追加・削除時は更新します。接続先や途中点が変わった線だけ経路を計算し直します。
  経路キャッシュは256本までとし、別ページや長時間の編集で増え続けないようにします。
- 交差判定は256 DIPのセルで近傍の線分を絞ります。64セルを超える長い線分は別管理し、
  巨大なセル配列を作らず全候補と照合します。アーチ無効時は交差候補の作成も省略します。
- ドラッグ開始時に選択要素の位置と索引を保持し、移動中は選択要素だけを更新します。
  整列ガイドと移動背景の選択判定にも集合を使い、大きな選択範囲での繰り返し検索を減らします。
- サイズ変更・端点編集・途中点編集では、マウス移動ごとの文書全体の複製をなくしました。
  Undo・取消用の原本は操作開始時に1度確保します。
- 移動用の背景生成で二重に行っていた文書複製を1度にし、描画結果のRGBA配列は所有権を移して
  BGRAへ変換します。1,280×720画像では画像1枚につき約3.5 MiBの余分なコピーを省きます。
- Direct2Dの補助線描画は同じ色のブラシを共有し、線分ごとのブラシ生成を避けます。

総当たりの交差判定との比較（負座標・セル境界・長い線・斜線・同一線・端点接触）、
経路キャッシュの更新条件、ロックされた図形を含む複数選択の移動、素材を含む文書での
サイズ変更・端点／途中点編集と取消、既存の保存・SVG・PNG・ズーム・キー操作を確認しています。
実際の交差が非常に多い図や複雑なアイコンの描画は内容に応じた計算量が残るため、
すべての文書で一定の応答時間を保証するものではありません。

## グループ化・整列の追加後の再評価

2026-10-20、同じWindows x64環境・releaseビルドで再測定しました。
`perf`、`perf_icons`、`perf_interaction`に加え、`cargo run --release -p yy-draw --example perf_layout`
を実行しています。時間はコア処理の測定で、Windowsアプリ全体のフレームレートではありません。

| 条件・処理 | 結果 |
| --- | ---: |
| 図形2,000個・接続線5,000本の経路計算 | 15.11 ms、未解決0 |
| 同条件の初回描画 | 91.24 ms |
| 同条件のキャッシュ使用時のパン | 14.91 ms |
| アイコン200個・1,280×720のキャッシュ使用時のパン | 16.48 ms |
| 同アイコンを全キャンバス描画する比較経路 | 1,001.45 ms |
| 1,000グループの選択範囲展開 | 0.244 ms |
| グループ単位の境界・索引収集 | 0.953 ms |
| グループをページ中央へ整列 | 0.946 ms |
| グループを等間隔に配置 | 0.997 ms |
| 全グループ選択状態のキャッシュ使用時のパン | 21.50 ms |
| 接続端点変更時の経路更新（索引再利用） | 0.0054 ms |
| 1,000図形の移動位置更新 | 0.0016 ms |
| 交差しない線5,000本のパス生成 | 2.29 ms |

グループの測定は図形2,000個・接続線5,000本で、2図形ずつ1,000グループを作り、
両端が同じグループに属する内部接続線も含めています。整列・移動では相対位置と接続を保持します。
選択枠の描画では集合・索引を共有し、画面外の枠とハンドルを除外しました。
これにより選択した図形ごとの全要素再検索や、画面外の選択枠を描画する処理を避けています。
グループ整列6方向・水平垂直の等間隔配置・ロック・Undo・複製・ページ・保存復元と、
SVGとキャッシュ経由のPNGの選択表示一致を自動テストで確認しています。
