# 08. ロードマップ・テスト・リスク

## 1. 開発ロードマップ

各マイルストーンで「動くもの」を出し、巨大ファイル対応を最初期から組み込みます（後付けは困難なため）。

| マイルストーン | 内容 | 完了条件 |
|---------------|------|---------|
| **M0: 基盤** | ワークスペース作成、CI（Windows / Linux）、`yy-jobs`、設定読込、空ウィンドウ | `cargo test` と Windows ビルドが CI で通る |
| **M1: 巨大ファイルビューア** | `yy-buffer`（永続ピースツリー）、mmap ソース、Indexer、DirectWrite 描画、スクロール、行番号 | 10 GB の UTF-8 ファイルを 0.5 秒以内に表示、任意位置へジャンプ |
| **M2: エディタ基本** | カーソル・選択・入力・削除・クリップボード、IME（IMM32）、Undo/Redo、上書き保存（UTF-8）。選択モデルは最初から `SelectionSet`（マルチカーソル前提）で実装 | 日本語入力を含む基本編集、10 GB ファイルの編集・保存 |
| **M2.5: 矩形選択・マルチカーソル** | 矩形選択（表示桁ベース、遅延展開）、マルチカーソル追加操作、一括編集、矩形クリップボード（`MSDEVColumnSelect`）、IME の複数位置プレビュー、巨大矩形のバッチ適用 | 全角・タブ混在行で見た目どおりの矩形編集、1 万カーソル同時入力が 16 ms 以内、1 回の Undo で復元 |
| **M3: 文字コード** | `yy-encoding`（判別、JIS 系全般、CP932/JIS 差分）、Transcoder、ロスレス往復、別名保存ダイアログ（文字コード・BOM・改行） | 全対応文字コードで「開く→保存」がバイト一致（テストで保証） |
| **M4: 検索・置換** | `yy-search`、インライン検索バー、すべて置換（ストリーミング）、Grep | 10 GB ファイルでの全置換がメモリ一定で完了 |
| **M5: 区切り文字 / CSV** | `yy-delimited`、レコードインデックス、列揃え表示、セル編集、セル範囲の矩形選択、列操作、方言判別、拡張子変更時の区切り文字変換 | RFC 4180 テストスイート合格、フィールド内改行を含む数 GB の CSV を表示・編集 |
| ~~M6: バックアップ~~ | **要件から取り下げ（2026-09-29）** | — |
| **M7: EBCDIC・拡張** | EBCDIC 系コーデック、固定長レコード、外部マッピングファイル、正規化オプション | IBM 930/939 のサンプルデータで往復一致 |
| **M7.5: シンタックスハイライト** | `yy-syntax`（定義の読み込み・多パターン DFA・状態チェックポイント・差分更新）、ファイル種類の判定、カラーテーマ、組み込み定義（主要言語・設定ファイル・ログ・COBOL/JCL）、括弧対応・コメント化 | 1 GB ファイルでも任意位置の初回描画が 16 ms 以内、差分更新と全体処理の結果が一致 |
| **M8: 仕上げ** | 分割表示、ダークモード、印刷、インストーラ（MSI / winget）、ドキュメント | 1.0 リリース |

M1〜M3 までで「巨大ファイルを様々な文字コードで開いて編集・保存できる軽量エディタ」として実用になり、以降は機能単位で独立して進められます。

## 2. テスト戦略

### 2.1 単体テスト・プロパティテスト

| 対象 | 手法 |
|------|------|
| `yy-buffer` | `proptest` でランダムな挿入・削除列を生成し、`String` による素朴な実装（オラクル）と内容・行数・行オフセットが常に一致することを検証。スナップショットの独立性（旧スナップショットが変化しないこと）も検証 |
| Undo/Redo | ランダム編集 → 全 Undo で初期内容、全 Redo で最終内容に戻ること |
| シンタックスハイライト | 言語ごとのトークン列の期待値比較、差分更新・チェックポイントからの処理と全体処理の一致（10 章 10） |
| マルチカーソル・矩形 | 一括編集と「後ろから逐次の単独編集」の結果一致、表示桁計算の検証（09 章 8） |
| `yy-encoding` | 全文字コードで「全マッピング表の往復」「ランダムバイト列のデコード→エンコードでバイト一致（ロスレス保証）」「チャンク分割位置を変えてもデコード結果が同一」 |
| `yy-delimited` | RFC 4180 の規定例、Python `csv` / Rust `csv` クレートとの差分テスト、チャンク境界・並列投機走査の結果が逐次走査と一致すること、編集後の差分再解析が全再解析と一致すること |
| `yy-search` | `regex` の単純全文検索結果とウィンドウ検索結果の一致（境界またぎを重点的に）、全置換の 2 方式（ツリー編集 / ストリーミング）の結果一致 |
| 保存 | 失敗注入（書き込みエラー、rename 失敗）で元ファイルが保たれること |

### 2.2 結合テスト・E2E

- `tests/fixtures/` に各文字コードの実データ（青空文庫テキストの各文字コード版、CP932 特殊文字、JIS X 0213 結合文字、EBCDIC サンプル、複雑な CSV）を配置。
- Windows CI 上で UI Automation を使った E2E テスト（起動、ファイルを開く、入力、保存）。

### 2.3 性能テスト

- `tools/gen-bigfile` で 1 GB / 10 GB / 50 GB のテストファイル（短い行、長い行、1 行のみ、CSV フィールド内改行多数、Shift_JIS）を生成。
- `criterion` ベンチマーク: ファイルオープン〜初回表示、行ジャンプ、1 文字挿入、検索スループット、全置換、保存スループット。
- CI で性能回帰を検出（基準値から 20% 以上の悪化で警告）。

## 3. 主なリスクと対策

| リスク | 影響 | 対策 |
|-------|------|------|
| EBCDIC ベンダー漢字コード（JEF / KEIS / JIPS）の対応表が公開されていない・ライセンス制約がある | 対応できない文字コードが出る | IBM 系（ICU の公開データで入手可能）を標準搭載し、ベンダー系は利用者が持つ対応表を読み込む外部マッピングファイル方式にする |
| 引用符の対応が崩れた巨大 CSV で、1 回の編集がファイル全体の再解析を誘発 | 応答性低下 | 収束判定による差分解析、バックグラウンド化、警告表示。再解析中も表示は暫定結果で継続 |
| 正規表現の境界またぎ・長大マッチ | マッチの取りこぼし | HIR からの最大長算出、マッチ長上限の明示、境界の差分テスト |
| `fancy-regex` のバックトラッキング爆発 | フリーズ | 既定は `regex`、`fancy-regex` はステップ上限・タイムアウト付きのジョブ実行 |
| mmap 中のファイルが外部で変更・切り詰められる（共有モードを緩めた場合など） | アクセス違反（クラッシュ） | 既定は書き込み共有を拒否。共有を許す場合は mmap を使わない `ReadFile` ソースに切替 |
| ネットワークドライブ上の巨大ファイル | mmap のページフォルトで UI が固まる | ネットワークパスではローカル一時領域へのバックグラウンドコピー後に開く方式を選択可能にする。描画時のページ読込はプリフェッチジョブで先回り |
| IME の実装品質 | 日本語ユーザーの体験を大きく損なう | M2 で IMM32 を優先実装し、主要 IME（Microsoft IME、Google 日本語入力、ATOK）で手動テスト |
| Win32 直書きによる UI 実装コスト | 開発期間の増大 | UI 部品を最小限にし、エディタビュー以外は標準コントロールとダイアログリソースで作る。ロジックは `yy-core` 側に寄せてテスト可能にする |
