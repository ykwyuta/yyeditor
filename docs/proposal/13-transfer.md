# 13. ファイル転送（yysftp）

エディタ・ターミナルとは別のアプリとして、同じクレートを使ったファイル転送 **yysftp**（SFTP・SCP）を
作ります（2026-10-06 追加）。

## 1. 要求

| # | 要求 | 対応 |
|---|------|------|
| F1 | エディタ・ターミナルと別のアプリ（`yysftp.exe`） | 2 |
| F2 | 巨大なファイル（数十 GB）の転送 | 3・4・5 |
| F3 | 転送の途中で切断されても、再接続後に続きから送る（レジューム） | 5 |
| F4 | 転送中の状態を細かく記録に残す | 6 |
| F5 | 基本の仕組み（接続・SSH・設定・フォント・ダイアログ）はエディタ・ターミナルと共通 | 2 |
| F6 | エクスプローラー風の UI | 7 |

## 2. 全体構成

```
apps/yysftp ──► yy-win::run_sftp ──┬─ sftp/mod.rs    フレーム・ツリー・一覧・アドレスバー・メニュー
                                   └─ sftp/queue.rs  転送の一覧・記録・作業スレッド
                 ▲                       │
                 │                       ├─ yy-remote  sftp（SFTP v3）・scp・xfer（ジョブ・ジャーナル・レジューム）・
                 │                       │             log（転送の記録）・接続設定・ホスト鍵・Transport::subsystem
 yy-ssh（russh）─┘                       ├─ yy-config  設定（[transfer]）
                                         └─ yy-win の部品（接続と問い合わせ、資格情報マネージャー、ダイアログ、同梱フォント）
```

- 転送の中核（SFTP・SCP・レジューム・記録）は `yy-remote` に置き、OS に依存しない（Linux の CI で、
  本物の `sftp-server`・`scp` と、途中で切れる接続を使ってテストする）。
- 接続は組み込みの SSH（OpenSSH を使わない）。接続設定・`~/.ssh/config`・踏み台・プロキシ・ホスト鍵・
  保存したパスワード・接続の記録（`logs\remote-ssh.log`）はエディタ・ターミナルと共通。
- 転送そのものは SFTP（SSH の `sftp` サブシステム。接続先の sftp-server）か SCP（接続先の `scp` と
  シェルの `cat`・`tail`・`wc`・`mv`）。どちらも `sudo` は使わない。
- 接続先のエージェント（11 章）を使うかは選べる（5.2。既定は使わない＝接続先に何も置かない）。

## 3. SFTP（`yy_remote::sftp`）

- 版 3（OpenSSH の sftp-server と同じ）。`Transport::subsystem("sftp")` を追加した（`yy-ssh` は
  `subsystem` の要求、手元の接続は sftp-server を直接起動する）。
- 要求には ID を付け、応答は読み出し用のスレッドが ID ごとの待ち手に渡す。読み書きは 32 KiB ずつ、
  最大 64 個を応答を待たずに並べて送る（回線の遅延を隠す。1 往復 100 ms でも 20 MB/s 程度まで出る）。
- 状態コードは `io::ErrorKind` に対応させる（`NO_SUCH_FILE` → `NotFound`、`CONNECTION_LOST` → 切断）。
- 一覧（`read_dir`）、`stat`・`lstat`・`realpath`、フォルダの作成・削除、名前の変更（`posix-rename`
  拡張があれば使う）、中身ごとの削除、`fsync`（`fsync@openssh.com` 拡張があれば）。

## 4. SCP（`yy_remote::scp`）

- 接続先の `scp -t`（受け取り）・`scp -f`（送り出し）と SCP の手順で話す。
- SCP には途中から送る仕組みがないので、アップロードは区切り（既定 32 MiB）ごとに `<名前>.yypart.chunk` に
  送り、接続先のシェルで `<名前>.yypart` につなげる（`cat >>`）。切断で失うのは多くても 1 区切り。
- ダウンロードの途中からは `tail -c +N` で読む。

## 5. レジューム（`yy_remote::xfer`）

- 転送の 1 件（ジョブ）は、送り終えたことが確かな位置（`done`）をジャーナル（設定のフォルダの
  `transfers\<番号>.job`）に書きながら進める。書き換えは一時ファイルから置き換える。
- 送り先には `<名前>.yypart` に書き、終わったら大きさを確かめてから本来の名前に変える（途中のファイルが
  本物と取り違えられない）。置き換えを選んだときだけ、既にあるファイルを置き換える。
- SFTP の書き込みは、応答の届いた範囲だけを確かな位置とする（並べて送った要求の途中で切れても、切れる前に
  届いていた応答の分は確定する）。
- 接続が切れたら（`ConnectionAborted`・`BrokenPipe`・`UnexpectedEof`・接続の終わり など）、2・5・10・20・
  30・60 秒と間を空けて接続し直す。進みがないまま続けて失敗した回数が上限（既定 10）を超えたら中断にする。
  認証の中止・失敗は待っても直らないので、すぐに中断にする。
- 続ける位置は「ジャーナルの位置」と「途中のファイルの大きさ」の小さい方。SFTP のアップロードでは、
  その直前の 64 KiB を接続先から読んで手元と比べ、違えば最初からにする。
- アップロードで手元のファイルの大きさ・更新日時が始めたときと変わっていたら、続けずに失敗にする
  （送り直しを促す）。ダウンロードで接続先のファイルの大きさが変わっていたら、最初から受け取る。
- 一時停止（とアプリの終了）は中断として残り、再開（次の起動でも）でその続きから送る。

### 5.2 エージェントは任意（2026-10-06 追加）

設定 `[transfer] use_agent`（転送メニューの「接続先にエージェントを置いて使う」で切り替えられる。既定は
使わない）。

| | 使わない（既定） | 使う |
|---|---|---|
| 接続先に置くもの | なし | エディタと同じエージェント（`~/.yyeditor/agent/…`） |
| 一覧・作成・名前の変更・削除 | SFTP（`fs::SftpFs`） | エージェント（sftp-server を止めている接続先でも使える） |
| 転送 | SFTP / SCP | SFTP / SCP（同じ） |
| 送り終えた内容の照合 | 大きさ、続ける位置の直前 64 KiB | それに加えて、ファイル全体の SHA-256 |
| 接続先 | どの OS でも（sftp-server か scp があれば） | エージェントの動く Linux |

- 一覧・ファイル操作はエージェントと SFTP の共通の口（`yy_remote::RemoteFs`）で書いてあり、
  `remote::fs` が設定に合わせてどちらかを返す（ターミナルのワークスペースも同じ）。
- 照合: プロトコル（版 4）に `Hash { path, len }`（先頭から `len` バイトの SHA-256）を足した。
  転送の作業スレッドは、転送に使っている SSH の接続にエージェントを起動して（接続ごとに 1 つ。一覧の
  エージェントとは別なので、照合の間も一覧を操作できる）、名前を変える前の途中のファイル
  （アップロードは接続先、ダウンロードは手元）と送り元の SHA-256 を比べる（`xfer::Context::hasher`）。
  一致しなければ途中のファイルを捨てて最初から 1 回だけ送り直し、それでも一致しなければ失敗にする
  （本来の名前にはしない）。エージェントを起動できない（Linux 以外など）ときは記録して照合を飛ばす。
  前回「送り終えて名前を変えた直後」に落ちた転送も、末尾に加えて SHA-256 で確かめる。

### 5.1 アプリが落ちたとき

アプリが落ちても（強制終了・OS の停止・電源断でも）、次に起動したときに確かに送り終えた位置から
続ける。

- ジャーナルは一時ファイルに書いてディスクに書き出し（`fsync`）、置き換える。前の内容か新しい内容の
  どちらかが必ず残る。
- 転送中は約 1 秒ごとにジャーナルの位置を進める。ダウンロードでは、その前に手元の途中のファイルを
  ディスクに書き出すので、ジャーナルの位置が中身より先に進まない。アップロードの位置は、接続先から
  書き込みの応答が届いた分だけ（SCP は区切りをつなげた後）。続けるときは「ジャーナルの位置」と
  「途中のファイルの大きさ」の小さい方からにし、SFTP のアップロードでは直前の 64 KiB を照合する。
- 名前を変える直前に「すべて送った」とジャーナルに書く。名前を変えた後、ジャーナルを消す前に落ちたときは、
  次に起動したときに「途中のファイルがなく、送り先の大きさが同じ」ことと、アップロードなら末尾の 64 KiB が
  手元と同じこと、ダウンロードなら更新日時（名前を変える前に合わせる）が同じことを確かめて、送り直さずに
  完了とする（置き換えないを選んでいても「既にあります」で止まらない）。
- yysftp は起動中、ジャーナルのフォルダの `yysftp.lock` をほかから開けないように開いておき、正常に
  終了したら消す。起動したときに印が残っていれば前回は正常に終了しなかったと記録に書き、再開を尋ねる
  ときにも知らせる。開けなければ別の yysftp が動いているので、ジャーナルからは再開しない（同じ転送を
  2 つが同時に続けないように）。番号はジャーナルにある番号を避けて振る。
- 転送の中で panic しても作業スレッドは止まらず、その転送を「失敗（再開できます）」にして次へ進む。
  panic は（UI のスレッドで落ちるときも）落ちる前に転送の記録に書く（スタック トレースつき）。

## 6. 転送の記録

- `%APPDATA%\yyeditor\logs\transfer.log`（8 MiB を超えたら `transfer.old.log` に移す）に 1 行ずつすぐ
  追記し、画面の「記録」のタブにも流す。行の先頭は手元の日時（ミリ秒まで）と転送の番号（`[#12]`）。
- 書くこと: 開始（向き・方式・大きさ・ジャーナルの位置）、接続（接続の記録を写す: 経路・ホスト鍵・認証）、
  SFTP の版と拡張、続ける位置の決め方（ジャーナル・途中のファイル・照合）、進み（10 秒または 256 MiB ごとに、
  位置・割合・速さ・確定した位置）、切断（理由・確定した位置・何秒後に何回目の再接続か）、送り終え（平均の速さ）、
  確認（大きさ）、名前の変更、完了・失敗・一時停止、取り消し（途中のファイルの削除）。

## 7. UI（エクスプローラー風）

```
┌─────────────────────────────────────────────────────────────────────┐
│ ← 戻る  進む →  ↑ 上へ  更新 │ アップロード ダウンロード 新しいフォルダ 削除 │ [yamada@build01:/home/yamada  ] 移動 │
├──────────────┬──────────────────────────────────────────────────────┤
│ ▸ build01    │ 名前            更新日時          種類          サイズ   属性      │
│   ▾ ホーム    │ 📁 src          2026/10/06 12:34  ファイル フォルダー        drwxr-xr-x│
│     ▸ src    │ 📄 data.csv     2026/10/05 09:00  CSV ファイル  1,234 KB -rw-r--r--│
│   ▸ /（ルート）│                                                      │
├──────────────┴──────────────────────────────────────────────────────┤
│ [転送] [記録]                                                         │
│ 名前  向き  方式  大きさ  進み  速度  状態  場所                         │
├─────────────────────────────────────────────────────────────────────┤
│ build01　2 個の項目　転送: SFTP                                          │
└─────────────────────────────────────────────────────────────────────┘
```

- 左のツリー: 接続先（設定・最近の接続先）→「ホーム」「/（ルート）」→ フォルダ（開いたときに読む）。
- 右の一覧（詳細表示）: 名前・更新日時・種類・サイズ・属性。アイコンと種類の名前はエクスプローラーと同じ
  （拡張子から）。列の見出しで並べ替え（フォルダが先、名前は自然順）、名前の変更（F2・ゆっくり 2 回クリック）、
  削除（Del）、新しいフォルダ（Ctrl+Shift+N）、すべて選択（Ctrl+A）、Enter・ダブルクリックでフォルダへ入る・
  ファイルを受け取る、Backspace で上へ。右クリックのメニュー。
- アドレスバー（Ctrl+L）: `ユーザー@ホスト:/パス`・`ssh://…`・`/パス`（同じ接続先）。戻る・進む・上へ。
- アップロード: エクスプローラーからのドラッグ＆ドロップ（ファイル・フォルダ）、Ctrl+U、フォルダのアップロード。
  ダウンロード: Ctrl+D（既定の保存先は設定、なければ「ダウンロード」）、保存先を選んでダウンロード。
  フォルダは中身ごと（接続先のシンボリック リンクのフォルダはたどらない）。同じ名前があれば、置き換える・
  飛ばす・やめるを尋ねる。
- 下の欄: 「転送」の一覧（名前・向き・方式・大きさ・進み・速度・状態・場所）と「記録」。一覧の右クリックで
  一時停止・再開・取り消し（途中のファイルも消す）・手元のフォルダを開く・すべて再開・完了したものを消す。
- 転送は 1 本の作業スレッドで順に行い、一覧の接続（SSH）にチャネルを足して使う。切断されたら作業スレッドが
  接続し直す（パスワードなどの問い合わせは UI のダイアログ）。
- 起動したとき、ジャーナルに残っている転送を一覧に並べ、再開するか尋ねる。
- メニュー: ターミナル（yyterm）・エディタ（yyeditor）で開く、SFTP・SCP の切り替え、隠しファイルの表示、
  転送の記録・接続の記録・設定ファイルを開く、保存したパスワードの削除。

## 8. 設定（`[transfer]`）

```toml
[transfer]
protocol = "sftp"        # 転送の方式（"sftp" か "scp"）
retries = 10             # 進みがないまま再接続してよい回数
scp_chunk_mb = 32        # SCP のアップロードで 1 回に送る量（MiB）
show_hidden = false      # 名前が . で始まるファイルも表示する
download_dir = ""        # ダウンロードの既定の保存先（空なら「ダウンロード」フォルダ）
use_agent = false        # 接続先にエージェントを置いて使う（一覧と SHA-256 の照合）
```

## 9. テスト

- `yy-remote`（Linux）: SFTP の読み書き・一覧・名前の変更・削除（本物の sftp-server）、SCP の送受信と
  途中からの受信、ジャーナルの読み書き、途中で切れる接続（決めたバイト数で切る）でのアップロード・
  ダウンロードのレジューム（SFTP・SCP）、再起動後のジャーナルからの再開と末尾の照合（食い違えば最初から）、
  送り先が既にあるときと手元のファイルが変わったときに止めること。
- アプリが落ちたときの再開（`yy-remote`）: 転送の途中で抜ける（後片付けをしない）と、ジャーナルには中断と
  確かな位置が残り、次の実行で続きから送り終える（SFTP・SCP、アップロード・ダウンロード）。名前を変えた後
  ジャーナルを消す前に落ちた転送は送り直さずに完了とし、送り先の中身が違えば送り直す。ジャーナルの書き換えで
  一時ファイルが残らない。Windows: 持ち主の印で、別の yysftp の動作中と前回の異常終了が分かる。
- `yy-ssh`（`apps/yy-agent/tests/ssh.rs`）: 組み込みの SSH の `sftp` サブシステムで転送し、転送の接続に
  エージェントを配置して SHA-256 で照合する（アップロード・ダウンロード）。
- 照合（`yy-remote`）: 一致すれば完了、1 回目が一致しなければ送り直して完了、2 回とも一致しなければ失敗
  （SFTP・SCP、アップロード・ダウンロード）。接続先で計算できなければ飛ばす。
- `RemoteFs`: SFTP での一覧（リンク・読めないリンク）、名前の変更（上書きしない）、削除、`~`。
  エージェントの `Hash`（先頭からの長さ、ファイルより長いときのエラー）。
- Windows の CI: 型検査・clippy・ビルド（`yysftp.exe` を配布物に入れる）。
