# 15. スプレッドシート（yysheet）

エディタ・ターミナル・ファイル転送とは別のアプリとして、同じクレートを使った、速く大量のデータを扱える
スプレッドシート **yysheet** を作ります（2026-10-07 提案）。

## 1. 要求と範囲

| # | 要求 | 優先度 | 対応 |
|---|------|--------|------|
| S1 | エディタ・ターミナル・ファイル転送と別のアプリ（`yysheet.exe`）。これまでのクレートを使う | 高 | 2 |
| S2 | 1000 列 × 5000 万行程度のデータでも、並べ替え・絞り込み・集計が数秒で終わる | 高 | 3・4・9・10 |
| S3 | 独自のファイル形式（速く開けて、速く保存できる） | 高 | 5 |
| S4 | RFC 4180 に準拠した CSV の読み書き（文字コード・区切り文字の選択を含む） | 高 | 6 |
| S5 | Excel 互換の関数: `XLOOKUP`・`SUMIFS`・`COUNTIFS`・文字列の連結・文字列の分割・四則演算・`PRODUCT`・`ABS` | 高 | 7 |
| S6 | Excel 互換の数値・日付の表示形式（書式記号） | 高 | 8 |
| S7 | セルの塗りつぶし・文字の色・罫線（と色） | 高 | 11 |
| S8 | 複数段階の絞り込み（フィルター）と並べ替え（複数のキー） | 高 | 9 |
| S9 | オートシェイプ（図形）・マクロは作らない | — | — |

範囲外: オートシェイプ・図・グラフ、マクロ（VBA・スクリプト）、ピボットテーブル、条件付き書式、
`.xlsx` の読み書き（14 で将来の拡張として扱う）、共同編集、印刷（M6 以降で検討）。関数は S5 の
ものだけを作るが、関数を足しやすい作りにする（7.6）。

### 1.1 「数秒で処理」の前提

1000 列 × 5000 万行は **500 億セル**あり、1 セル平均 4 バイトに詰めても約 200 GB になる。全セルを読む
処理はディスクの速さ（NVMe で 3〜7 GB/s）だけで 30 秒〜1 分かかるので、どんな作りでも数秒にはならない。
そこで次のように目標を定める（10 で詳しく）。

- **数秒で終える**: ファイルを開く・画面を出す・スクロール・ジャンプ、関わる列が数列〜十数列の
  並べ替え・絞り込み・`SUMIFS`・`COUNTIFS`・`XLOOKUP`、セルの編集と再計算、編集後の保存。
  これらは**関わる列だけ**を読むので、全体の列数（1000）には左右されない。
- **ディスクの速さで決まる（数秒より長い）**: 巨大な CSV の取り込み（1 回だけ。取り込み中も先頭から
  見られる）、全列を書き直す保存（整理）、全列の CSV への書き出し。

このため、データは**列ごとに分けて持ち**（列指向）、行の並べ替え・絞り込みは**行番号の並び**
（データを動かさない）で表す。これが全体の設計の軸になる。

想定する手元の機械: 8 コア以上、メモリ 32 GB 以上、NVMe SSD、Windows 10/11（64 ビット）。

## 2. 全体構成

```
apps/yysheet ──► yy-win::run_sheet ──┬─ sheet/mod.rs     フレーム・シートのタブ・数式バー・メニュー・ステータス
                                     ├─ sheet/grid.rs    格子の描画（見える範囲だけ）・選択・編集・IME
                                     ├─ sheet/filter.rs  絞り込み・並べ替えのダイアログ、列見出しのボタン
                                     └─ sheet/format.rs  セルの書式（表示形式・色・罫線）のダイアログ
                   │
                   ├─ yy-sheet    ブック・シート・列の保管（チャンク・差分・スナップショット）・書式・Undo、
                   │              独自のファイル形式、CSV の取り込みと書き出し、絞り込み・並べ替え・索引
                   ├─ yy-formula  数式の解析・依存関係・再計算（セルごとと列まとめて）・関数
                   ├─ yy-numfmt   Excel の表示形式（書式記号の解析と表示）、日付のシリアル値、入力の解釈
                   │
                   └─ これまでのクレート:
                        yy-delimited  RFC 4180 の状態機械・レコードの索引・方言の推定・書き出しの引用符
                        yy-encoding   文字コード（Shift_JIS・EUC-JP・UTF-16・EBCDIC など）の判別と変換
                        yy-io         メモリマップ・共有モードでの読み取り
                        yy-jobs       バックグラウンドの処理（進み・取り消し）
                        yy-search     正規表現（検索・置換・「正規表現に合う」の絞り込み）
                        yy-config     設定・色
                        yy-win の部品 フレーム・同梱フォント・IME・検索バー・ダイアログ・クリップボード・ヘルプ・
                                      最近使ったファイル
```

- `yy-sheet`・`yy-formula`・`yy-numfmt` は OS に依存しない（Linux の CI でテストと性能の計測をする）。
  Windows に関わるのは `yy-win` の `sheet` だけ（ターミナル・ファイル転送と同じ分け方）。
- UI のスレッドは止めない。ファイルを開く・取り込む・並べ替える・絞り込む・再計算する・保存するは
  すべてバックグラウンド（`yy-jobs` の進みと取り消し）で行い、その間は前の状態を表示し続ける。
- データの並列処理には `rayon`（Pure Rust）を使う（チャンクごとに分けて全コアで処理する）。

## 3. データの持ち方（`yy-sheet`）

### 3.1 ブック・シート・領域

- ブックは複数のシートを持つ（タブで切り替え。`XLOOKUP` などは別のシートを参照できる）。
- シートの中身は 2 種類の領域に分ける。
  - **表（テーブル）**: 大量のデータの部分。列ごとに型を持つ列指向の保管（3.2）。CSV を取り込むと
    ここに入る。1 シートに 1 つ、A1 から始まる（見出し行は 1 行目。見出しなしも選べる）。
  - **自由なセル**: 表の外（右や下）に置く、集計表・メモなどの少数のセル。疎な表（`(行, 列) → セル`）
    で持つ。Excel と同じく任意のセルに値・数式・書式を置ける。
- 利用者からは 1 枚の格子に見え、区別を意識させない（表の中のセルに数式を入れれば、そのセルだけの
  上書きになる。3.4）。

### 3.2 列の保管（チャンク）

- 各列は **65,536 行ずつのチャンク**の並びで持つ。チャンクは変更しない（イミュータブル）。5000 万行は
  1 列 763 チャンク、1000 列で約 76 万チャンク。
- チャンクの中身は型ごとに詰めた形（エンコーディング）にする。

| 型 | 中身 | 1 セルの目安 |
|----|------|-------------|
| 数値 | `f64` の並び。整数だけのチャンクは `i64`、さらに範囲が狭ければビット詰め（差分＋ビット幅） | 1〜8 バイト |
| 日付・時刻 | Excel のシリアル値（`f64`）として数値と同じ。列の既定の表示形式を日付にする | 数値と同じ |
| 文字列 | **辞書**（列ごとの文字列の一覧）と辞書番号（`u32`。種類が少なければビット詰め） | 1〜4 バイト＋辞書 |
| 真偽値 | ビット列 | 1/8 バイト |
| 混在 | 型のタグ（ビット詰め）＋型ごとの値 | 型による |

- 空のセル・エラー値は、チャンクごとのビット列（空・エラー）と例外の表で持つ。
- 同じ値が続く部分は連長（RLE）で詰める（見出しの分類・日付の列などで効く）。
- チャンクごとに**統計**（最小・最大・空の数・異なる値の数の目安、文字列なら辞書番号の範囲）を持つ。
  絞り込み・`SUMIFS` で、条件に当たり得ないチャンクを丸ごと飛ばし、Ctrl+↓（データの端へ移動）を
  空の数だけで決める。
- 文字列の辞書には**並び順の順位**（7.5 の照合順で並べたときの順位）を付けて保存する。並べ替えは
  文字列を比べずに順位の整数で行える（9.3）。

### 3.3 行の構造（チャンクの木）

- 行の挿入・削除のために、チャンクの並びは**行数を集約した永続的な木**（エディタのピースツリー〔02 章〕と
  同じ考え方。ノードに「この下の行数」を持つ）にする。行番号からチャンクと位置を O(log n) で求められる。
- 行を途中に挿入すると、その行を含むチャンクだけを（列ごとに）作り直して木に差し込む。チャンクが
  大きくなりすぎたら分け、小さくなりすぎたら隣と合わせる。
- 列の挿入・削除は列の並び（列の一覧）を変えるだけで、他の列には触らない。

### 3.4 編集の差分

- 1 セルの編集のたびにチャンクを作り直さず、シートごとの**差分**（`(列, 行) → 新しい値`。B 木）に
  入れる。読むときは差分を先に見る。
- 差分が一定量（例: 1 列で 4096 セル）を超えたら、バックグラウンドでそのチャンクを作り直して差分から
  外す。
- 大きな操作（貼り付け・下へコピー・置換・並べ替えの確定）は、差分を通さず新しいチャンクを作る。

### 3.5 スナップショットと Undo

- シートの状態（列の一覧・チャンクの木・差分・書式・数式）は、すべて `Arc` で共有する永続的な構造に
  する。**スナップショットは O(1)**（参照を数えるだけ）で取れる。
- Undo は操作の前のスナップショットを積むだけ。5000 万行を書き換えた操作でも、古いチャンクを参照で
  残すだけなので、Undo の記録にデータのコピーは要らない（エディタと同じ方式。06 章）。
- 保存・再計算・並べ替え・絞り込みはスナップショットに対して行うので、処理中も編集を続けられる
  （終わったときに編集が進んでいれば、結果を新しい状態に当て直すか、やり直す）。

### 3.6 メモリ

- 独自形式のファイルはメモリマップ（`yy-io`）して、チャンクを必要になったときに読む（全体を読み込まない）。
  OS のページキャッシュがチャンクのキャッシュになる。
- 詰めた形のままでは処理しにくいチャンク（ビット詰め・RLE）は、展開したものを LRU のキャッシュ
  （既定 2 GB。設定で変えられる）に置く。
- 行番号の並び（`u32` × 5000 万 = 200 MB）、絞り込みのビット列（6 MB）、索引（7.4）が主な常駐の
  メモリ。1000 列分のデータを常駐させることはない。

## 4. 処理の進め方（全体）

- 処理は**列単位・チャンク単位**に分けて `rayon` で並列に行う。1 列 763 チャンクを 8 コアで分ける。
- 処理に関わる列だけを読む（例: 3 列の条件の絞り込みは 3 列だけ）。
- 結果は「行番号の並び」「ビット列」「新しいチャンク」のいずれかで返し、元のデータは変えない。
- 進みはチャンクの数で数え、取り消しはチャンクごとに確かめる（`yy-jobs` の `CancelToken`）。

## 5. 独自のファイル形式（`.yys`）

### 5.1 要件

- 大きさによらず**すぐ開ける**（末尾の目次だけを読む）。
- **少し直しただけなら、すぐ保存できる**（変えたところだけを書き足す）。
- メモリマップしてそのまま読める（チャンクを展開せずに使える形で置く）。
- 壊れにくい（書きかけで落ちても、前に保存した状態は残る）。

### 5.2 構成

```
┌──────────────┐
│ ヘッダー       │ 識別子 "YYSHEET\0"・形式の版・作ったアプリの版
├──────────────┤
│ チャンク       │ 列のチャンク（3.2 の形。8 バイト境界に揃える。チェックサム付き）
│ チャンク       │
│ 辞書・統計     │ 文字列の辞書（並び順の順位を含む）・チャンクの統計
│   …           │
├──────────────┤
│ 目次           │ シート・列（名前・型・既定の表示形式）・チャンクの位置と行数・自由なセル・
│               │ 数式・書式（11.2）・列幅と行の高さ・絞り込みと並べ替えの設定・前の目次の位置
├──────────────┤
│ 末尾           │ 目次の位置と長さ・チェックサム・識別子
└──────────────┘
```

- **書き足しの保存**: 変わったチャンク・辞書・目次だけをファイルの末尾に書き足し、新しい末尾を書く
  （PDF の増分更新と同じ）。最後に `FlushFileBuffers` で書き込みを確かにする。1 セルを直した 200 GB の
  ファイルも、数 MB を書くだけで保存できる。書いている途中で落ちても、古い末尾が有効なまま残る。
- **整理（書き直し）**: 書き足しで使われなくなった部分が一定の割合（既定 30%）を超えたら、保存のときに
  新しいファイルへ書き直して差し替える（エディタの保存と同じ「一時ファイルに書いてから置き換え」）。
  変わっていないチャンクはバイトのままコピーするので、ディスクの速さで終わる。
- 圧縮: 既定は 3.2 の軽い詰め方だけ（展開が速く、メモリマップのまま読める）。文字列の辞書だけは
  LZ4（`lz4_flex`。Pure Rust）で圧縮できるようにする。
- 形式の版を持ち、新しい版のアプリは古い版を読める。形式の仕様は付録に書き、テストで固定する。

## 6. CSV（RFC 4180）

### 6.1 読み込み

- 解析は `yy-delimited` をそのまま使う（RFC 4180 の状態機械、引用符の中の改行・`""`、寛容な引用符の
  扱い、方言の推定 `sniff`）。文字コードは `yy-encoding` で判別・変換する（UTF-8・Shift_JIS・EUC-JP・
  UTF-16・EBCDIC など。エディタと同じ範囲）。
- 開くときに「区切り文字・引用符・文字コード・見出し行の有無・各列の型」を確かめるダイアログを出す
  （推定した値を既定にする。設定で省ける）。

### 6.2 並列の取り込み

巨大な CSV を全コアで取り込むため、ファイルを区切って並列に解析する。

1. ファイルを 64 MB ずつの区画に分ける。
2. 各区画を「先頭が引用符の外」と仮定して並列に解析し、区画の終わりの状態（引用符の中か外か）を記録する。
   同時に「引用符の中」と仮定した場合の終わりの状態も求めておく（2 通り。`Scanner` の状態は 2 つの
   どちらかに収束するので、この 2 通りで足りる）。
3. 先頭から順に、前の区画の終わりの状態で本当の仮定を決め、その仮定での結果を採る（エディタの
   レコード索引〔04 章 3.2〕と同じ考え方）。
4. 各区画の値を列ごとのチャンクに詰める（型の判定と辞書づくりも並列。辞書は最後に合わせる）。

- **型の判定**: 列ごとに先頭の 10 万行で決め（数値・日付・真偽値・文字列）、合わない値が出たら、その値を
  文字列として持つ（混在の列）。`00123`・`1-2` のような、数値や日付にすると元に戻らない値は文字列のまま
  にする（Excel の「勝手に変換される」問題を避ける）。型の判定は、取り込みのダイアログで列ごとに
  変えられる（「すべて文字列」も選べる）。
- 取り込み中も、取り込み済みの先頭から表示・スクロールできる（並べ替え・絞り込みは取り込みが終わってから）。
- 取り込みの速さの目標は 1 コアあたり 300〜500 MB/s。8 コアで 2〜4 GB/s となり、ふつうは**ディスクの
  速さが上限**になる（10）。

### 6.3 CSV のまま開く（取り込まない）

- 「取り込まずに見る」を選ぶと、エディタの CSV モードと同じく、レコードの索引（`RecordIndex`）を
  バックグラウンドで作りながら表示する（取り込みを待たずにすぐ見られる。読み取り専用）。
- 並べ替え・絞り込み・数式を使おうとしたら、取り込みを勧める。

### 6.4 書き出し

- RFC 4180 に従って書く（区切り文字・改行・引用符を含む値だけを引用符で囲み、`"` は `""`。
  `yy-delimited` の `quote_field`・`write_record`）。改行は CRLF（既定）か LF、文字コードは
  `yy-encoding` の範囲から選ぶ。書けない文字があれば、保存の前に一覧で知らせる（エディタと同じ）。
- 値は「表示どおり」（表示形式を当てた文字列。Excel の CSV 保存と同じ）か「元の値」（数値はそのまま、
  日付は ISO 8601）を選ぶ。数式は計算結果を書く。
- 絞り込み中なら「見えている行だけ」も選べる。並べ替えた順で書く。
- CSV に書けないもの（数式・色・罫線・複数のシート）があれば、保存の前に知らせる。
- 書き出しは列を読みながらストリーミングで書く（全体を組み立てない）。

## 7. 数式と関数（`yy-formula`）

### 7.1 文法

- Excel と同じ文法: `=` で始まる。参照（`A1`・`$A$1`・`A1:C10`・`A:A`・`1:1`・`Sheet2!A1`・
  `'売上 2026'!B:B`）、数値・文字列（`"…"`、`""` で `"`）・真偽値（`TRUE`・`FALSE`）・エラー値の定数、
  配列定数（`{1,2;3,4}`）、演算子、関数の呼び出し。関数名は大文字・小文字を区別しない。
- 演算子と優先順位（Excel と同じ）: 参照演算子 `:`、単項の `-`・`+`、`%`、`^`、`*`・`/`、`+`・`-`、
  `&`、比較 `=`・`<>`・`<`・`<=`・`>`・`>=`。
  - 注意する Excel の決まり: `-2^2` は `4`（単項の `-` が `^` より先）、`=1/0` は `#DIV/0!`、
    文字列の比較は大文字・小文字を区別しない、文字列と数値の比較は文字列が大きい。
- 数式の入力では、関数名の補完と引数のヒントを出す。

### 7.2 値と型

- 値: 数値（`f64`）・文字列・真偽値・エラー・空・配列（スピル用）。
- 型の変換は Excel に合わせる: 四則演算で数値に見える文字列は数値にする（`="3"+1` は `4`）、
  見えなければ `#VALUE!`。空は `0` または `""`。真偽値は `1`・`0`。
- エラー値: `#N/A`・`#VALUE!`・`#REF!`・`#DIV/0!`・`#NUM!`・`#NAME?`・`#NULL!`・`#SPILL!`・`#CALC!`。
  関数の引数のエラーは、Excel と同じ規則で伝わる。
- 数値は IEEE 754 の倍精度。表示は Excel と同じく有効数字 15 桁で丸める（`=0.1+0.2` は `0.3` と表示）。
  比較で Excel が行う「ごく近い値を等しいとみなす」丸め（最下位の数ビットを無視する）も合わせる。

### 7.3 関数

| 関数・演算 | 内容 | Excel との互換の要点 |
|-----------|------|--------------------|
| 四則演算 | `+`・`-`・`*`・`/`・`^`・`%`、単項の `-` | 7.1・7.2 の決まり。範囲どうしの演算は要素ごと（スピル） |
| `PRODUCT(数値1, …)` | 積 | 範囲の中の文字列・真偽値・空は無視、引数に直接書いた文字列の数値は数える。引数が全部無視なら `0` |
| `ABS(数値)` | 絶対値 | 範囲を渡すと要素ごと（スピル） |
| `SUMIFS(合計範囲, 条件範囲1, 条件1, …)` | 条件すべてに合う行の合計 | 条件の書き方（7.3.1）、範囲の大きさが違えば `#VALUE!`、合計範囲の数値だけを足す |
| `COUNTIFS(条件範囲1, 条件1, …)` | 条件すべてに合う行の数 | 7.3.1。空の条件は空のセルに合う |
| `XLOOKUP(検索値, 検索範囲, 戻り範囲, [見つからない場合], [一致モード], [検索モード])` | 検索 | 一致モード `0`（完全一致）・`-1`（完全一致か次に小さい）・`1`（完全一致か次に大きい）・`2`（ワイルドカード）、検索モード `1`（先頭から）・`-1`（末尾から）・`2`・`-2`（二分探索）。戻り範囲が複数列なら横にスピル。見つからなければ `#N/A`（第 4 引数があればその値） |
| `&`・`CONCAT(…)`・`TEXTJOIN(区切り, 空を無視, …)` | 文字列の連結 | 数値は表示形式ではなく「標準」の文字列にする（Excel と同じ）。結果が 32,767 文字を超えたら `#VALUE!`。`TEXTJOIN` は範囲・配列を受ける |
| `TEXTSPLIT(文字列, 列の区切り, [行の区切り], [空を無視], [一致モード], [埋める値])` | 文字列の分割 | 区切りは複数（配列定数）も可、一致モード `1` で大文字・小文字を区別しない。結果をスピル。足りない部分は `#N/A`（埋める値があればその値） |

- 文字列の分割・連結の関数として、Excel 365 の `TEXTSPLIT`・`CONCAT`・`TEXTJOIN` と `&` を作る（古い
  `CONCATENATE` も `CONCAT` の別名として受け付ける）。
- **スピル（動的配列）**: `TEXTSPLIT` と、複数の値を返す式（範囲どうしの演算、複数列の `XLOOKUP`）は、
  結果を右・下のセルにあふれさせる（Excel 365 と同じ）。あふれる先に値があれば `#SPILL!`。スピルの範囲は
  `A1#` で参照できる。

#### 7.3.1 条件（`SUMIFS`・`COUNTIFS`）

- `"東京"`（等しい。大文字・小文字を区別しない）、`">=100"`・`"<>"`・`"<>東京"`（比較）、`"東*"`・
  `"??店"`（ワイルドカード `*`・`?`、`~` で打ち消し）、数値・日付（条件の文字列は `">="&A1` のように
  連結で作れる。日付は `"2026/10/1"` のような文字列も日付として比べる）。
- 数値の条件 `"100"` は数値の 100 と、文字列の `"100"` の両方に合う（Excel と同じ）。
- 条件の解釈は、Excel が実際に返す値の表（13）でテストして合わせる。

### 7.4 大量のデータでの計算

5000 万行の表に対して Excel と同じ関数を数秒で計算するため、次の仕組みを持つ。

- **共有式（列の式）**: 表の列全体に入れた式（例: `=C2*D2` を 5000 万行に入れる）は、5000 万個の式を
  持たず、「この列の 2〜50,000,001 行は、行ごとに相対的に同じ式」として 1 つだけ持つ（Excel の `.xlsx`
  の共有式と同じ考え方）。計算はチャンク単位でまとめて（ベクトル化）行う。
- **`SUMIFS`・`COUNTIFS` の計算**: 条件の列を読んでチャンクごとに条件のビット列を作り（チャンクの
  統計で飛ばせるものは飛ばす）、合計範囲の列とまとめて足す。1 つの式は、関わる列（例: 合計 1 列＋
  条件 2 列）を 1 回読むだけ。
- **同じ範囲に対する多数の `SUMIFS`**（集計表で、条件だけを変えた数千〜数万の式）は、1 回の読み取りで
  条件の値ごとの合計をまとめて作り（ハッシュによる集計）、各式はその表を引くだけにする。比較の条件
  （`">="`）が多い場合は、並べた累積和を作って二分探索で引く。
- **`XLOOKUP` の索引**: 完全一致の検索は、検索範囲の列に**ハッシュの索引**を作って持つ（初回だけ
  作り、列が変わるまで使い回す）。1 回の検索は O(1)。5000 万行の列から 5000 万行を引く（表どうしの
  結合）ような共有式も、全コアで数秒で終わる。近似一致（`-1`・`1`）は並べた索引で二分探索する。
  索引の大きさの目安は 5000 万行で 0.6〜1 GB（設定で上限を決め、超えたら作らずに順に探す）。
- **再計算**: セルの依存関係をグラフで持ち、変わったセルから影響のある式だけを計算し直す。範囲の参照
  （`A:A` など）は「範囲 → それを参照する式」の区間の索引で持ち、5000 万行の範囲を参照する式を
  セルごとの辺に展開しない。計算はバックグラウンドで行い、計算中の式は「計算中」と表示する。
  互いに依存しない式は並列に計算する。循環参照は検出して知らせる（反復計算は作らない）。

### 7.5 文字列の比べ方（照合順）

- 比較・並べ替え・`XLOOKUP` の近似一致・条件の比較で使う文字列の順を 1 つに決める。既定は Excel の
  日本語の環境に近い順: 大文字・小文字を区別しない、全角・半角の英数字を同じに扱わない（Excel と同じ）、
  ひらがなとカタカナは並べ替えでは近くに置く。正確な規則は Excel の結果の表（13）で決める。
- 等しいかどうか（`=`・完全一致・`SUMIFS` の等しい）は、大文字・小文字の区別だけを外して比べる。

### 7.6 関数を足しやすい作り

- 関数は「名前・引数の数・引数ごとの扱い（範囲を受けるか、配列で要素ごとか）・本体」の表で登録する。
  共有式でのまとめた計算が要るものは、まとめた計算も登録する（なければ 1 行ずつ計算する）。
- S5 にない関数（`IF`・`SUM`・`LEFT` など）は今回は作らないが、同じ表に足すだけで使えるようにする。
  未登録の関数は `#NAME?`。

## 8. 表示形式（`yy-numfmt`）

Excel の表示形式（書式記号）を Excel と同じ結果になるように作る。

### 8.1 書式記号

| 種類 | 記号 |
|------|------|
| 区分 | `正;負;ゼロ;文字列` の最大 4 区分、条件 `[>=100]`・`[<0]`、色 `[赤]`・`[Red]`・`[色10]`・`[Color10]` |
| 数値 | `0`・`#`・`?`・`.`・`,`（桁区切り。末尾の `,` は千で割る）、`%`、`E+`・`E-`、分数 `# ?/?`・`# ??/16` |
| 文字 | `"文字列"`・`\x`（1 文字）・`_x`（x の幅の空白）・`*x`（列幅まで x で埋める）・`@`（文字列そのもの） |
| 日付 | `yyyy`・`yy`・`m`・`mm`・`mmm`・`mmmm`・`mmmmm`・`d`・`dd`・`ddd`・`dddd`・`aaa`・`aaaa`（日本語の曜日） |
| 時刻 | `h`・`hh`・`m`・`mm`（`h` の後・`s` の前なら分）・`s`・`ss`・`.0`〜`.000`・`AM/PM`・`A/P`・`午前/午後`、経過時間 `[h]`・`[mm]`・`[ss]` |
| 和暦 | `g`・`gg`・`ggg`（元号）・`e`・`ee`（年）、`[$-ja-JP]`・`[$-411]`（ロケールの指定） |
| 通貨 | `¥`・`$`・`[$¥-ja-JP]` など |
| その他 | `General`（`標準`）、`[DBNum1]`〜`[DBNum3]`（漢数字。M6 以降） |

- 書式記号は解析して保存し、セルごとに書式の番号で参照する（同じ書式記号は 1 つだけ持つ）。
- Excel の組み込みの表示形式（番号 0〜49 と日本語の環境の 50〜58 など）を同じ番号で持つ。
- **標準（General）**: 列幅に収まるように丸め、収まらなければ指数表記にする Excel の規則も合わせる
  （列幅を変えると表示が変わる）。数値が列幅に収まらない表示形式では `####` にする。

### 8.2 日付

- 日付はシリアル値（1900 年 1 月 1 日が 1）。Excel と同じく **1900 年 2 月 29 日（シリアル値 60）が
  あるものとする**（1900 年のうるう年の誤り）。ブックの設定で 1904 年の日付（Mac の Excel）も選べる。
- 和暦は明治・大正・昭和・平成・令和（元号の境目の日付を表で持つ。新しい元号は設定で足せる）。

### 8.3 入力の解釈

- セルに入力した文字列を、Excel の日本語の環境と同じ規則で数値・日付・時刻・百分率・通貨に
  解釈し、表示形式も自動で付ける（`2026/10/7` → 日付と `yyyy/m/d`、`10/7` → 今年の日付、`1,234` →
  数値と桁区切り、`15%` → 0.15 と `0%`、`R8.10.7`・`令和8年10月7日` → 日付と和暦）。
- 先頭の `'` で文字列として入力する（Excel と同じ）。

## 9. 絞り込みと並べ替え

### 9.1 表し方

- 並べ替え・絞り込みは表のデータを動かさず、**表示する行番号の並び**（`u32` の配列。全行なら持たない）と
  して持つ。数式の参照（`A2` など）は元の行を指したまま。
- 「並べ替えを確定」で、並べた順にチャンクを作り直す（バックグラウンド。Undo できる）。
- 絞り込みと並べ替えの設定はファイルに保存し、開いたときに当て直す。

### 9.2 絞り込み（複数段階）

- 列見出しのボタンから列ごとの条件を付け、**すべての列の条件を満たす行**を表示する（Excel のオート
  フィルターと同じ。列の数に制限はない）。条件を付けた順に「段階」として並べて見せ、各段階の
  残りの行数を表示する。段階を外す・並べ替える・一時的に止めることができる。
- 列の条件の種類:
  - 値の一覧（チェックボックス。値ごとの件数付き。文字列の列は辞書から作るので、5000 万行でもすぐ出る。
    異なる値が多ければ検索して選ぶ）
  - 文字列: 等しい・含む・で始まる・で終わる・ワイルドカード・正規表現（`yy-search`）・空・空でない
  - 数値・日付: 比較・範囲・上位／下位 N 件・平均より上／下・期間（今日・今月・前年など）
  - 色: 塗りつぶしの色・文字の色（11）
  - 1 列に条件を 2 つまで（AND・OR）
- 計算: 条件ごとにチャンク単位で並列にビット列を作り（統計で当たらないチャンクは飛ばす）、段階の順に
  AND を取る。条件を 1 つ変えたら、その段階から先だけを計算し直す（前の段階のビット列は残す）。
- 絞り込んだあとの列見出しの値の一覧は、ほかの列の条件で残った行の値だけを出す（Excel と同じ）。

### 9.3 並べ替え（複数のキー）

- キーは列ごとに昇順・降順、並べ替えの対象（値・塗りつぶしの色・文字の色）、ユーザー定義の順（例:
  「北海道, 東北, 関東, …」）を選べる。キーの数に制限はない（目安 64）。安定な並べ替え（同じキーの
  行は元の順を保つ）。
- 値の順は Excel と同じ: 数値 < 文字列 < 真偽値 < エラー、**空のセルは昇順・降順とも最後**。文字列は
  7.5 の照合順。
- 計算:
  1. 各キーを、順序を保つ整数に変える（数値は `f64` のビットを順序の保たれる `u64` に、文字列は辞書の
     **並び順の順位**〔3.2〕に、型の違いと空は上位のビットに）。文字列を比べる処理はここでは起きない。
  2. キーの整数の幅を合わせて 1 つの整数（64 ビットまたは 128 ビット）に詰められれば、行番号と組にして
     **並列の基数ソート**を 1 回行う。詰められなければ、後ろのキーから順に安定な基数ソートを重ねる。
  3. 絞り込み中なら、残った行だけを並べる。
- 5000 万行・キー 1〜3 列で 1〜2 秒程度が目安（10）。

### 9.4 そのほかの大量データの操作

- 重複の削除（列を選んで）、列の値の置換（正規表現）、下へのコピー（共有式になる）、列の型の変更は、
  いずれもチャンク単位の並列処理で新しいチャンクを作る。
- ステータスバーに、選んだ範囲の個数・合計・平均を出す（Excel と同じ。絞り込み中は見える行だけ）。
  5000 万行の列を選んでも、チャンクの統計と並列の計算で 1 秒以内に出す（計算中は「計算中」）。

## 10. 性能の目標と見積もり

見積もりの前提: 8 コア、メモリ 32 GB、NVMe（読み取り 3 GB/s）。データは 5000 万行。「温」はデータが
ページキャッシュにある場合、「冷」はディスクから読む場合。数値の列 1 列は詰めて 100〜400 MB。

| 操作 | 読む量 | 目標（冷／温） |
|------|-------|---------------|
| 独自形式のファイルを開いて最初の画面を出す | 目次と見える部分 | 0.5 秒未満（大きさによらない） |
| スクロール・ジャンプ（Ctrl+↓・行番号へ移動） | 見える部分 | 16 ms 未満 |
| 1 列の条件で絞り込み（数値の比較） | 1 列 | 0.2 秒 ／ 0.05 秒 |
| 5 列の条件で絞り込み | 5 列 | 1 秒 ／ 0.3 秒 |
| 値の一覧（文字列の列。件数付き） | 辞書と辞書番号 | 1 秒 ／ 0.3 秒 |
| 並べ替え（数値 1 キー） | 1 列＋行番号 200 MB | 1.5 秒 ／ 1 秒 |
| 並べ替え（3 キー。文字列を含む） | 3 列 | 3 秒 ／ 2 秒 |
| `SUMIFS`・`COUNTIFS` 1 つ（条件 2 つ） | 3 列 | 0.5 秒 ／ 0.1 秒 |
| 同じ範囲の `SUMIFS` 1 万個（集計表） | 3 列（1 回） | 1 秒 ／ 0.5 秒 |
| `XLOOKUP` の索引づくり（完全一致） | 1 列 | 2 秒（初回だけ） |
| `XLOOKUP` を 5000 万行の共有式で（表どうしの結合） | 2 列＋索引 | 5 秒 ／ 3 秒 |
| 共有式の四則演算（`=C2*D2` を 5000 万行） | 2 列 | 1 秒 ／ 0.3 秒 |
| セルの編集から再表示 | 依存する式だけ | 16 ms 未満（依存する集計の再計算は上の目安で裏で） |
| 編集後の保存（書き足し） | 変わった部分 | 1 秒未満 |
| CSV の取り込み | CSV 全体 | ディスクの速さ（3 GB/s で 30 GB の CSV が約 10〜15 秒） |

- **1000 列 × 5000 万行の CSV**（1 セル平均 6 バイトとして約 300 GB）の取り込みは、ディスクの速さで
  **約 2 分**かかる。取り込みは最初の 1 回だけで、その後は独自形式で上の表の速さになる。取り込み中も
  先頭から見られる。
- 独自形式のファイルの大きさは、1000 列 × 5000 万行で 100〜250 GB 程度（データ次第）。
- 性能の計測は Linux の CI（小さめのデータ）と、手元の計測用の機械（目標の大きさ）で行い、
  `tools/` に計測用のデータを作る道具を足す（13）。

## 11. 書式（色・罫線）

### 11.1 できること

- 塗りつぶしの色、文字の色、太字・斜体・下線・取り消し線、文字の大きさ・フォント、配置（左・中央・右、
  上・中央・下、折り返し、インデント）、罫線（上下左右と斜め。線の種類: 細線・中線・太線・点線・破線・
  二重線。線ごとの色）、表示形式（8）。
- 色は Excel と同じテーマの色・標準の色の一覧と、任意の RGB を選べる。
- 書式のコピー（書式のブラシ）、書式のクリア。

### 11.2 持ち方

- 書式は「書式の組（色・罫線・表示形式などの組み合わせ）」として 1 つだけ持ち、セルは組の番号を持つ
  （同じ組は共有。Excel の `.xlsx` のスタイルと同じ考え方）。
- 5000 万行に個別の番号を持たないよう、書式は**範囲で持つ**: 列全体の書式、行全体の書式、長方形の範囲の
  書式（区間の木）、個別のセル（疎な表）を重ね、後から付けたものが優先する。表の列ごとの書式は
  チャンク単位の連長（RLE）でも持てる（色分けした行が交互に並ぶ場合など）。
- 罫線は隣のセルとの共有の辺として解決する（Excel と同じく、右のセルの左の罫線と左のセルの右の罫線が
  違えば優先の規則で決める）。

  Shift+Space（行）・F2（編集）・Enter／Tab（確定して移動）・Esc・Ctrl+Enter（選んだ範囲に入れる）・
  Ctrl+D（下へコピー）・Ctrl+Z／Y・Ctrl+F／H（検索・置換。`yy-search`）・Ctrl+1（セルの書式）・
  Ctrl+Shift+L（絞り込みの切り替え）・F4（参照の `$` の切り替え）・Ctrl+;（今日の日付）。
- セルの編集は IME のインライン変換に対応する（エディタの IME の部品を使う）。
- クリップボード: Excel との間でコピー・貼り付けできるよう、タブ区切りの文字列（`CF_UNICODETEXT`）と
  HTML の表（色を含む）で書き、読むときは両方を受け付ける。大量の範囲（例: 100 万セルを超える）は確かめて
  から行い、バックグラウンドで作る。
- ファイルの関連付け（`.yys`）、最近使ったファイル、ドラッグ＆ドロップで開く、エディタ（yyeditor）で
  CSV を開いている場合の「yysheet で開く」。
- 設定（`config.toml` の `[sheet]`）とヘルプ（`help.md` に章を足す）はほかのアプリと共通の仕組み。

## 13. テスト

- **関数の互換**: Excel で実際に計算した結果の表（入力・式・期待値。日本語の文字列、空・エラー・型の混在、
  ワイルドカード、照合順、スピル、`XLOOKUP` の全モードを含む）を用意し、`yy-formula` の結果と比べる。
  表は CSV で `tests/` に置き、Excel で作り直せる手順も書く。
- **表示形式の互換**: 書式記号と値の組（数千通り。日付・和暦・経過時間・分数・条件・色・`General` と
  列幅）を Excel で表示した文字列の表と比べる。入力の解釈（8.3）も同じ方法でテストする。
- **CSV**: RFC 4180 の例、引用符の中の改行、壊れた引用符、各文字コード、並列の取り込みと 1 スレッドの
  取り込みが同じ結果になること（区画の境目が引用符の中に入る場合を含む。乱数で作った CSV で性質のテスト）、
  書き出して読み直して同じになること。
- **独自形式**: 書き足しの保存を繰り返しても読み直せること、途中で書くのをやめたファイルが前の状態で
  開けること、整理の前後で中身が同じこと、古い版の形式を読めること。
- **絞り込み・並べ替え**: 単純な実装（全行を比べて並べる）と結果が同じこと（乱数のデータで性質のテスト）、
  安定であること、空・型の混在の順。
- **再計算**: 依存関係（範囲の参照・別シート・スピル・循環）を変えたあとの結果が、全部を計算し直した
  結果と同じこと。
- **性能**: `tools/gen-sheet`（計測用の大きなデータを独自形式・CSV で作る）と、10 の表の操作を測る
  計測の道具。CI では 500 万行 × 50 列で回帰を見張り、目標の大きさ（5000 万行 × 1000 列）は手元の機械で
  測って記録する。
- **UI**: Windows の CI で、起動・CSV を開く・入力・絞り込み・保存の一連の操作。

## 16. 決めていただきたいこと

| # | 事項 | 提案 |

| 1 | アプリの名前・独自形式の拡張子 | `yysheet`・`.yys` |
