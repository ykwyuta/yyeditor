# 05. 正規表現検索・置換

## 1. 要求

- 通常文字列・正規表現による検索、置換、すべて置換
- 大文字小文字の区別、単語単位、選択範囲内、区切り文字モードでの列限定
- 数 GB のファイルでも UI を止めずに検索・全置換でき、キャンセル可能
- 複数行にまたがるパターン（`\n` を含む正規表現）
- 置換文字列でのキャプチャ参照（`$1`, `${name}`）、特殊文字（`\n`, `\t`）、大文字小文字変換（`\U`, `\L`, `\E`）

## 2. 正規表現エンジンの選定

| エンジン | 特徴 | 位置づけ |
|---------|------|---------|
| `regex`（`regex::bytes`） | 線形時間保証（ReDoS なし）、SIMD リテラル最適化、非常に高速。後方参照・先読み/後読みは非対応 | **既定エンジン** |
| `fancy-regex` | 後方参照・先読み・後読みに対応（バックトラッキング）。内部で `regex` に委譲できる部分は委譲 | パターンにこれらの構文が含まれる場合に**自動切替** |
| `regex-automata` | `regex` の低レベル API。逆方向 DFA、ストリーミング用の状態保持 | 後方検索・チャンク境界処理に使用 |

- パターン構文を解析し、後方参照 `\1` や `(?=...)` `(?<=...)` を含む場合のみ `fancy-regex` を使います。この場合はバックトラッキングの計算量爆発に備え、ステップ数上限とタイムアウトを設定します。
- EmEditor / 秀丸ユーザーのために、Perl/Onigmo 風の構文差（`\<` `\>` 単語境界、`\h` など）を `regex` 構文へ変換する前処理レイヤーを用意します。
- 日本語向けオプション: 全角/半角を同一視、ひらがな/カタカナを同一視（パターン展開による実装）。

## 3. 検索の実装

### 3.1 対象データ

バッファは UTF-8 のバイト列（不正バイトを含み得る）なので `regex::bytes::Regex` を使い、`(?u)` で Unicode 対応を有効にします。

### 3.2 連続領域とチャンク検索

ピースツリーの内容はメモリ上で連続していないため、次のように使い分けます。

| 状況 | 方式 |
|------|------|
| 未編集の巨大ファイル（ピースがすべて同じソースで連続） | **mmap 全体を 1 つの `&[u8]` として直接検索**（コピーなし、最速） |
| 編集済み | 隣接ピースが同一ソースで連続していれば結合し、連続区間ごとに検索。区間境界はオーバーラップ付きウィンドウで検索 |

**ウィンドウ検索**: 境界をまたぐマッチを取りこぼさないよう、4 MiB のウィンドウに前ウィンドウの末尾 `overlap` バイトを重ねて連結・検索します。

- `overlap` の既定は 64 KiB。パターンの最大マッチ長が静的に分かる場合（`regex-syntax` の HIR から算出）はその長さを使う。
- `.*` 等で最大長が無制限なパターンは、既定では「1 マッチは改行をまたがない（`.` は改行にマッチしない）」ので行単位で完結し問題にならない。`(?s)` や `[\s\S]*` で改行をまたぐ無制限パターンのみ、マッチ長上限（既定 1 MiB、設定可能）を適用し、超える場合は警告を表示する。

### 3.3 インクリメンタル検索と「次を検索」

- 「次を検索」はカーソル位置から前方にウィンドウ検索し、最初のマッチで打ち切る。巨大ファイルで遠くにしかマッチがない場合も、ジョブとして実行し進捗バーとキャンセルを提供。
- 「前を検索」は `regex-automata` の逆方向 DFA で後方にスキャンして候補開始位置を求め、前方検索で確定する。
- 入力中のインクリメンタル検索は、表示範囲周辺を同期的に、それ以外をバックグラウンドで検索。

### 3.4 マッチのハイライトと件数

- 検索ジョブはマッチ位置を「スナップショット世代付き」で UI へ送信する。表示中の範囲のマッチは即座にハイライト。
- 全件数カウントは並列（ピース区間ごとに `rayon` で分割、境界部分は逐次で補正）。
- マッチ位置の保持はメモリを食うため、全マッチを保持するのは 100 万件まで。超える場合は件数のみ保持し、ハイライトは表示範囲の再検索で行う。
- 編集が入った場合、編集範囲外のマッチ位置はオフセット補正し、編集範囲周辺だけ再検索する。

### 3.5 検索オプション

| オプション | 実装 |
|-----------|------|
| 大文字小文字を区別しない | `(?i)` |
| 単語単位 | `\b...\b`（日本語では文字種境界を単語境界とする独自判定をオプションで提供） |
| 選択範囲内 | 検索区間を選択範囲に限定。マルチ選択・矩形選択の場合は複数区間（矩形は行ごとの範囲） |
| 列限定（区切り文字モード） | マッチ位置を (レコード, フィールド) に変換し、対象列のみ採用。`^` `$` をフィールドの先頭・末尾として扱うオプション |
| 複数ファイル検索（Grep） | 指定フォルダ配下を `ignore` クレートで列挙し、ファイルごとに文字コード判別して検索。結果一覧ウィンドウ |

## 4. 置換の実装

### 4.1 単発の置換

1 マッチの置換 = 1 回の削除＋挿入。通常の編集コマンドとして実行し、Undo 1 単位。

### 4.2 すべて置換

マッチ数によって方式を切り替えます。

| マッチ数 | 方式 |
|---------|------|
| 少数（既定 1 万件未満） | ピースツリーへの一括編集。すべての編集を 1 つのトランザクションとして適用（Undo は 1 単位） |
| 多数 | **ストリーミング書き換え**: スナップショットを先頭から読み、マッチ部分を置換しながら新しい一時ファイル（UTF-8）に書き出し、完了後にツリー全体をその一時ファイルを参照する新しいツリーに差し替える。Undo は差し替え前のスナップショットに戻すだけなので O(1) |

- ストリーミング書き換え中も UI は操作可能（ただし当該ドキュメントは読み取り専用にロック）。キャンセル時は一時ファイルを破棄するだけ。
- 書き換え後の新しいファイルに対して Indexer / CSV Scanner を再実行（新ファイルは書き出し時に改行数を同時カウントしておくことで再走査を省略）。
- 1 億件の置換でもメモリは一定（ピースを 1 億個作らない）。

### 4.3 置換文字列

```
$0, $1, ${name}   キャプチャ参照
\n \t \r \\ \$    特殊文字
\U...\E           大文字化
\L...\E           小文字化
\u \l             次の 1 文字のみ大文字/小文字化
```

`yy-search` 内で置換文字列を事前にトークン列へコンパイルし、マッチごとに高速に展開します。

## 5. API 概要

```rust
pub struct SearchQuery {
    pub pattern: String,
    pub kind: PatternKind,          // Literal | Regex
    pub case_sensitive: bool,
    pub whole_word: bool,
    pub scope: SearchScope,         // Document | Selections(Vec<Range>) | Rect(RectSelection) | Columns(Vec<usize>)
    pub max_match_len: usize,
}

pub struct Searcher { /* コンパイル済みパターン（regex / fancy-regex） */ }

impl Searcher {
    pub fn find_next(&self, snap: &Snapshot, from: u64, ctx: &JobContext) -> Option<Match>;
    pub fn find_prev(&self, snap: &Snapshot, from: u64, ctx: &JobContext) -> Option<Match>;
    pub fn find_all(&self, snap: &Snapshot, ctx: &JobContext, sink: impl FnMut(Match));
    pub fn replace_all(&self, snap: &Snapshot, repl: &Replacement, ctx: &JobContext)
        -> Result<ReplaceOutcome, JobError>;   // Edits(Vec<Edit>) | NewSource(TempFile)
}
```
