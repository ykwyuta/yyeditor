# 07. UI と描画

## 1. ウィンドウ構成

```
┌──────────────────────────────────────────────────────────────┐
│ メニューバー（ファイル / 編集 / 検索 / 表示 / 区切り文字 / 文字コード / ツール） │
├──────────────────────────────────────────────────────────────┤
│ ツールバー（任意）                                              │
├──────────────────────────────────────────────────────────────┤
│ タブバー（複数ドキュメント）                                     │
├─────┬────────────────────────────────────────────────────────┤
│行番号│ ルーラー（列番号 / CSV 列名）                             │
│     ├────────────────────────────────────────────────────────┤
│     │ EditorView（独自コントロール, Direct2D/DirectWrite）      │
│     │                                                        │
├─────┴────────────────────────────────────────────────────────┤
│ 検索バー（インライン, Ctrl+F）                                   │
├──────────────────────────────────────────────────────────────┤
│ ステータスバー: 行:列 | 文字コード | 改行 | モード | 進捗 | 挿入/上書 │
└──────────────────────────────────────────────────────────────┘
```

- メニュー・ツールバー・タブ・ステータスバー・ダイアログは Win32 標準コントロール（Common Controls v6）。
- 検索・置換は非モーダルのインラインバー＋詳細ダイアログ。
- ステータスバーの文字コード・改行コード表示をクリックすると「この文字コードで開き直す / この文字コードで保存する」メニューを表示（VS Code 風）。

## 2. EditorView（独自テキストビュー）

### 2.1 描画パイプライン

```
スクロール位置（バイトオフセット＋表示行内オフセット）
  │
  ▼  yy-layout: 表示範囲の論理行を取得（ピースツリーから必要な行だけ読む）
  │             → 折り返し・表示セグメント分割・CSV セル配置・タブ展開
  ▼  VisualLine の列（テキスト、属性スパン: 選択/検索ハイライト/構文色/不正バイト）
  │
  ▼  yy-win レンダラ: IDWriteTextLayout を行ごとに生成（LRU キャッシュ）
  │                  → ID2D1DeviceContext に描画
  ▼  IDXGISwapChain1::Present（ちらつきなし）
```

- **描画するのは表示範囲の行だけ**（通常 50〜200 行）。ファイルサイズは描画コストに影響しない。
- 行レイアウトキャッシュ: `(スナップショット世代, 行開始オフセット) → IDWriteTextLayout`。編集された行のみ無効化。
- 等幅フォント前提の高速パス: ASCII と東アジア全角のみの行は `unicode-width` による幅計算で x 座標を決め、`IDWriteTextLayout` を使わず `DrawGlyphRun` で直接描画する。プロポーショナルフォント・合字・結合文字・絵文字を含む行は DirectWrite のレイアウトに委ねる。
- カラー絵文字（`D2D1_DRAW_TEXT_OPTIONS_ENABLE_COLOR_FONT`）、異体字セレクタ、サロゲートペアに対応。カーソル移動・削除は書記素クラスタ単位（`unicode-segmentation`）。

### 2.2 特殊表示

| 要素 | 表示 |
|------|------|
| タブ・全角空白・半角空白・改行（CRLF/LF/CR 別）・EOF | 設定で可視化 |
| 不正バイト（`U+10FExx` エスケープ / 不正 UTF-8） | `\x81` のような枠付きグリフ |
| 制御文字 | `^A` のような表記 |
| 表示セグメント境界（長大行の強制分割） | 行番号欄にマーク |
| CSV のフィールド内改行 | `↵` |
| 引用符不整合・フィールド数不一致レコード | 行番号欄に警告マーク |

### 2.3 スクロール

- 巨大ファイルでは縦スクロールバーは **バイト位置比例**（32bit のスクロール範囲に収まるようにスケーリング）。行数確定後も、ファイルサイズが大きい場合はバイト比例を維持し、ドラッグで任意位置へ即時ジャンプできる。
- 行数が小さいファイル（既定 100 万行未満）では行比例のスクロールバー。
- 折り返し有効時の総表示行数は巨大ファイルでは計算しない（表示範囲のみ折り返し計算）。

### 2.4 シンタックスハイライト

ファイル種類別のハイライトは [10 章](10-syntax-highlight.md) を参照。描画層は `yy-layout` が重ね合わせた属性スパン（シンタックス・選択・検索マッチ等）ごとに色・書式を設定するだけで、ハイライトの解析自体は `yy-syntax` が行う。

## 3. 日本語入力（IME）

日本語エディタとして最重要の要素の一つです。

- まず IMM32 で実装: `WM_IME_STARTCOMPOSITION` / `WM_IME_COMPOSITION` / `WM_IME_ENDCOMPOSITION` を処理し、`ImmGetCompositionStringW` で未確定文字列・文節属性・カーソル位置を取得して **EditorView 内にインライン描画**（下線・太下線で文節表示）。
- `ImmSetCompositionWindow` / `ImmSetCandidateWindow` で候補ウィンドウをカーソル位置に追従させる。
- 再変換（`WM_IME_REQUEST` / `IMR_RECONVERTSTRING`）、確定取り消しに対応。
- 将来: TSF（Text Services Framework）の `ITextStoreACP` 実装に移行し、手書き入力・音声入力・タッチキーボードとの親和性を高める。
- 区切り文字モードではセル内に未確定文字列を描画し、列幅は確定まで仮拡張。

## 4. 操作系

| 機能 | 内容 |
|------|------|
| キーバインド | Windows 標準（Ctrl+Z/Y/F/H/G/S）＋設定ファイルでカスタマイズ |
| 複数カーソル・矩形選択 | Alt+ドラッグで矩形選択、Ctrl+クリックでカーソル追加（詳細は [09 章](09-multi-cursor-rectangle.md)） |
| 分割ウィンドウ | 同一ドキュメントを上下 2 分割（スナップショット共有なので追加メモリほぼ不要） |
| ドラッグ＆ドロップ | ファイルを開く、テキストの移動・コピー |
| 最近使ったファイル | ジャンプリスト連携 |
| 印刷 | 表示範囲・選択範囲の印刷（巨大ファイルは範囲指定を必須化） |
| ダークモード | Windows のアプリモード設定に追従（`DwmSetWindowAttribute` の `DWMWA_USE_IMMERSIVE_DARK_MODE`） |
| 高 DPI | Per-Monitor V2。モニター間移動でフォントサイズ・レイアウトを再計算 |
| 長いパス | `\\?\` プレフィックス対応、マニフェストの `longPathAware` |

## 5. 応答性の設計

- UI スレッドで行う処理は「表示範囲に比例する処理」と「ピースツリーへの O(log n) 編集」だけに限定し、ファイルサイズに比例する処理は必ずジョブにする（コードレビューのチェック項目とする）。
- 長時間ジョブ中はステータスバーに進捗とキャンセルボタン（Esc でもキャンセル）を表示。
- 50 ms を超えて UI スレッドがブロックされた場合に `tracing` で警告を出すウォッチドッグをデバッグビルドに組み込む。

## 6. 異常終了の記録

- yyeditor・yyterm・yysftp・yysheet は起動の初めに `crash::install` を呼ぶ。panic の hook（前の hook に
  つなぐ）と、Windows の処理されない例外のフィルター（`SetUnhandledExceptionFilter`。アクセス違反など）で、
  `%LOCALAPPDATA%\yyeditor\logs\crash-アプリ-日時-プロセス番号.log` に版・ビルドの種類・日時・プロセス・
  実行ファイル・スレッド・panic の文言と場所（例外ならコードとアドレス）・バックトレースを書く。
- 知らせ（記録の場所のメッセージボックス）は UI のスレッドの panic と例外のときだけ。作業スレッドの panic は
  `catch_unwind` で受け止めて続けることがある（転送・計算のジョブ）ので、記録だけ書く。
- 起動中は `running-アプリ-プロセス番号.txt` を共有なし（ほかのプロセスから消せない）で開いておき、正しく
  終われば消す。次の起動で消せる印が残っていれば前回は異常終了（記録を書けなかったときも分かる）。同時に
  動いているウィンドウの印は消せないので数えない。yysheet はステータスバーで知らせ、ヘルプのメニューから
  記録のフォルダを開ける。記録は新しいものから 30 個まで残す。
