# 16. ソース管理（Git）

yyeditor に、VS Code のソース管理と同じ形の Git の連携を足す。コアは `yy-git`（OS に依存しない。Linux の CI で
実際の git を使って試験する）、画面は `yy-win` の `app/gitmode.rs`。

## 1. 方針

- **Git の実装は持たず、入っている `git` コマンドを呼ぶ。** 資格情報（Git Credential Manager）・SSH の鍵・
  フック・`.gitconfig`・LFS などが、コマンド プロンプトの git とそのまま同じになる。libgit2 などを組み込むと、
  これらを作り直すことになり、利用者の環境の設定ともずれる。
- 呼び方: `git -C <作業ツリー> -c core.quotepath=off -c color.ui=false …`。環境変数 `GIT_TERMINAL_PROMPT=0`
  （端末でパスワードを尋ねて固まらない。資格情報マネージャーの画面は出てよい）、`GIT_EDITOR=true`
  （エディタを開かない）。Windows ではコンソールの窓を出さない（`CREATE_NO_WINDOW`）。`YYEDITOR_GIT` で
  git の場所を変えられる。git がなければ「Git for Windows を入れて PATH を通す」と知らせる。
- 状態は `git --no-optional-locks status --porcelain=v2 --branch -z --untracked-files=all` を読む
  （ブランチ・HEAD・上流・ahead/behind・変更。パスは NUL 区切りで、空白や日本語もそのまま）。
  `--no-optional-locks` で、裏で読むときにほかの git の操作と index のロックを取り合わない。

## 2. リポジトリの検出と選択

- ワークスペースのフォルダ（手元のもの）の下を幅優先でたどり、`.git`（中に `HEAD` のあるフォルダ、または
  サブモジュール・`git worktree` の `.git` ファイル）のあるフォルダを集める。深さ 8・フォルダ 50,000 個まで。
  `.git`・`node_modules`・`.svn`・`.hg` などの下は見ず、シンボリック リンク・ジャンクションはたどらない。
  リポジトリの中も続けてたどる（入れ子のリポジトリ・サブモジュールも並べる）。
- ワークスペースのフォルダ自体がリポジトリでなければ、上のフォルダをたどって、含むリポジトリも入れる
  （ワークスペースにリポジトリの中の一部のフォルダだけを登録したとき）。
- 一覧の名前はワークスペースのフォルダの名前からの相対パス（`app/libs/core`）。探すのは作業スレッドで行う。
- **どれを表示するかは使う人が 1 つ選ぶ**（一覧の上のコンボ ボックス）。1 つだけなら自動で選ぶ。選んだものは
  設定フォルダの `last-git-repo.txt` に覚え、次に探したときにあれば選ぶ。ワークスペースのフォルダが変わったら
  探し直す。

## 3. 操作

| 操作 | git |
|---|---|
| ステージ | `add -A -- パス…`（削除も） |
| ステージの解除 | `reset -q -- パス…`（まだコミットがなければ `rm --cached -r -q`） |
| 変更の破棄 | 追跡しているもの `checkout -q -- パス…`（ステージした版に戻す）、追跡していないもの `clean -f -q -- パス…` |
| コミット | `commit -q -F - --cleanup=strip`（メッセージは標準入力。amend は `--amend`） |
| 版の中身 | `cat-file -e` で有無を見て `cat-file blob HEAD:パス`・`:パス`（インデックス） |
| ブランチ | `for-each-ref refs/heads refs/remotes`、切り替え `checkout`、リモートのブランチは手元にあればそれ、なければ `checkout --track`、作成 `checkout -b`（`check-ref-format --branch` で名前を確かめる） |
| プル・フェッチ | `pull`・`fetch --prune` |
| プッシュ | 上流があれば `push`、なければ最初のリモート（`origin` を先に）へ `push -u リモート ブランチ` |

## 4. ソース管理のビュー

- サイドバーに、エクスプローラー（ツリー）と切り替えて出す（Ctrl+Shift+E・Ctrl+Shift+G。VS Code のアクティビティ
  バーの代わり）。中身は 1 つの子ウィンドウ（`YYEditorGit`）にまとめ、通知はそこで受ける。
- 上から: リポジトリの一覧（コンボ ボックス）、ブランチのボタン（`⎇ main ↑1 ↓2`。押すとブランチのメニュー）・
  ↻（読み直す）・「…」（プル・プッシュ・同期・フェッチ・まとめての操作・amend・探し直す・出力）、コミットの
  メッセージ（複数行。Ctrl+Enter でコミット。欄にいる間はエディタのショートカット〔Ctrl+C など〕を欄に任せる）、
  コミットのボタン、変更の一覧（ツリー。マージの競合・ステージ済みの変更・変更）。
- 差分は既存の比較のウィンドウ（`diffview`）に、git から取り出した版と作業ツリーのファイルを渡す（文字コードは
  推定して UTF-8 にする）。ステージ済みは HEAD ⇔ インデックス、変更はインデックス（なければ HEAD）⇔ 作業ツリー。
- git の操作は作業スレッドで動かし、終わったら状態を読み直して一覧を作り直す（選んでいたファイルを選び直す）。
  動いている間は次の操作を受け付けず、ブランチのボタンに「… 実行しています」と出す。失敗は理由（git の
  エラーの出力）をメッセージ ボックスで知らせ、「Git の出力を表示」で最近の出力を見られる。
- 読み直す時: ビューを出したとき、↻、操作のあと、ファイルを保存したとき、ウィンドウに戻ったとき（`WM_ACTIVATE`。
  ほかのアプリで git を使ったあと）。

## 5. これから

- リモート（SSH）のフォルダのリポジトリ（接続先で git を動かす）。
- 行ごとのステージ（hunk）、ブレーム、履歴（ログ）の表示、スタッシュ、エディタの行番号の横の変更の印。
