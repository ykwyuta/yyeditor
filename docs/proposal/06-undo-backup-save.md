# 06. Undo/Redo、自動バックアップ、保存

## 1. Undo / Redo

### 1.1 方式: スナップショット履歴

永続ピースツリー（02 章）のスナップショットは `Arc` のルート 1 つなので、**編集前のスナップショットを履歴に積むだけ** で Undo が実現できます。逆操作を計算する「操作ログ方式」に比べて、次の利点があります。

- 全置換・列削除・並べ替えのような巨大な一括操作でも Undo が O(1)。
- 逆操作の計算ミスによるバグ（Undo 後の内容不一致）が原理的に起きない。
- 共有されていないノードだけが追加メモリになるため、1 回の小さな編集あたり数 KB 程度。

```rust
pub struct History {
    undo: Vec<HistoryEntry>,
    redo: Vec<HistoryEntry>,
    open_group: Option<GroupKind>,
    limits: HistoryLimits,         // 件数上限（既定 10,000）、メモリ上限（既定 256 MB）
}

pub struct HistoryEntry {
    before: Snapshot,              // 編集前の内容
    after_generation: u64,
    selections_before: Vec<Selection>,
    selections_after: Vec<Selection>,
    kind: EditKind,                // Typing | Delete | Paste | Replace | ReplaceAll | Column | ...
    changed_range: Range<u64>,     // Undo 後のカーソル位置・再描画範囲
    timestamp: Instant,
}
```

### 1.2 グループ化

| 規則 | 例 |
|------|----|
| 連続する文字入力（同じ行・1 秒以内・空白/改行で区切る）を 1 単位 | 単語ごとに Undo |
| IME の確定文字列を 1 単位 | 変換確定ごとに Undo |
| 複数カーソル・矩形選択の同時編集を 1 単位 | 全カーソル分を 1 つのスナップショットとして適用（[09 章](09-multi-cursor-rectangle.md) 4.2） |
| すべて置換・列操作・並べ替え・文字コード変換を伴う再読込を 1 単位 | |
| カーソル移動・保存で入力グループを閉じる | |

### 1.3 保存状態との関係

- `Document.save_point` に保存時点の generation を記録し、現在の generation と一致すれば「未変更」と表示（Undo で保存時点に戻れば変更マークが消える）。
- **保存後も Undo 履歴を保持**する。履歴中のスナップショットが保存前の元ファイル（mmap）を参照している場合でも、下記 3.4 の「元ファイルの退避」により参照が有効なまま保たれる。
- メモリ上限を超えた古い履歴は破棄。破棄により参照されなくなった Add バッファのチャンクや一時ファイルは `Arc` の解放で自動的に削除される。

## 2. 自動バックアップとクラッシュ復元

### 2.1 目的

- アプリのクラッシュ、OS のクラッシュ、停電時に、未保存の編集内容を失わない。
- 数 GB のファイルでも、バックアップのたびに全内容を書き出さない。

### 2.2 方式: 差分ジャーナル

元ファイルを参照するピースは「元ファイルの識別情報 ＋ オフセット」として記録し、**編集で追加されたテキスト（Add バッファ）とピース構成だけ** を書き出します。

```
%LOCALAPPDATA%\yyeditor\backup\<document-id>\
  ├─ manifest.json      # 元ファイルパス、サイズ、更新日時、ファイル ID、先頭/末尾 64KB のハッシュ、
  │                     # 文字コード、改行コード、区切り文字設定、カーソル位置、最終バックアップ時刻
  ├─ add.bin            # Add バッファ（追記のみ。前回からの増分だけ書き足す）
  ├─ pieces.bin         # 現在のピース列（ソース種別, オフセット, 長さ）。毎回書き換え（小さい）
  └─ transcoded.ref     # 非 UTF-8 ファイルの場合、変換済み一時ファイルへの参照
```

- **タイミング**: 最後の編集から 3 秒アイドル後、かつ前回から 30 秒以上経過で実行（設定変更可）。ジョブとしてバックグラウンドで実行（スナップショットを使うので編集をブロックしない）。
- **原子性**: `pieces.bin` と `manifest.json` は一時名で書いて `FlushFileBuffers` 後に rename。`add.bin` は追記のみで、manifest に有効長を記録。
- **小さいファイル**（既定 16 MB 未満、または元ファイルが一時ファイル・ネットワークパスの場合）は、差分ではなく全文を UTF-8 で保存し、元ファイルに依存しない完全なバックアップとする。
- **無題の新規ドキュメント** も同じ仕組みでバックアップする（元ファイル参照がないので常に全文）。
- **パニック時**: `std::panic::set_hook` で緊急バックアップを同期実行してから終了する。

### 2.3 復元

起動時に `backup` ディレクトリを確認し、正常終了で削除されていないバックアップがあれば「復元」ダイアログを表示します。

1. manifest の元ファイル識別情報（サイズ・更新日時・ハッシュ）と現在の元ファイルを照合。
2. 一致すれば、元ファイルを mmap し `pieces.bin` と `add.bin` からツリーを再構築して、未保存状態として開く。
3. 元ファイルが変更・削除されている場合は、差分バックアップからは復元できないため、その旨を表示し、復元可能な範囲（Add バッファのテキスト）を別ドキュメントとして開く。**このリスクを下げるため、元ファイルが一定サイズ以下の場合は初回バックアップ時に元ファイルのコピーも保持する**（設定: 既定 256 MB 以下）。

### 2.4 保存時のバックアップ（世代バックアップ）

自動バックアップとは別に、保存時に上書き前のファイルを残す機能も提供します。

| 設定 | 動作 |
|------|------|
| なし（既定） | |
| 同じフォルダに `.bak` | `file.txt` → `file.txt.bak` |
| 指定フォルダに世代管理 | `backup_dir\file.txt.20260928-153012` の形式で N 世代保持 |

3.4 の「元ファイルの退避」がそのまま使えるため、追加コストは rename のみです。

## 3. 保存

### 3.1 保存ダイアログ

Windows 標準のファイル保存ダイアログ（`IFileSaveDialog`）を使い、`IFileDialogCustomize` で次のコントロールを追加します。

- **文字コード**（コンボボックス。03 章の一覧）
- **BOM の有無**
- **改行コード**（CRLF / LF / CR / 変更しない）
- **ファイルの種類**（拡張子。区切り文字モードの方言と連動）

### 3.2 拡張子変更に伴う変換

保存先の拡張子に対応するファイルタイプ設定（01 章 4.4）が現在のモードと異なる場合、変換内容を確認したうえで適用します。

| 変換 | 処理 |
|------|------|
| `.csv` → `.tsv` 等（区切り文字モード間） | フィールド値を取り出し、保存先方言の区切り文字で再出力。区切り文字・引用符・改行を含むフィールドには保存先方言の規則で引用符を付与。TSV（引用符なし）で表現できない値（タブ・改行を含む）は警告し、置換方法（空白化 / `\t` `\n` エスケープ / 引用符付き TSV）を選択 |
| `.txt` → `.csv` | 変換なし（そのまま保存し、以後 CSV モードで扱う） |
| 既定の文字コード・改行コードを持つファイルタイプ | ダイアログの初期値を切り替え（ユーザーが変更可能） |

区切り文字の変換は全レコードを書き換えるため、保存パイプラインのストリーム変換段として実装します（下記 3.3、編集バッファ自体は変更しない）。「保存後に編集中のバッファも変換後の内容にするか」を選択でき、する場合は保存されたファイルを開き直します。

### 3.3 保存パイプライン

```
Snapshot ──► PieceReader ──► [区切り文字変換] ──► [改行コード変換] ──► Encoder ──► BufWriter ──► 一時ファイル
 (UTF-8)     (チャンク列)     (任意)              (任意)              (文字コード)                 (同じフォルダ)
                                                                           │
                                                          変換不能文字を検出したら位置を記録
```

1. 保存開始時のスナップショットを取得し、**保存ジョブとしてバックグラウンドで実行**（保存中も編集可能。保存完了時の save_point はスナップショットの generation）。
2. 保存先と同じフォルダに一時ファイル（`.<name>.yytmp-XXXX`）を作成して書き出す。同じボリュームにすることで最後の差し替えを原子的な rename にできる。
3. 文字コード変換で変換不能文字が見つかった場合（`Unmappable::Error`）:
   - 書き出しを中断し、見つかった位置（最大 1,000 件）を一覧表示。
   - ユーザーが代替方法を選択したら、その設定で書き出しを再実行。
   - 事前チェックだけを行う「変換可能か確認」コマンドも提供。
4. 同じ文字コードで保存し、かつ私用領域にエスケープした不正バイト（03 章）が含まれている場合は元のバイトに戻して書き出す。
5. 書き出し完了後 `FlushFileBuffers` で永続化。

### 3.4 元ファイルとの差し替え

mmap で参照中の元ファイルを安全に上書きするため、次の手順を取ります。

```
1. 元ファイル file.txt は FILE_SHARE_DELETE 付きで開いているため rename 可能
2. MoveFileExW(file.txt → .file.txt.yyorig-XXXX)   ← mmap は旧ファイルを参照し続ける
3. MoveFileExW(一時ファイル → file.txt)
   （または ReplaceFileW でファイル属性・ACL・作成日時・代替ストリームを引き継ぐ）
4. 新しい file.txt を開き直し、ドキュメントのソースを新ファイルに切り替える
   - UTF-8 で保存した場合: 現在のツリーを「新ファイル全体を参照するピース列」に置き換え（内容は同一）
   - 非 UTF-8 で保存した場合: 新ファイルは直接参照できないため、現在のツリー（変換済み一時ファイル
     と Add バッファを参照）をそのまま使い続ける
   - Undo 履歴中の古いスナップショットは退避した旧ファイルを参照し続ける
5. 退避ファイルは、履歴から参照されなくなった時点（Arc 解放）または
   ドキュメントを閉じた時点で削除。世代バックアップ設定があればそこへ移動
```

- 途中で失敗した場合（ディスクフル、権限不足）は手順 2 を巻き戻し、元ファイルが失われないようにする。
- 保存先がネットワークドライブや FAT32 など rename の原子性が弱い場合も手順は同じ（失敗時の回復手順をログに記録）。
- 読み取り専用属性・管理者権限が必要な場所への保存は、エラーメッセージで「別名で保存」を提案する。

### 3.5 巨大ファイルの「上書き保存」の高速化（オプション）

編集が元ファイルと同じ長さの置換だけ（例: 固定長レコードの一部書き換え）で、文字コードも同じ場合は、一時ファイルを作らずに該当バイトのみ in-place で書き換える高速保存モードを提供します（停電時の安全性が下がるため既定は無効、確認ダイアログ付き）。
