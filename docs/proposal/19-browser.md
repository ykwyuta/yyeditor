# 19. タブブラウザ（yybrowser）

エディタなどとは別のアプリとして、**OS とは別のプロキシを指定できる** タブブラウザ **yybrowser** を作ります
（2026-10-09 提案。実装の状況は 9 節）。社内のプロキシを通さずに外へ出たい・逆に検証用のプロキシ（Fiddler・mitmproxy など）だけを
通したい・SSH のポート転送（yyterm の `-D`）で作った SOCKS を通したい、といった場面で、OS の設定を変えずに、
このブラウザだけ別の経路でつなぎます。ほかは最低限の機能のタブブラウザにします。

## 1. 要求

| # | 要求 | 対応 |
|---|------|------|
| B1 | エディタなどと別のアプリ（`yybrowser.exe`）。基本の仕組み（設定・フォント・ヘルプ・異常終了の記録）は共通 | 2 |
| B2 | OS（インターネット オプション）のプロキシとは別に、このブラウザだけのプロキシを指定できる | 3 |
| B3 | プロキシは「OS と同じ」「使わない（直接）」「指定（HTTP・HTTPS・SOCKS）」「自動構成（PAC）」から選べる。除外するホストも指定できる | 3.1 |
| B4 | 名前を付けた複数のプロキシの設定（プロファイル）を持ち、切り替えられる。違うプロキシのウィンドウを同時に開ける | 3.2・3.3 |
| B5 | 最低限のタブブラウザ: タブ、アドレスバー（URL か検索語）、戻る・進む・再読み込み・中止・ホーム、ページ内検索、拡大・縮小、印刷、ダウンロード、全画面 | 4 |

対象外: 拡張機能、ブックマークの同期（ブックマーク・履歴の画面・ダウンロードは 4.1〜4.3 で対象にした）、パスワードの管理（WebView2 の既定の動作に任せる）、
広告の除去（→ 20 章で対象にした）、複数のアカウントの切り替え（プロファイルごとにデータが分かれるので、事実上は使い分けられる）。

## 2. 全体構成

```
apps/yybrowser ──► yy-win::run_browser ──┬─ browser/mod.rs     フレーム・タブ・ツールバー・アドレスバー・状態表示
                                         ├─ browser/tab.rs     タブごとの WebView2（コントローラー）とイベント
                                         └─ browser/proxydlg.rs プロキシのプロファイルの編集
                 │
                 ├─ yy-browser（新規・OS に依存しない中核。Linux で試験する）
                 │    proxy    プロキシの設定・検証・Chromium の起動引数・データのフォルダの名前
                 │    profiles プロファイルの一覧（browser.toml）の読み書き
                 │    input    アドレスバーの入力 → URL（検索語なら検索の URL）
                 └─ yy-config（[browser] のホーム・検索の URL）
```

- 表示は **WebView2**（Microsoft Edge と同じ Chromium）。エディタの Markdown のプレビューで既に使っているので、
  新しい依存は要らない（`webview2-com`。読み込み部品は静的にリンク済み）。WebView2 のランタイムは Windows 10・11
  に標準で入っている。
- 1 つのウィンドウのタブは、1 つの WebView2 の「環境」（ブラウザのプロセス）を共有し、タブごとに 1 つの
  コントローラー（表示）を持つ。

## 3. プロキシ

### 3.1 指定のしかた

WebView2 の環境を作るときに、Chromium の起動引数（`CoreWebView2EnvironmentOptions` の
`AdditionalBrowserArguments`）で渡す。OS の設定は変えない。

| やり方 | 起動引数 | 説明 |
|---|---|---|
| OS と同じ | （なし） | インターネット オプションの設定（自動検出・PAC・手動）に従う |
| 使わない（直接） | `--no-proxy-server` | OS にプロキシがあっても直接つなぐ |
| 指定 | `--proxy-server="…"` `--proxy-bypass-list="…"` | `host:port`（HTTP のプロキシ）、`https://host:port`、`socks5://host:port`、`socks4://host:port`。スキームごとに分けるときは `http=host:port;https=host:port` |
| 自動構成（PAC） | `--proxy-pac-url="…"` | PAC ファイルの URL（`http(s)://…`・`file:///…`） |

- 除外（バイパス）は `;` 区切りのホスト（`*.example.co.jp`・`192.168.0.0/16`・`<local>`）。
- 入力は保存する前に確かめる（ホスト名・ポートの範囲・スキーム・PAC の URL）。起動引数に `"` や改行を混ぜない。
- **SOCKS5 の名前解決**: Chromium は SOCKS5 のときホスト名をプロキシ側で解決する（社内の DNS を使わない）。
  yyterm の `-D`（動的なポート転送）と組み合わせれば、SSH の踏み台の先のネットワークのサイトを開ける。

### 3.2 プロファイル

- 名前を付けたプロキシの設定（例: 「OS と同じ」「直接」「検証用 Fiddler」「踏み台 SOCKS」）を、設定のフォルダの
  `browser.toml` に保存する。メニューの「プロキシ」から選んで切り替え、「プロキシの設定...」で足す・直す・消す。
- 起動するときの既定のプロファイルを選べる。コマンドラインでも指定できる（`yybrowser.exe --profile 検証用 URL`、
  その場限りの `--proxy socks5://127.0.0.1:1080`）。
- 状態表示とタイトルに、今のプロファイルとプロキシを常に出す（どの経路でつないでいるかを取り違えない）。

### 3.3 プロファイルごとのデータと、切り替え

- WebView2 は、**同じデータのフォルダを使う環境は起動引数も同じでなければならない**（同じブラウザのプロセスを
  共有するため）。そこで、データのフォルダ（Cookie・キャッシュ・ログイン状態）を **プロファイルごとに分ける**
  （`%LOCALAPPDATA%\yyeditor\yybrowser\<プロファイルの名前から作ったフォルダ>`）。
  - プロファイルを分ければ、Cookie も分かれる（検証用の経路でのログインが、普段の経路に混ざらない）。
  - 違うプロファイルのウィンドウは同時に開ける（「新しいウィンドウ（別のプロキシ）」）。別のプロセスとして起動する。
- 開いているウィンドウのプロキシを切り替えるときは、環境を作り直す（ブラウザのプロセスを起動し直す）。開いて
  いたタブは同じ URL で開き直す（入力中のフォームなどは失われるので、確かめてから切り替える）。

### 3.4 プロキシの認証

- 社内のプロキシの多くは Windows の統合認証（Negotiate・NTLM）で、Chromium はサインイン中の利用者の資格情報で
  自動的に認証する（入力は要らない）。
- Basic 認証を求められたときは、WebView2 の `BasicAuthenticationRequested`（`ICoreWebView2_10`）で受けて、
  ユーザー名とパスワードを尋ねる。「保存する」を選べば Windows の資格情報マネージャーに保存する（yyterm の
  パスワードと同じ仕組み）。プロキシの認証でもこのイベントが来るかは、WebView2 のランタイムの版で違う
  ことがあるので、実機で確かめる（来ないときは WebView2 の既定の動作になる）。

### 3.5 ドメインごとのプロキシ

- プロファイルに、上から順に当てはめる規則（「ホストの型 = プロキシ」）を持たせる。型は、ドメイン（そのドメインと
  サブドメイン）・`*` を使う型・IPv4 の範囲（`10.0.0.0/8`）。プロキシは `direct` か、「指定」と同じ書き方の 1 つ。
- 規則があれば、yybrowser が自動構成のスクリプト（PAC）を作り、`data:` の URL で `--proxy-pac-url` に渡す
  （Chromium は `data:` の PAC をネットワークを使わずに読む）。PAC の中は、転送するホスト（3.6）→ 直接、規則、
  最後にプロファイルのやり方（「使わない」なら直接、「指定」なら除くホストと指定のプロキシ。スキームごとの
  指定は URL のスキームで分ける）。
- 「OS と同じ」「自動構成」とは組み合わせない（OS や外の PAC の判断を、PAC の中から呼べないため）。
- 型・プロキシは確かめてから PAC に入れる（引用符などでスクリプトを壊させない）。

### 3.6 ホストの転送と開発者用証明書

- **ホストの転送**: 「ホスト[:ポート] = 転送先[:ポート]」。Chromium の `--host-resolver-rules` の `MAP` で、
  名前の解決（とポート）を差し替える。URL・`Host`・TLS の SNI は元のホストのまま（hosts ファイルの書き換えを、
  このプロファイルだけで、ポートも含めて行う）。例: `www.example.com = 127.0.0.1:8443`。
- 転送するホストはプロキシを通さない（通すとプロキシ側で名前を解決する）。PAC では直接、「指定」では除くホストに
  加える。「OS と同じ」「自動構成」では利用者がプロキシ側で直接にする（ヘルプに書く）。
- **開発者用証明書**: 転送先のサーバーは本物の証明書を持たないので、転送の行に証明書の SHA-256 の指紋を
  登録しておき、WebView2 の `ServerCertificateErrorDetected`（`ICoreWebView2_14`）で、エラーの URL のホストが
  転送の対象で、サーバーの証明書（`ToPemEncoding`）の指紋が一致したときだけ `ALWAYS_ALLOW` にする
  （そのブラウザのプロセスの間）。OS の証明書ストアには入れない。
  - プロキシの設定の画面で **開発者用証明書を作る**（rcgen。そのホスト名を別名に持ち、サーバー認証用の、
    有効期間が約 3 年の自己署名の証明書と秘密鍵を `browser-devcerts` に書き、指紋を行に書く）か、
    **証明書ファイルを登録**（既にある PEM・DER の指紋を書く）。
  - アドレスバーの左に、受け入れたホストのページなら「🔒 開発者用証明書を利用中」、転送だけなら
    「転送 → 127.0.0.1:8443」を出す（押すと詳しく。経路を取り違えないため）。
  - rcgen（ring）は C のビルドが要るので、実行ファイルの機能（`devcert`、既定で有効）で入れ、なければ作る
    ボタンは使えない（登録・受け入れはできる）。

## 4. ブラウザとしての機能（最低限）

| 機能 | 内容 |
|---|---|
| タブ | 新しいタブ（Ctrl+T）・閉じる（Ctrl+W・中クリック）・切り替え（Ctrl+Tab・Ctrl+Shift+Tab・Ctrl+1〜9）。タブの見出しはページのタイトル（読み込み中は印）。新しいウィンドウを開くリンク（`target=_blank`・`window.open`）は新しいタブで開く |
| アドレスバー | URL を入力して Enter。URL らしくないもの（空白を含む・ドットがない など）は検索語として、設定の検索の URL（既定は Bing）で開く。`localhost:8080` のようなホスト名・ポートは `http://` を補う。Ctrl+L・Alt+D・F6 で移る |
| 移動 | 戻る（Alt+←・Backspace は使わない）・進む（Alt+→）・再読み込み（F5・Ctrl+R）・中止（Esc）・ホーム（Alt+Home） |
| ページ内検索 | Ctrl+F（WebView2 の `ICoreWebView2Find`。ランタイムが古くて使えないときはメニューを灰色にする）。F3・Shift+F3 で次・前 |
| 拡大・縮小 | Ctrl++・Ctrl+−・Ctrl+0・Ctrl+ホイール |
| 印刷 | Ctrl+P（WebView2 の印刷の画面） |
| ダウンロード | WebView2 の既定の動作（ダウンロードの一覧の吹き出し。保存先はブラウザの既定） |
| 全画面 | F11。動画などの要素の全画面にも合わせる |
| 開発者ツール | F12（設定で無効にできる） |
| 証明書のエラー | WebView2 の既定のエラーの画面（警告を飛ばして進む機能は付けない） |

- ページの中にフォーカスがあっても、ブラウザのショートカット（Ctrl+T など）を使えるようにする
  （`AcceleratorKeyPressed`。エディタのプレビューと同じ仕組み）。
- 閉じたタブを開き直す（Ctrl+Shift+T）だけは持つ。履歴の画面は持たない（ブックマークは 4.1）。

### 4.1 ブックマーク（2026-10-09 追加）

- 設定のフォルダの `bookmarks.toml`（プロファイルに関係なく共通）。1 つは名前・URL・フォルダ（入れ子は `親 / 子`）。
- アドレスバーの右の ☆／★ と Ctrl+D で今のページを足す（登録済みなら編集・削除）。メニュー「ブックマーク」に
  一覧（フォルダはサブメニュー。開くときに読み直すので、ほかのウィンドウで足したものも出る）。
- 管理の画面（Ctrl+Shift+O）: 開く・新しいタブで開く・編集・削除・並べ替え、Edge・Chrome・Firefox の HTML
  （Netscape Bookmark File）の読み込み（同じ URL は足さない。javascript: は除く）と書き出し。
- 変えるときはそのつどファイルを読み直してから変えて保存する（別のプロセスのウィンドウと食い違わないように）。
- 中核は `yy-browser::bookmarks`（読み書き・木・HTML。Linux で試験）、画面は `browser/bookmarkui.rs`。

### 4.2 閲覧履歴と閲覧データの消去（2026-10-09 追加）

- 読み込みが終わったページを、プロファイルのデータのフォルダの `yybrowser-history.tsv` に 1 行 1 件
  （時刻・URL・題名）で足す。題名は後から変わるので、そのタブの次の移動・閉じるとき・終わるときに書く。
  同じ URL の続き（再読み込み）は書かない。2 万件を超えたら古いものから捨てる。
- 履歴の画面（Ctrl+H）: 語での絞り込み（題名・URL）、開く・新しいタブで開く・選んだものを消す。
- 閲覧データの消去（Ctrl+Shift+Del）: 期間と種類（閲覧履歴・ダウンロード履歴・キャッシュ・Cookie とサイトの
  データ・自動入力とパスワード）を選び、yybrowser の履歴のファイルと、WebView2 の
  `ICoreWebView2Profile2::ClearBrowsingDataInTimeRange`（今のプロファイルのデータ）を消す。

### 4.3 ダウンロード（2026-10-09 追加）

- `DownloadStarting`（`ICoreWebView2_4`）で既定の吹き出しを出さず（`Handled`）、保存先を決める。既定は
  WebView2 が示す「ダウンロード」フォルダ、`browser.toml` の `download_dir` で変えられる。同じ名前があれば
  番号を付ける。`download_ask` なら「名前を付けて保存」を出す（イベントは `GetDeferral` で待たせる）。
- 終わったら、保存したフォルダの直下（サブフォルダは見ない）に同じ大きさのファイルがあれば SHA-256 を比べ、
  同じ内容のものがあれば新しいほうを消す（上書きも別名での保存もしない。同じファイルを繰り返しダウンロード
  したときに重ねない）。比べるのは別のスレッドで行い、履歴には「重複のため破棄」と前からあるファイルを残す。
- 進み具合（`BytesReceivedChanged`）を状態表示に出し、終わったら（`StateChanged`）プロファイルの
  `yybrowser-downloads.tsv` に残す。一覧の画面（Ctrl+J）: 進行中と履歴、開く・フォルダを開く・一時停止・
  再開・中止・履歴から消す・すべて消す・保存先の変更。

### 4.4 検索エンジン（2026-10-09 追加）

- ファイル > 検索エンジン: Bing・Google・Yahoo! JAPAN・DuckDuckGo・Brave Search・Startpage と、その他（`%s` を
  含む URL）。`browser.toml` の `search_url` に保存し、なければ設定ファイルの `[browser] search_url`。

### 4.5 Cookie の編集（開発者用。2026-10-09 追加）

- 表示 > Cookie の編集: `ICoreWebView2_2::CookieManager` の `GetCookies(今のページの URL)` で一覧（HttpOnly も含む）。
  追加・編集は `CreateCookie` と期限・HttpOnly・Secure・SameSite を設定して `AddOrUpdateCookie`、名前・ドメイン・
  パスを変えたら前のものは `DeleteCookie`。削除・すべて削除・読み直し。閉じるときに変えていればページを読み直すか
  尋ねる。
- 入力の確かめ（名前・値に使えない文字、ドメイン、パス、SameSite=None なら Secure）と期限の日時の読み書きは
  `yy-browser::cookies`（Linux で試験）。Windows の CI で、入れた Cookie が取り直しても同じで、サーバーとページに
  届き、HttpOnly がページから見えず、消せることを本物の WebView2 で確かめる。

## 5. 設定

```toml
[browser]
home = "about:blank"                         # ホーム（新しいタブ）
search_url = "https://www.bing.com/search?q=%s"  # %s を検索語に置き換える
devtools = true                              # F12 の開発者ツール
```

プロキシのプロファイルは `browser.toml`（画面から編集する）:

```toml
default = "検証用 Fiddler"

[[profile]]
name = "OS と同じ"
mode = "system"

[[profile]]
name = "検証用 Fiddler"
mode = "manual"
server = "127.0.0.1:8888"
bypass = "<local>;*.example.co.jp"

[[profile]]
name = "踏み台 SOCKS"
mode = "manual"
server = "socks5://127.0.0.1:1080"
```

## 6. 試験

- `yy-browser`（Linux）: 起動引数の組み立て（やり方ごと・除外・引用符）、入力の検証（ポートの範囲・スキーム・
  改行や `"` の拒否）、プロファイルの読み書き、データのフォルダの名前（使えない文字・大文字小文字・長さ）、
  アドレスバーの入力の解釈（URL・ホスト名とポート・`file:`・検索語・空白）。
- Windows の CI: 手元に試験用の HTTP プロキシ（試験の中で立てる小さなもの）を立て、プロファイルを「指定」にした
  WebView2 でページを開くと、要求がそのプロキシを通ること、「直接」では通らないことを確かめる。

## 8. 決めること（提案）

1. **表示の部品**: WebView2（新しい依存なし。Edge と同じ描画）。CEF などは配布が大きいので使わない。
2. **プロキシの単位**: ウィンドウ（= プロファイル）ごと。タブごとに違うプロキシは WebView2 ではできない
   （環境が 1 つ）ので、違うプロキシは別のウィンドウで開く。
3. **データの分け方**: プロファイルごとにデータのフォルダを分ける（Cookie も分かれる）。
4. **検索の既定**: Bing（設定で変えられる）。
