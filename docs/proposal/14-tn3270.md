# 14. 3270 エミュレータ（yyterm の TN3270 セッション）

> 2026-10-07 起案。ターミナル（yyterm。12 章）に、IBM メインフレームに接続する **3270 端末エミュレーター**
> （TN3270・TN3270E）を加える方式を提案します。
>
> 同日、決定事項を反映（18）: yyterm のタブとして加える、日本語（DBCS）を使う、TLS とクライアント証明書は
> 対応するが優先度は低い、自己署名の証明書は SSH のホスト鍵と同じく初めて見たときに確かめて記録する、
> キー割り当ては独自でよい（ホストにしかないキーは画面のボタンで押せるようにする）、**IND$FILE と
> プリンター（3287）は優先度が高い**、**マクロは必要**（13）、5250 は現時点では不要（付録 A）。

## 1. 要求と範囲

| # | 要求 | 優先度 | 対応 |
|---|------|--------|------|
| E1 | yyterm のタブとして 3270 セッションを開ける（VT のタブと並べて使える） | 高 | 3、9 |
| E2 | TN3270（RFC 1576）と TN3270E（RFC 2355）で接続する。LU 名の指定 | 高 | 5 |
| E3 | 3270 データストリームの解釈（フィールド、属性、拡張属性、色）と、端末の入力の規則（保護・数字・MDT・AID） | 高 | 6、7 |
| E4 | 日本語（DBCS。CCSID 930・939・1390・1399、SO/SI、全角の入力） | 高 | 8 |
| E5 | 画面のサイズ（モデル 2〜5）、独自のキー割り当てと、PF・PA などを押せる画面のボタン（キーパッド） | 高 | 6、9 |
| E6 | **IND$FILE によるファイル転送**（TSO・CMS。日本語のデータセットを含む） | 高 | 11 |
| E7 | **プリンター**（3287。TN3270E のプリンター LU。Windows のプリンターへの印刷、PDF・テキストへの保存） | 高 | 12 |
| E8 | 踏み台・プロキシの経由（組み込みの SSH を使う。OpenSSH には依存しない） | 中 | 4 |
| E9 | 障害の調査に使える記録（ネゴシエーションとデータストリームのトレース） | 中 | 10 |
| E10 | TLS（サーバー証明書の検証、自己署名の証明書を初めて見たときに確かめて記録する） | 低 | 4.2 |
| E11 | TLS のクライアント証明書による認証（Windows の証明書ストアの証明書） | 低 | 4.2 |
| E12 | **マクロ**（操作の記録と再生、画面を待つ・読む・キーを送るスクリプト、画面からのデータの取り出し） | 高 | 13 |

**範囲外（今回は作らない）**: 5250（IBM i。付録 A。現時点では不要と決定）、富士通 F6680・日立 T560/20 などの
国産端末の手順。いずれも同じ構成の上に後から足せるように作ります（17）。

## 2. 方針

- **既存の部品を最大限に使う。**
  - 文字コード: `yy-encoding` の EBCDIC（037・1047・290・1027・930・939・1390・1399、外部の対応表）を
    そのまま使う。3270 のために変換表を持たない。固定長・可変長のレコード（`Records`）の扱いも
    IND$FILE のデータセットの変換に使う（11.3）。
  - 描画: ターミナルの格子の描画（`term/paint.rs`。同梱の UDEV Gothic で全角がちょうど 2 桁）を使う。
    DBCS の 1 文字が 2 セルという 3270 の約束と一致する。
  - 接続: 踏み台・HTTP/SOCKS プロキシ・ホスト鍵・パスワードの保存は組み込みの SSH（`yy-ssh`）。
    SSH の `direct-tcpip` チャネルを TN3270 の通り道に使える（4.3）。
  - 転送の一覧と記録: IND$FILE の転送は yysftp（13 章）の転送の記録の形と、ダウンロードしたものを
    エディタ（yyeditor）で開く流れを使う。
  - 設定・記録: `config.toml`、`logs\` の記録、タブ・ワークスペース・閉じるボタン・右クリックのメニューは
    ターミナルと共通。
- **プロトコルと画面のモデルは OS 非依存の新しいクレート `yy-3270` に置く。** Linux の CI で、録った
  データストリームと模擬ホストでテストする（16）。UI は `yy-win` の `term` に 3270 用のタブの種類を
  足す（新しいアプリは作らない）。
- **画面は「フィールドつきの画面バッファ」で持つ。** VT の `yy-term` とは画面の考え方（ブロック転送、
  フィールド、保護）が違うので共有しないが、描画に渡す「セルの並び」の形（`Cell`・色・属性）を合わせて、
  描画とコピーの処理を共有する。

## 3. 全体構成

```
yyterm（タブ）
 ├─ VT のタブ ─────────── yy-term（制御シーケンス）  ← 12 章
 ├─ 3270 のタブ ─ term/tn3270.rs（入力・OIA・キーパッド・メニュー）
 ├─ 3287 のタブ ─ term/printer.rs（受け取った印刷の一覧・プレビュー・印刷）
 └─ マクロ ───── term/macro_ui.rs（実行・停止・記録・進みの表示）
                     │
                     ▼
                  yy-3270（OS 非依存）
                   ├─ telnet.rs    Telnet のオプション交渉・IAC・EOR（レコード）
                   ├─ tn3270e.rs   TN3270E のヘッダー・DEVICE-TYPE（端末・プリンター）・FUNCTIONS・応答
                   ├─ stream.rs    3270 データストリーム（コマンド・WCC・オーダー・WSF）
                   ├─ screen.rs    画面バッファ・フィールド・属性・カーソル・キーボードの状態
                   ├─ input.rs     キー操作（AID・タブ・Erase EOF・挿入）と Read Modified の組み立て
                   ├─ query.rs     Read Partition Query への応答（Query Reply。DDM を含む）
                   ├─ charset.rs   EBCDIC ⇔ Unicode（yy-encoding）と DBCS のセルの扱い
                   ├─ ind_file.rs  IND$FILE（DFT。構造化フィールドの Open・Get・Insert・Close）
                   ├─ scs.rs       SCS（SNA Character String。LU1 のプリンター）の解釈
                   ├─ print.rs     印刷のページの組み立て（LU1 の SCS・LU3 の 3270 データストリーム）
                   ├─ macro.rs     マクロの実行（Rhai のスクリプトに 3270 の操作を公開）と記録
                   └─ trace.rs     トレース（送受信の 16 進と解釈）
                     │
                     ▼
            通り道（Transport）: TCP ／ TLS（rustls）／ SSH の direct-tcpip（yy-ssh）
```

- `yy-3270` は「バイト列を受け取って画面を更新し、送るバイト列を返す」純粋な状態機械とし、ソケットは
  持たない（`Session::receive(&[u8]) -> Vec<Event>`、`Session::key(Key) -> Vec<u8>`）。読み書きの
  スレッドは VT のタブと同じ作り（12 章 5）で、UI へは出力のまとまりごとに 1 回だけ知らせる。

## 4. 接続

### 4.1 通り道

| 方式 | 使う場面 | 実装 |
|------|----------|------|
| TCP | 社内ネットワークで直接届く | `std::net::TcpStream`（読み取り用のスレッド） |
| TLS（直接） | ポート 992 など、TN3270 over TLS | `rustls`（暗号は SSH と同じ `ring`）＋ Windows の証明書ストア |
| SSH の中継 | 踏み台の先、メインフレームがインターネットから見えない | 組み込みの SSH で接続し、`direct-tcpip` で `ホスト:ポート` へ。その上で TCP か TLS |

- HTTP・SOCKS のプロキシは SSH と同じ設定（11 章 4.5）を TCP の接続にも使う（`yy-ssh` のプロキシの
  処理を TCP 用に公開する）。
- 接続の各段階（経路、TLS の証明書、Telnet の交渉、TN3270E のデバイス、BIND）は SSH と同じ形式の
  接続の記録（`logs\tn3270.log`）に書き、失敗したときはその最後の部分を表示する。

### 4.2 TLS（優先度は低い。M5）

- 既定は「ポート 992 なら TLS、23 なら平文」。平文の Telnet ではパスワードが暗号化されずに流れるので、
  初めて平文で接続するときに警告し、確認を接続先ごとに覚える（平文の接続は M1 から使える）。
- サーバー証明書は Windows の証明書ストアで検証する。検証できない証明書（社内の自己署名など）は、
  **SSH のホスト鍵と同じく初めて見たときに確かめて記録する**（決定）。主体・発行者・有効期限・SHA-256 の
  指紋を表示し、承認したら `%APPDATA%\yyeditor\known_tn3270_certs` に `ホスト:ポート 指紋` で記録する。
  次からは記録と一致すれば黙って接続し、違えば接続せずに警告する（SSH の「ホスト鍵が変わった」と同じ）。
- **クライアント証明書**（優先度は低い）: Windows の証明書ストア（個人）から選び、秘密鍵は CNG
  （`NCryptSignHash`）で署名する（秘密鍵を取り出さない。スマートカードの証明書も使える）。接続先ごとに
  拇印を設定に書く（`client_cert = "拇印"`）。
- TLS 1.2 以上のみ（1.0・1.1 は使わない）。

### 4.3 SSH の中継

- 接続設定に `ssh = "bastion"`（`~/.ssh/config` の Host 名・`ユーザー@ホスト`）があれば、その SSH の
  接続（ターミナルの SSH のタブと共有）で `direct-tcpip` を開き、その上で TN3270 を話す。
- 12 章 4.3 のポートフォワーディング（`-L`）と同じ仕組みだが、手元のポートを開かないので安全で、
  ポートの使用中の失敗もない。

## 5. Telnet と TN3270E

### 5.1 Telnet の交渉

- 受け付けるオプション: TERMINAL-TYPE（24）、BINARY（0）、END-OF-RECORD（25）、TN3270E（40）。
  それ以外は断る（DONT・WONT）。IAC の二重化、サブネゴシエーション、レコードの終わり（IAC EOR）を扱う。
- 端末の種類は `IBM-3278-<モデル>-E`（拡張属性あり）。日本語のホストでは DBCS の Query Reply（6.5）で
  漢字を扱えることを知らせる。設定で任意の文字列（`IBM-DYNAMIC` など）に変えられる。
- TN3270E を断られたら TN3270（BINARY・EOR・TERMINAL-TYPE）に戻る。

### 5.2 TN3270E

- DEVICE-TYPE REQUEST で端末の種類と **LU 名**（`CONNECT` で指定。設定 `lu`）を送り、割り当てられた
  デバイス名を接続の記録と OIA に出す。LU が使えないとき（`DEVICE-IN-USE`・`INV-NAME` など）は
  理由を表示する。
- プリンターは `IBM-3287-1` で、プリンターの LU 名を指定するか、`ASSOCIATE` で端末の LU に対応する
  プリンター LU を求める（12.1）。
- FUNCTIONS は BIND-IMAGE・RESPONSES・SYSREQ（プリンターは SCS-CTL-CODES・DATA-STREAM-CTL も）を求める。
- 5 バイトのヘッダー（DATA-TYPE・REQUEST-FLAG・RESPONSE-FLAG・SEQ-NUMBER）を付け外しし、
  `ALWAYS-RESPONSE`・`ERROR-RESPONSE` の要求に肯定・否定の応答を返す。
- BIND-IMAGE から画面のサイズ（既定・代替）を読む（6.1）。UNBIND・SSCP-LU データ（SNA の
  ログオン前の画面）にも対応する。

## 6. 3270 データストリーム

### 6.1 画面とアドレス

- 画面のサイズ: 既定は 24×80。**代替のサイズ**はモデルで決まる。モデル 2（24×80）、3（32×80）、
  4（43×80）、5（27×132）。Erase/Write Alternate で代替に切り替える。
- バッファのアドレスは 12 ビット・14 ビット・16 ビットの 3 通りを読み、送るときは画面の大きさに応じて
  選ぶ。

### 6.2 コマンド

Write（W）、Erase/Write（EW）、Erase/Write Alternate（EWA）、Read Buffer（RB）、Read Modified（RM）、
Read Modified All（RMA）、Erase All Unprotected（EAU）、Write Structured Field（WSF）。SNA と非 SNA
（ローカル）の両方のコードを受け付ける。

- **WCC**（Write Control Character）: キーボードの復帰、MDT のリセット、警報音、印刷の開始。

### 6.3 オーダー

SF（Start Field）、SFE（Start Field Extended）、SBA（Set Buffer Address）、SA（Set Attribute）、
MF（Modify Field）、IC（Insert Cursor）、PT（Program Tab）、RA（Repeat to Address）、
EUA（Erase Unprotected to Address）、GE（Graphic Escape。APL の文字は対応表で近い Unicode に）。

### 6.4 属性

- **フィールド属性**: 保護・非保護、英数字・数字、表示の強さ（通常・高輝度・非表示）、ペン検出、
  MDT（変更済み）。保護かつ数字は「自動スキップ」。
- **拡張属性**（SFE・SA・MF）: 色（青・赤・ピンク・緑・トルコ石・黄・白と既定）、強調（点滅・反転・
  下線）、文字セット（DBCS の X'F8' など）、フィールドの検証（必須入力・必須記入・トリガー）、
  外枠（Field Outlining）。
- **拡張属性のない画面の色**は 3279 と同じく、非保護・通常＝緑、非保護・高輝度＝赤、保護・通常＝青、
  保護・高輝度＝白とする（設定で変えられる）。

### 6.5 Structured Field と Query Reply

- Read Partition Query・Query List に、次の Query Reply で答える: Summary、Usable Area（画面の
  サイズ・セルの大きさ）、Alphanumeric Partitions、Character Sets（SBCS と **DBCS**）、Color、
  Highlighting、Reply Modes（Field・Extended Field・Character）、Implicit Partition、
  **DBCS-Asia**（日本語）、**DDM**（IND$FILE の DFT 転送。11.2）、RPQ Names（`yyterm` と版）。
- Erase/Reset、Outbound 3270DS、Set Reply Mode、**Data Chunk（D0 系。IND$FILE）** に対応する。
  それ以外の構造化フィールドは読み飛ばし、トレースに記録する。

## 7. 入力（端末の規則）

- **キーボードの状態**: 入力できる・ロック中（`X SYSTEM`・`X <-*>` など）を OIA（画面下の 1 行）に
  表示する。ロック中のキーは捨て、Reset で解除する（先打ちは行わない）。
- **入力の規則**: 保護フィールドには入力できない。数字フィールドは数字と `.`・`-` だけ（ホストの設定に
  合わせて切り替え可）。入力するとそのフィールドの MDT を立てる。フィールドの終わりで次の非保護
  フィールドへ進む（自動スキップ）。
- **編集**: 上書きと挿入（Insert キー。挿入は後ろの null を詰める）、Delete、Backspace、Erase EOF、
  Erase Input、Tab・Back Tab（非保護フィールドの間）、Home、New Line、Field Mark・Dup。
- **AID**: Enter、PF1〜PF24、PA1〜PA3、Clear、SysReq、Attn。Read Modified の形（AID・カーソルの
  アドレス・MDT の立ったフィールドの SBA と中身。null は詰める）で送る。Clear・PA は短い形。
- **既定のキー割り当て**（独自。設定 `[tn3270.keys]` で変えられる）。PC のキーボードにないキー
  （PF13〜PF24、PA1〜PA3、Clear、Attn、SysReq、Field Mark、Dup など）は、キーの組み合わせに加えて
  **画面のキーパッドのボタン**（9.2）でも押せる。

| 機能 | キー |
|------|------|
| Enter | Enter |
| New Line | Shift+Enter |
| PF1〜PF12 / PF13〜PF24 | F1〜F12 / Shift+F1〜F12 |
| PA1 / PA2 / PA3 | Alt+1 / Alt+2 / Alt+3 |
| Clear | Esc |
| Reset | Ctrl+R |
| Erase EOF / Erase Input | End / Shift+End |
| Insert | Insert |
| Tab / Back Tab | Tab / Shift+Tab |
| SysReq / Attn | Alt+SysRq（Alt+PrintScreen）/ Ctrl+Pause |
| Field Mark / Dup | Ctrl+; / Ctrl+D |

- **マウス**: クリックでカーソルを移す（ペン検出のフィールドは選択として送る）。ドラッグで矩形選択。
- **コピー・貼り付け**: 矩形でコピー（行末の空白は除く）。貼り付けは非保護フィールドにだけ入れ、
  フィールドを越えたら次の非保護フィールドへ（改行は New Line）。入りきらなければ止めて警告する。

## 8. 日本語（DBCS）

- 文字コードは接続ごとに CCSID を選ぶ（既定 930。939・1390・1399、英語は 037・1047）。`yy-encoding` の
  表で SBCS と DBCS の両方を変換する。富士通 JEF などの外部の対応表（`.map`）も選べるが、国産端末の
  手順（範囲外）とは別。
- 画面のセルは 1 バイトの文字、DBCS の前半・後半、SO・SI（表示は空白 1 桁）の 4 種類を区別する。
  DBCS の 1 文字は 2 セルで、同梱フォントの全角 2 桁と一致する。
- 漢字の入れ方は 2 通り: (a) フィールドの文字セット属性が DBCS（X'F8'）なら、そのフィールドは
  すべて DBCS、(b) SBCS のフィールドの中で SO〜SI に囲む（混在）。
- **入力**: IME で確定した文字列を、フィールドの種類に合わせて入れる。混在のフィールドでは SO・SI を
  自動で入れ（必要な 2 セルを含めて入らなければ入れずに警告）、半角に戻るところで SI を入れる。
  DBCS の途中のセルにはカーソルを置かない。削除・挿入は文字の単位で行い、SO・SI の対応が崩れない
  ようにする（崩れた画面を送らない）。IME の変換ウィンドウはカーソルの位置に合わせる（12 章 5 と同じ）。
- 半角カナは CCSID 930（290）で、英小文字は 939（1027）で扱える。1390・1399 は JIS X 0213 相当の拡張と
  ユーロ記号。

## 9. UI（yyterm）

### 9.1 タブと画面

- **開き方**: 「3270 で接続」（ファイル メニュー）で接続先を入力する。`tn3270://ホスト:ポート`・
  `tn3270s://ホスト:992`（TLS）・`LU名@ホスト`、または設定の名前。ワークスペースやコマンドラインからも
  開ける（`yyterm tn3270://mvs01.example.co.jp`）。
- **タブ**: VT のタブと同じタブ（閉じる・右クリックのメニュー）。タブの名前は接続先と LU 名。
  1 つのタブが 1 つのセッション。プリンターのセッションは別のタブ（12.3）。
- **描画**: 画面の行数・桁数に合わせて文字の大きさを自動で調整するか、ウィンドウの大きさを合わせるかを
  選べる（3270 の画面は固定の大きさ）。フィールドの外枠・下線・反転・点滅を描く。非表示のフィールド
  （パスワード）は描かず、コピーにも含めない。
- **OIA**（画面の最下行の状態表示）: 接続の状態（`4B`・`6`）、キーボードのロック（`X SYSTEM` など）、
  挿入モード、カーソルの位置（行/桁）、LU 名、TLS・SSH 経由の印、通信中・転送中の表示。
- **メニュー**: 接続・切断・再接続、ファイルの転送（11）、プリンターの接続（12）、属性の表示（フィールドの
  境界を見せる。開発者向け）、トレースの開始・停止、キー割り当ての表示、画面の保存（テキスト）、
  キーパッドの表示・非表示。

### 9.2 キーパッド（ホストにしかないキーのボタン）

PC のキーボードにない 3270 のキーを、画面の右（または下。設定で選ぶ）に並べたボタンで押せるように
する。ボタンを押してもフォーカスは画面に残す（入力の途中で押せる）。

```
┌──────────────── 3270 の画面（24×80） ────────────────┐┌─ キーパッド ─┐
│                                                         ││ PF1  PF2  PF3 │
│                                                         ││ PF4  PF5  PF6 │
│                                                         ││  …    …   PF12│
│                                                         ││ PF13 PF14 PF15│
│                                                         ││  …    …   PF24│
│                                                         ││ PA1  PA2  PA3 │
│                                                         ││ Clear  Reset  │
│                                                         ││ Attn  SysReq  │
│                                                         ││ ErEOF ErInput │
│                                                         ││ FldMk  Dup    │
│ 4B  TCP00042           X SYSTEM          INS   012/034  ││ Enter         │
└─────────────────────────────────────────────────────────┘└───────────────┘
```

- 並びと表示するボタンは設定で変えられる（`[tn3270.keypad] buttons = [...]`）。ボタンにマウスを置くと
  割り当てたキーの組み合わせを表示する。
- 画面の下の 1 行に、よく使う PF キー（ISPF の PF3＝戻る、PF7/PF8＝上下など）を出す「ファンクション
  キー行」も選べる（`style = "row"`）。

## 10. 記録とトレース

- 接続の記録（`logs\tn3270.log`）: 経路、TLS（証明書の主体・指紋・プロトコルの版）、Telnet の交渉の
  順序、TN3270E のデバイスと関数、BIND、切断の理由。常に書く。
- **データストリームのトレース**（メニューで開始・停止。`logs\tn3270-trace-<日時>.log`）: 送受信の
  16 進と、コマンド・WCC・オーダー・属性の解釈（`SBA 5,12  SF(protected,intense)  "LOGON"`）。
  非表示のフィールドへの入力（パスワード）は送るときに `******` に置き換えて記録する。
- トレースは 16 のテストの入力にもそのまま使える形にする（障害の再現）。
- IND$FILE の転送とプリンターの印刷も、yysftp と同じ形の記録（`logs\tn3270-transfer.log`）に、開始・
  進み・終了・エラーを書く。

## 11. IND$FILE によるファイル転送（優先度は高い。M3）

### 11.1 仕組み

- IND$FILE は **ホストの側のプログラム**（TSO・CMS にある）で、端末（エミュレーター）と 3270 の
  データストリームの上でファイルをやり取りする。端末は TSO の READY（または ISPF のコマンド行）に
  `IND$FILE GET データセット名 (オプション` / `IND$FILE PUT …` を入力して始め、そのあとはホストが
  構造化フィールド（DFT）で端末にファイルを開かせ・読ませ・書かせる。
- **DFT 方式**（Distributed Function Terminal。構造化フィールドの Data Chunk）だけに対応する。古い
  CUT 方式（画面の書き換えで送る）は遅く、今の TSO・CMS では DFT が使えるので対応しない。
- Query Reply の DDM で受け取れる大きさ（既定 4 KiB、最大 32 KiB）を知らせる。大きいほど速い。

### 11.2 手順

1. 転送のダイアログで、向き（ダウンロード＝GET、アップロード＝PUT）、ホストの種類（TSO・CMS）、
   手元のファイル、データセット名（`'USER.DATA(MEMBER)'` など）、モードを選ぶ。アップロードでは
   RECFM・LRECL・BLKSIZE・SPACE（新しいデータセットを作るとき）も指定できる。
2. yyterm が IND$FILE のコマンドを組み立てて、今の画面（READY など）に入力して Enter を送る（どの画面で
   入力するかは利用者が開いておく。READY でなければ警告する）。
3. ホストからの Open（ファイル名の `FT:DATA`・`FT:MSG`）、Get・Insert（データ）、Close の構造化
   フィールドに答える。転送の間はキーボードをロックし、OIA と転送の一覧に進み（バイト数・速さ）を出す。
4. ホストからの終わりのメッセージ（`TRANS03 File transfer complete` など。`FT:MSG` で届く）を読み、
   成功・失敗を判定して記録に残す。失敗のメッセージ（`TRANS13` など）はそのまま表示する。
5. 取り消しは Cancel を送ってホストに中止させる（ホストが途中のデータセットを残すことがあるので記録する）。

### 11.3 文字コードとレコード（日本語のデータセット）

- IND$FILE の `ASCII CRLF` オプションでは **ホストが** EBCDIC と ASCII を変換するが、ホストの変換表は
  日本語（DBCS・SO/SI）を正しく扱えないことが多い。そこで次の 2 つのモードを用意する。
  - **バイナリ＋手元で変換（日本語の既定）**: `ASCII` を付けずに EBCDIC のまま転送し、手元で
    `yy-encoding` の CCSID（930・939・1390・1399）とレコードの形式で変換する。ダウンロードでは、
    固定長（RECFM=F・FB）は LRECL ごとに区切り、可変長（V・VB）は `CRLF` で行の区切りを付けて
    ホストに送らせ（`CRLF` だけ付けて `ASCII` は付けない）、行末の空白の扱いを選べる。アップロードでは
    手元の文字コード（UTF-8・Shift_JIS など）から CCSID に変換し、行の長さが LRECL を超えれば止めて
    警告する（切り詰めない）。
  - **ホストで変換**（英数字だけのデータ向け）: `ASCII CRLF` を付ける（ホストの変換表に任せる）。
  - **バイナリのまま**: ロードモジュールなど、何も変換しない。
- ダウンロードしたものは yyeditor で開ける（EBCDIC のまま保存して、yyeditor の EBCDIC とレコードの
  表示で開くこともできる。03 章）。

### 11.4 転送の一覧と記録

- 転送はタブごとに 1 本ずつ（IND$FILE は同時に 1 つ）。待ち行列に入れたものは順に行う。
- 一覧と記録は yysftp（13 章）と同じ形（ファイル・向き・大きさ・進み・速さ・状態）で、記録は
  `logs\tn3270-transfer.log`。IND$FILE には途中からの再開がないので、切断されたら最初からやり直すことを
  表示する。

## 12. プリンター（3287。優先度は高い。M4）

### 12.1 接続

- 3270 のプリンターは **端末とは別の TN3270E のセッション**（デバイスの種類 `IBM-3287-1`）。ホストの
  印刷（JES・VTAM のアプリケーション・CICS など）はプリンター LU に送られてくる。
- 端末のタブのメニュー「プリンターを接続」で、(a) 端末の LU に対応するプリンター LU（`ASSOCIATE`）か、
  (b) 設定に書いたプリンターの LU 名で、プリンターのセッションを開く。接続先の設定ごとに、端末を
  開いたら自動でプリンターも開くかを選べる（`printer = "auto"`）。
- プリンターのセッションは yyterm の **プリンターのタブ**（受け取った印刷の一覧）として表示する。

### 12.2 データの種類

| LU の種類 | データ | 解釈 |
|-----------|--------|------|
| LU1（SCS） | SNA Character String。NL・CR・LF・FF・HT・VT、SHF/SVF（用紙の横・縦の形式）、SLD（行間）、SO/SI・DBCS、TRN（透過） | `scs.rs` で行とページに組み立てる |
| LU3（DSC） | 3270 データストリーム（画面と同じ形を「印刷する画面」として送る） | `stream.rs` の画面バッファを使い、WCC の印刷の行の長さ（40・64・80・132 桁）で行にする |

- TN3270E の SCS-CTL-CODES・DATA-STREAM-CTL・PRINT-EOJ で、1 つの印刷（ジョブ）の終わりを知る。
  PRINT-EOJ がないホストでは、一定時間（既定 5 秒）データが来なければ終わりとみなす。
- 文字は端末と同じ CCSID で変換する（DBCS を含む）。

### 12.3 出力

- 受け取った印刷は、ジョブごとにプリンターのタブの一覧に並べ、プレビュー（ページごとの文字の表示）を
  出す。
- 出力先は設定で選ぶ（ジョブごとに変えられる）:
  - **Windows のプリンター**（GDI。用紙・余白・桁数と行数から文字の大きさを決める。全角は 2 桁。
    「Microsoft Print to PDF」を選べば PDF にもなる）
  - **PDF のファイル**（Windows の印刷の仕組みで PDF を作る。同梱フォントで全角・半角の幅が揃う）
  - **テキストのファイル**（UTF-8。改ページは FF）
  - **自動で印刷しない**（一覧に溜めて、利用者が選んで印刷・保存する）
- 印刷の記録（ジョブの日時・ページ数・出力先）を `logs\tn3270-transfer.log` に残す。

## 13. マクロ（優先度は高い。M5）

### 13.1 できること

- **決まった手順の自動化**: ログオン（利用者 ID と、資格情報マネージャーに保存したパスワード）→
  `READY` を待つ → `ISPF` → 目的の画面、のような定型の操作。
- **画面からのデータの取り出し**: 一覧の画面を PF8 で最後までめくりながら、各行を CSV・テキストに
  書き出す。
- **繰り返しの作業**: 一覧のファイルの名前ごとに同じ操作（ジョブの投入、IND$FILE でのダウンロード、
  画面の印刷）を繰り返す。
- **記録と再生**: 実際の操作（入力した文字・押したキー）を記録してマクロにし、後で再生・編集する。

### 13.2 方式

- スクリプトの言語は **Rhai**（Rust だけで書かれた組み込み用のスクリプト言語。C のライブラリを使わず、
  ファイル・ネットワークなどには明示的に渡した関数からしか触れない）。条件・繰り返し・関数・文字列の
  処理が書け、一覧のページめくりのような処理に足りる。独自の小さな命令の言語は、繰り返しや条件を
  足していくと結局言語を作ることになるので採らない。
- マクロのファイルは `%APPDATA%\yyeditor\macros\*.rhai`（ワークスペースのフォルダに置いたものも一覧に
  出す）。yyeditor で編集できる（Rhai のシンタックスハイライトの定義を同梱する。10 章）。
- 実行はタブの中で行い、画面の動きがそのまま見える。実行中は利用者のキー入力を止め、OIA に
  「マクロ実行中」と今の行を表示する。**停止**は Ctrl+Break かキーパッドの「停止」ボタン（どこで止めても
  ホストへの送信の途中にはならないよう、キーを送る単位で止める）。
- 実行の方法: マクロ メニュー（一覧から選ぶ）、キーパッドに割り当てたボタン、キーの組み合わせ、
  接続時に自動で実行（接続設定の `on_connect`）、コマンドライン（`yyterm --macro logon.rhai prod`）。

### 13.3 スクリプトから使える操作

| 操作 | 説明 |
|------|------|
| `connect("prod")`・`disconnect()` | 接続設定の名前で接続する（マクロをタブの外から始めたとき） |
| `wait_unlocked(秒)` | キーボードのロックが解けるまで待つ（ホストの応答を待つ基本の操作） |
| `wait_text("READY", 秒)`・`wait_text_at(行, 桁, "文字", 秒)` | 画面（またはその位置）にその文字が出るまで待つ |
| `text_at(行, 桁, 長さ)`・`screen_lines()`・`row(行)` | 画面の文字を読む（DBCS を含む。Unicode の文字列） |
| `fields()`・`field_at(行, 桁)` | フィールドの一覧と、位置・長さ・保護・数字・中身 |
| `move_to(行, 桁)`・`tab()`・`home()` | カーソルを動かす |
| `type("文字")` | 今のフィールドに入力する（入力の規則を守る。日本語も SO/SI を自動で入れる） |
| `key("Enter")`・`key("PF8")`・`key("Clear")` | AID などのキーを押す（押したあとは自動では待たない） |
| `password("社内ホスト")` | 資格情報マネージャーに保存したパスワードを、非表示のフィールドに入れる（スクリプトには値を渡さない。記録・トレースには `******`） |
| `transfer_get(…)`・`transfer_put(…)` | IND$FILE で転送する（11。終わるまで待って結果を返す） |
| `print_screen()` | 今の画面をプリンターの出力先へ（12.3） |
| `csv_open(パス)`・`write_row([…])`・`write_line(文字)` | 取り出したデータを書く（パスはマクロの出力のフォルダから。外に書くときは初回に確かめる） |
| `log("…")`・`sleep(ミリ秒)`・`ask("質問")`・`message("…")` | 記録・待ち・利用者への問い合わせと表示 |

- 待つ操作には必ず時間の上限があり（既定 30 秒）、時間切れ・切断・停止でスクリプトはエラーで止まる。
  エラーは行番号つきで表示し、記録に残す。
- 例（一覧を最後までめくって CSV に書き出す）:

```rhai
wait_unlocked(30);
let out = csv_open("datasets.csv");
loop {
    for r in 5..23 {
        let name = text_at(r, 11, 44).trim();
        if name != "" { out.write_row([name, text_at(r, 60, 10).trim()]); }
    }
    if wait_text_at(24, 2, "BOTTOM OF DATA", 0) { break; }
    key("PF8");
    wait_unlocked(30);
}
```

### 13.4 記録

- 「記録を開始」で、入力した文字（`type`）・押したキー（`key`）・カーソルの移動（`move_to`）を Rhai の
  スクリプトとして書き出す。AID のキーのあとには `wait_unlocked` を自動で入れる。
- 非表示のフィールド（パスワード）への入力は記録せず、`password("…")` の行（資格情報の名前は記録の
  終わりに尋ねる）に置き換える。
- 記録したものは yyeditor で開いて、待つ文字（`wait_text`）や繰り返しを書き足して仕上げる。

### 13.5 安全のために

- スクリプトに渡すのは上の操作だけで、任意のプログラムの実行・ネットワークへの接続はできない。
  ファイルへの書き込みはマクロの出力のフォルダ（`Documents\yyterm\macros-out` など。設定で変えられる）が
  基本で、その外は初回に確かめる。
- パスワードはスクリプトの中に書かず、`password("名前")` で資格情報マネージャーから入れる。マクロの
  実行の記録・トレースには値を残さない。
- 実行の記録（開始・終了・エラー・送ったキー）を `logs\tn3270-macro.log` に残す。

  次の画面に進むこと。

## 17. 今後の拡張に備えて

- `yy-3270` の画面バッファ・入力の規則は 5250 とも似ているので、プロトコルの層（`telnet.rs`）と画面の
  層を分けておき、5250（付録 A）を別のモジュールとして足せるようにする。
- マクロ（13）は `yy-3270` の「キーを送る・画面を読む・状態を待つ」口（`Session::key`・
  `Session::screen_text`・`Session::wait_unlocked`）の上に作るので、将来 5250 を足したときも同じ操作の
  名前でマクロを書けるようにする。
- 国産の端末の手順（F6680・T560/20 など）は、端末の手順そのものが違うため別の提案とする。
  文字コードは `yy-encoding` の外部の対応表（JEF・KEIS）で共通に使える。

## 付録 A. 5250 とは

- **IBM i（旧 AS/400・iSeries）** の端末（5250 型の端末）の手順。3270 がメインフレーム（z/OS など）の
  端末なのに対し、5250 は IBM i のための別の手順で、TN5250（RFC 1205・4777）で接続する。
- 画面をまとめて送る・フィールドがある、という考え方は 3270 と似ているが、データの形（コマンド・
  フィールドの形式・エラーの行・SO/SI の扱い）は互換性がない。
- **現時点では不要と決定**（2026-10-07）。IBM i（AS/400）を使うことになったら、16 の構成の上に別の
  モジュールとして足す。社内に IBM i の業務（販売管理・会計のパッケージなど）が
  あり、今は IBM i Access Client Solutions などで接続しているなら、5250 の対応が役に立つ。
