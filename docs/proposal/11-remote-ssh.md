# 11. SSH 経由のリモートファイル編集（リモートエージェント方式）

> 2026-10-05 起案。同日、16 の事項を決定（エージェントは別ファイルで配布、接続先は Linux x86_64、次の段階で Linux aarch64 も必須、Windows・AIX などは対象外、OpenSSH の設定ファイルは読んでよい、`sudo` での保存はしない、SFTP 簡易モードは設けない）。同日、M9.1（接続基盤）を実装（実装に合わせて変えた点は 17 にまとめる）。
>
> Visual Studio Code の Remote - SSH と同じく、SSH 接続先に小さな常駐プログラム（**エージェント** `yy-agent`）を送り込み、ファイル操作と重い処理を接続先で行わせる方式を提案します。

## 1. 要求と制約

| # | 要求・制約 |
|---|-----------|
| R12-1 | SSH で接続した先（主に Linux サーバー）のファイルを、手元の yyeditor で開いて編集・保存できる |
| R12-2 | 接続先の **数 GB のファイル** でも、全体を転送せずに開いて表示・編集・保存できる（R2 と同じ水準をネットワーク越しに保つ） |
| R12-3 | 文字コード（R5）・CSV（R3/R4）・検索置換と Grep（R6）・シンタックスハイライト（R11）などの既存機能が、リモートのファイルでもそのまま使える |
| R12-4 | 入力の応答性がネットワークの遅延に左右されない |
| R12-5 | 回線が切れても編集中の内容を失わず、つなぎ直したら作業を続けられる |
| **C1** | **画面を表示する端末側（Windows の yyeditor）は OpenSSH に依存してはならない。** `ssh.exe`・`scp.exe`・`sftp.exe`・`ssh-agent` サービス・OpenSSH の DLL を起動・呼び出し・同梱しない。SSH プロトコルは yyeditor の exe に組み込んだ実装で話す |
| C2 | 接続先には、OpenSSH 互換の SSH サーバー（`sshd`）と POSIX `sh` 以外の前提を置かない（`curl`・`wget`・`python`・`sftp-server`・インターネット接続は不要） |
| C3 | 01 章の方針（軽量な単一 exe、外部ランタイム不要、UI スレッドを止めない）を守る |

C1 は「Windows に OpenSSH クライアント機能が入っていない／無効化されている環境」「社内ポリシーで `ssh.exe` の実行が制限されている環境」でも使えること、また OpenSSH のバージョン差による動作の違いを持ち込まないことを狙いとします。なお、接続**先**の `sshd` が OpenSSH であることは問題ありません（C1 は端末側の制約）。

## 2. 方式の比較

| 方式 | 概要 | 巨大ファイル | 検索・Grep | 端末側の依存 | 評価 |
|------|------|-------------|-----------|-------------|------|
| `ssh.exe` を子プロセスで起動しパイプで通信（VS Code の方式そのもの） | OpenSSH クライアントに認証・暗号化を任せる | ○ | ○ | **OpenSSH 必須** | **C1 に反するため不可** |
| SFTP だけで読み書き（WinSCP 型） | ファイル全体を取得して手元で編集し、保存時に送り返す | × 全体の転送が必要 | × 手元に全部持ってこないと検索できない | なし（組み込み SFTP） | 不採用（16 で決定） |
| ネットワークドライブ化（SSHFS + WinFsp など） | ドライブとしてマウントし、ローカルファイルとして開く | △ mmap のページフォルトがそのまま回線待ちになり UI が固まる（08 章リスク表） | × | ファイルシステムドライバが必要 | 不採用 |
| **組み込み SSH ＋ リモートエージェント** | exe 内の SSH 実装で接続し、接続先に `yy-agent` を置いて独自プロトコルで通信 | ◎ 表示範囲だけ取り寄せ | ◎ 接続先で実行し結果だけ受け取る | なし | **採用** |

VS Code と同じ「接続先にエージェントを入れる」構造を取りつつ、トランスポートだけを `ssh.exe` から組み込みの SSH 実装に置き換えます。

## 3. 全体構成

```
┌──────────── 端末（Windows） ────────────┐            ┌────────── 接続先（Linux） ──────────┐
│ yy-win（UI スレッド）                     │            │ sshd（OpenSSH など。接続先の前提）      │
│   │  Document（ピースツリーは手元に持つ）  │            │   │ exec チャネル                       │
│   ▼                                       │            │   ▼                                   │
│ yy-core ── RemoteSource（疎キャッシュ）    │            │ yy-agent serve --stdio                │
│   │                                       │  SSH 1 本   │   ├ ファイル: open / read / stat /     │
│ yy-remote（専用スレッド, tokio）           │◄──────────►│   │          readdir / save / watch    │
│   ├ russh（SSH クライアント, ring 暗号）    │ (TCP 22)   │   ├ 複製ソース（Add チャンクの写し）    │
│   ├ 認証・known_hosts・ProxyJump           │            │   └ ジョブ: 行数 / 文字コード変換 /     │
│   ├ エージェントの配置・起動               │            │          検索・全置換 / Grep / CSV /    │
│   └ RPC（yy-proto, 優先度付き多重化）      │            │          ハイライト / 保存             │
└───────────────────────────────────────────┘            └───────────────────────────────────────┘
```

基本となる考え方は次の 3 点です。

1. **編集はすべて手元で行う。** ピースツリー・選択・Undo は従来どおり端末側の `Document` が持つので、1 文字入力の応答（16 ms 以内）は回線の遅延と無関係です（R12-4）。リモート端末で vim を動かす方式との最大の違いです。
2. **バイトの実体は接続先に置いたまま、必要な範囲だけ取り寄せる。** 元ファイルは接続先で開いたままにし、端末は画面に必要な範囲だけを取り寄せてキャッシュします（R12-2）。
3. **ファイルサイズに比例する処理は接続先で行う。** 行数のカウント・文字コード変換・検索・全置換・Grep・CSV の解析・保存はエージェントが実行し、端末には小さな結果（改行数、一致位置、チェックポイント）だけを返します。

### 3.1 「追記専用ソース」による複製

02 章 3.1 のとおり、ピースが参照するソースは**追記専用で一度書いた範囲は変化しません**。この性質のため、端末とエージェントの間でソースを複製しても食い違いが起きません。

| ソース | 実体の所在 | もう一方が持つもの |
|--------|-----------|-------------------|
| `Original`（接続先のファイル） | エージェント（開いたままの fd） | 端末: 取り寄せた範囲の疎キャッシュ |
| `Transcoded`（接続先で UTF-8 に変換した一時ファイル） | エージェント | 端末: 疎キャッシュ |
| 全置換・区切り文字変換などの結果ファイル | エージェント | 端末: 疎キャッシュ |
| `Add`（入力・貼り付けしたテキスト） | 端末 | エージェント: 送られたチャンクの写し |

スナップショットは「(ソース ID, 開始, 長さ) の並び」で表せるので、端末はピースの並び（10 GB のファイルで約 1 万個、圧縮して数十 KB）を送るだけで、エージェント側に**同じ内容のスナップショットを再構成**できます。保存・検索・全置換はこの再構成したスナップショットに対して接続先で実行します。Add チャンクはアイドル時にバックグラウンドで送っておき、保存や検索の直前には未送信分だけを送ります。

1 行だけ直した 10 GB のファイルを保存しても、回線を流れるのは**ピースの並びと Add チャンク（数 KB）だけ**です。

## 4. 端末側の SSH 実装（C1 への対応）

### 4.1 ライブラリの選定

| 候補 | 実装 | ライセンス | Windows でのビルド | 評価 |
|------|------|-----------|-------------------|------|
| **`russh`（0.6x 系）** | Pure Rust（暗号処理は `ring` または `aws-lc-rs` を選択） | Apache-2.0（GPL-3.0 と両立） | `ring` を選べば MSVC だけでビルドできる | **採用** |
| `ssh2`（libssh2 のバインディング） | C | BSD | OpenSSL または WinCNG とのリンク、C のビルド環境が必要 | 不採用 |
| `libssh` のバインディング | C | LGPL | DLL 配布または静的リンクの扱いが煩雑 | 不採用 |
| 自前実装 | — | — | — | 不採用（暗号プロトコルを自作する危険が大きい） |

- 暗号バックエンドは `default-features = false, features = ["ring", "rsa", "flate2"]` とし、**`aws-lc-rs`（CMake・NASM が必要）を避けます**。CRT 静的リンク（01 章 3.2）とも両立します。
- `russh` は非同期（tokio）なので、`russh` と tokio は **`yy-ssh` クレートに閉じ込め**、外には同期的な trait（`yy_remote::Connector` / `Transport`）だけを見せます。tokio のランタイム（ワーカー 1 本）は最初に接続するときに作ります。UI とは `crossbeam-channel` と `PostMessageW` でやり取りします（01 章 4.2 と同じ形）。他のクレートは async を知る必要がありません。
- `ring` は C のコードを含むため、Windows SDK のない Linux からは Windows 向けに型検査（CI の「type-check Windows UI」）ができません。そこで UI（`yy-win`）は `yy-ssh` に依存せず、実行ファイル（`apps/yyeditor`）が起動時に接続の実装を渡します（機能 `ssh`。既定で有効）。Linux からの型検査は `--no-default-features` で行い、SSH を含むビルドは Windows のジョブで行います。
- exe サイズの増加は 2〜3 MB 程度を見込みます（M9.1 で実測し、10 MB 未満の目標（README 4 章）に収まることを確認）。

### 4.2 認証

| 方式 | 対応 | 備考 |
|------|------|------|
| 公開鍵（ファイル） | ○ | OpenSSH 形式の秘密鍵（Ed25519・ECDSA・RSA。`ssh-key` クレートで読む）。パスフレーズ付きは入力ダイアログ。PuTTY の `.ppk` は v3 形式の読み込みを M9.4 で追加 |
| パスワード | ○ | 入力ダイアログ。保存は既定でしない |
| keyboard-interactive | ○ | ワンタイムパスワードなどの多要素認証。サーバーからの質問をそのままダイアログに出す |
| 認証エージェント | 任意 | Pageant（PuTTY）、および起動済みであれば Windows 標準の `\\.\pipe\openssh-ssh-agent` に**プロトコルとして**話しかける。使えなければ黙って次の方式へ進むだけで、**依存はしない** |
| パスフレーズ・パスワードの記憶 | 任意（既定は無効） | Windows 資格情報マネージャー（`CredWriteW`）に保存。接続設定ごとに選択 |

### 4.3 ホスト鍵の検証

- yyeditor 独自の `%APPDATA%\yyeditor\known_hosts`（**OpenSSH と同じ書式**）で管理します。初回接続では SHA256 フィンガープリントを表示して確認し、承認したら記録します。
- 記録と異なるホスト鍵が届いた場合は**接続を中止**し、警告を出します（「このまま接続」は用意しない。記録の削除は設定画面から明示的に行う）。
- `%USERPROFILE%\.ssh\known_hosts` があれば**読み取り専用で参照**し、そこに記録済みのホストは確認なしで接続します。ファイルを読むだけなので OpenSSH への依存にはあたりません（16 で決定）。yyeditor から OpenSSH のファイルへ書き込むことはしません。

### 4.4 接続設定

```toml
# %APPDATA%\yyeditor\config.toml（抜粋）
[remote]
read_ssh_config = true          # %USERPROFILE%\.ssh\config を読む（読むだけ）
keepalive_secs = 15
cache_limit_mb = 2048           # 端末側の疎キャッシュの上限（5.2）
agent_dir = "~/.yyeditor/agent" # 接続先のエージェント配置先

[remote.host.build-server]
hostname = "build01.example.co.jp"
user = "yamada"
port = 22
identity_file = "~/.ssh/id_ed25519"
proxy_jump = "bastion"          # 踏み台。組み込み実装で direct-tcpip チャネルを中継
proxy = "socks5://socks:1080"   # プロキシ（4.5）
agent_dir = "/work/yamada/.yyeditor"   # ホームが noexec の場合など
```

- `~/.ssh/config` は `Host`（ワイルドカード）・`HostName`・`User`・`Port`・`IdentityFile`・`ProxyJump`・`ProxyCommand` だけを解釈します。**`ProxyCommand` は外部プログラムの起動が前提なので、よく使われる形だけを組み込みの踏み台・プロキシに読み替えます**（4.5）。
- 踏み台（`ProxyJump`）は、1 段目の SSH 接続上で `direct-tcpip` チャネルを開き、その上で 2 段目の SSH を話します（多段も同様）。すべて exe 内で完結します。

### 4.5 踏み台とプロキシ（2026-10-06 追加）

- **踏み台**: `ProxyJump`（`~/.ssh/config`）・`proxy_jump`（yyeditor の設定）に `[ユーザー@]ホスト[:ポート]` を
  カンマ区切りで書く（`ssh://` も可）。接続設定の解決（`yy_remote::ssh_config`）で踏み台ごとに `HostSpec` を作り、
  最初に接続するものから順に `HostSpec::jumps` に並べる。OpenSSH の `-J a,b` と同じく、最初の踏み台だけが自身の
  踏み台・プロキシの設定をたどる（循環は 8 段で止める）。
- 接続（`yy-ssh`）は踏み台ごとに **ホスト鍵の照合（known_hosts の名前は各踏み台のもの）→ 認証** を行い、
  次の接続先へは前の接続の `direct-tcpip` チャネルを `russh::client::connect_stream` に渡して SSH を話す。
  途中の接続は最後の接続と一緒に保持し、閉じるときは接続先から順に切断する。どれかが切れたら切断とみなす。
- **プロキシ**: `proxy`（全体の既定と接続先ごと）に `http://`・`socks5://`（`socks5h`・`socks` も同じ）・`socks4://` を書く。
  最初の接続（踏み台がなければ接続先）の TCP 接続だけに使う。HTTP は `CONNECT`（Basic 認証）、SOCKS5 はホスト名を
  プロキシで解決させ、ユーザー名・パスワード認証に対応する。ユーザー名だけを書いた場合はパスワードを尋ね、
  何も書いていなければプロキシに認証を求められた（HTTP 407、SOCKS5 で方式 2 を選ばれた）ときにユーザー名とパスワードを尋ねる。
  認証に失敗したら 3 回まで尋ね直す。
- **`ProxyCommand` の読み替え**（`yy_remote::proxy::translate_command`）: `ssh [-q] [-p] [-l] -W %h:%p 踏み台` は踏み台、
  `nc [-X 5|4|connect] -x`・`ncat --proxy [--proxy-type] [--proxy-auth]`・`connect -S|-H` はプロキシにする。
  それ以外（`-o` などの選択肢、`socat`、クラウドの CLI など）は、接続するときに「対応していない」と知らせて接続しない
  （外部プログラムは起動しない。C1）。yyeditor の設定で `proxy_jump`・`proxy` を書けば、`~/.ssh/config` の指定より優先する。
- 優先順位: yyeditor の接続先ごとの `proxy_jump`・`proxy` ＞ `~/.ssh/config` の `ProxyJump`・`ProxyCommand`（先に現れたもの）
  ＞ 全体の `proxy`。`none` はそれぞれの段で「使わない」。

### 4.6 接続の記録（2026-10-06 追加）

- 接続に失敗したときに原因を調べられるよう、1 回の接続ごとに `yy_remote::ConnectLog` に経過時間つきで記録する。
  `Connector::connect`・`Session::connect`/`start`・`deploy::install` が受け取り、次を書く。
  - 解決した接続設定（接続先、秘密鍵の候補と有無、踏み台、プロキシ、経路の設定の誤り、エージェントの配置先）と、
    `~/.ssh/config`・`~/.ssh/known_hosts` を読むか、yyeditor の接続設定を使ったか（UI が書く）
  - 段ごとの接続（直接・プロキシ経由・踏み台経由）、TCP の接続先アドレス、プロキシの中継の開始・認証の要求、
    踏み台の direct-tcpip チャネル、SSH の鍵交換の完了
  - ホスト鍵の種類と指紋、known_hosts での名前、照合の結果（一致・記録なし（探したファイル）・不一致（ファイルと行））
  - 試した認証方式とその結果、サーバーが受け付ける方式、使えなかった秘密鍵とその理由、keyboard-interactive の質問
  - 接続先の環境（OS・アーキテクチャ・ホーム）、エージェントの配置（配置済み・置き換え）と起動、プロトコルの版
  - 失敗した段階とエラー
- パスワード・パスフレーズ・keyboard-interactive の答えは記録しない（プロキシの URL もパスワードを除いて表示する）。
- UI は接続のたびに `%APPDATA%\yyeditor\logs\remote-ssh.log` に日時と接続先の見出しをつけて追記する（1 MiB を超えたら
  `remote-ssh.old.log` に移して 1 世代残す）。失敗したときはエラーの下に記録の最後の 12 行とファイルの場所を出す
  （利用者が中止した場合は出さない）。ヘルプ メニューの「リモート接続の記録を開く」で記録をエディタで開ける。

### 4.7 パスワードの保存（2026-10-06 追加）

- パスワード（SSH の接続先・プロキシ）は、入力欄の「このパスワードを保存する」を選んだ場合だけ、**認証に成功してから**
  Windows の資格情報マネージャーに保存する（汎用資格情報、名前は `yyeditor/ssh/ユーザー@ホスト:ポート`・
  `yyeditor/proxy/http://ホスト:ポート`、`CRED_PERSIST_LOCAL_MACHINE`）。設定ファイルには書かない。
- 次の接続では、パスワード認証の前に保存したものを尋ねずに試す。プロキシは認証を求められたとき（ユーザー名だけを
  書いた場合は最初）に使い、保存したユーザー名も使う。**受け付けられなければ保存を消し**、その旨を添えて尋ね直す。
- 保存先は `yy_remote::PasswordStore`（`load`・`save`・`delete`）で、UI が `ConnectorOptions::passwords` で渡す
  （`yy-ssh` は保存先の実装を知らない。テストではメモリに置く `MemoryPasswords` を使う）。
  `Prompter::ask_password` は「保存を選べるか」と説明を受け取り、パスワードと「保存する」の選択を返す。
- 設定 `[remote] remember_passwords = false` で保存も保存したものの利用もしない（パスフレーズも同じ）。ヘルプ メニューの
  「保存したリモート接続のパスワードを削除」で `yyeditor/` の資格情報をまとめて削除する。
- 秘密鍵のパスフレーズも、入力欄で「保存する」を選んだ場合だけ、**鍵を開けてから** `yyeditor/key/<鍵ファイルの絶対パス>` に
  保存する（2026-10-06 に追加。利用者の判断で選ぶ）。次からは尋ねる前に保存したもので鍵を開き、開けなければ保存を消して
  尋ね直す。パスフレーズは鍵ファイルが盗まれたときの守りであり、同じ PC に保存するとその守りがなくなる（資格情報マネージャーの
  汎用資格情報は同じユーザーのプログラムなら確認なしで読める）ため、既定ではチェックを外しておき、ヘルプにも注意を書く。
- keyboard-interactive の答え（ワンタイムパスワードなど）は保存しない。接続の記録（4.6）には保存したパスワード・
  パスフレーズを使ったか・保存したか・消したかだけを書き、値そのものは書かない。

## 5. 端末側のバッファ：疎キャッシュ付きリモートソース

### 5.1 `ByteSource` の拡張

現在の `ByteSource::bytes()` はソース全体を `&[u8]` で同期的に返す前提で、`Piece::bytes()` からツリーの全読み出しがそこを通ります。リモートソースではまだ取り寄せていない範囲があるため、**取り寄せ済みかどうかを問い合わせる口**を追加します。

```rust
pub trait ByteSource: Send + Sync + 'static {
    fn bytes(&self) -> &[u8];
    /// `range` のうちまだ読めない範囲（ローカルのソースは常に None）。
    fn missing(&self, _range: Range<u64>) -> Option<Range<u64>> { None }
}

impl Snapshot {
    /// 表示やコピーの前に呼ぶ。読めない範囲をソースごとに返す。
    pub fn missing_ranges(&self, range: Range<u64>) -> Vec<(SourceRef, Range<u64>)>;
}
```

- `RemoteSource` は、ファイルと同じ大きさの**スパースファイル**（`FSCTL_SET_SPARSE`。実際には取り寄せた分しかディスクを使わない）を `%LOCALAPPDATA%\yyeditor\remote-cache\<id>` に作ってメモリマップし、取り寄せ済みの 64 KiB ブロックをビットマップで管理します。`bytes()` は従来どおりマップ全体を返し、未取得の部分は 0 として読めてしまうため、**読む側が先に `missing` を確認する**決まりにします。
- ローカルのソースは `missing` が常に `None` なので、既存の処理は変わりません。

### 5.2 端末側で実体を読む処理の整理

ファイルサイズに比例する処理は接続先に移すため（6 章）、端末側で実体を読むのは次の処理だけになります。M9.2 で、これらの読み出し経路を洗い出して `missing_ranges` の確認を入れます。

| 処理 | 未取得の範囲があるとき |
|------|----------------------|
| 画面の描画（表示範囲＋先読み） | 取り寄せを要求し、その行は「読み込み中」の淡い帯で描く。届いたら再描画（通常は 1 往復） |
| カーソル移動・単語選択など、カーソル周辺だけを読む処理 | 表示範囲の内側なので、通常は取得済み。未取得なら取り寄せを待つ（最大 200 ms、超えたら入力を保留して再実行） |
| 大きな範囲のコピー・切り取り | 進捗付きのバックグラウンド取得のあとでクリップボードへ（Esc で中止） |
| 比較・プレビュー・変換（選択範囲） | 同上。比較は 7.3 の制限あり |

- **先読み**: 表示範囲の前後 2 画面分と、スクロールしている方向の先を、通常の取得より低い優先度で取り寄せます。
- **キャッシュの上限**: `cache_limit_mb` を超えたら、表示範囲から遠いブロックの穴を空け直し（`FSCTL_SET_ZERO_DATA`）、ビットマップを戻します。穴を空けるのは UI スレッドのフレームの合間だけにし、借用中のスライスと競合させません。
- キャッシュは接続が切れても残すので、つなぎ直したあとはソースが同一であることを確認するだけで再利用できます（8 章）。

### 5.3 ファイルの場所の表し方

`Path` で表していたファイルの場所を、ローカルとリモートを区別できる型に置き換えます。

```rust
pub enum Location {
    Local(PathBuf),
    Remote { host: HostId, path: RemotePath },   // RemotePath は POSIX のバイト列（UTF-8 でない名前も失わない）
}
```

- 表示・履歴・ブックマーク・タグジャンプ用の文字列表現は `ssh://user@host:port/abs/path` とします（`history.txt`・`bookmarks.txt` にそのまま 1 行で書ける）。`recent.rs` の `same_path` はリモートでは大文字小文字を区別して比較します。
- タイトルバーとタブには `[build-server]` のように接続先名を付け、ステータスバーに接続状態（接続中・再接続中・切断）を表示します。
- `Document::open(path: &Path)` などは `&Location` を受け取る形に広げ、ローカルの処理は今の実装をそのまま呼びます。

## 6. エージェント（`yy-agent`）

### 6.1 役割と実装

- Rust 製の単一バイナリで、既存の OS 非依存クレート（`yy-buffer`・`yy-encoding`・`yy-search`・`yy-delimited`・`yy-syntax`・`yy-io` の非 Windows 部分）を**そのままリンク**します。端末と接続先で同じコードが文字コード変換・検索・CSV 解析を行うため、結果が食い違いません。
- 対象は **Linux** です（16 で決定）。M9.1 では **x86_64** だけを作り、次の段階の M9.2 で **aarch64 を必須**として追加します。どちらも `*-unknown-linux-musl` で静的リンクし、glibc の古いディストリビューション（RHEL 7 など）でも動くようにします（1 本 2〜3 MB の見込み）。エージェントのコードはアーキテクチャに依存しない Rust だけで書き、x86_64 固有の処理（SIMD など）は `memchr` などのクレートの実行時判定に任せるので、aarch64 の追加はビルドターゲットの追加と CI での実機相当の試験が中心です。
- **Windows・AIX などの Linux 以外の接続先は対象外**とします（16 で決定）。6.2 の 1 で Linux 以外と判定したら、対応していない旨を表示して接続を終えます。
- 接続先ではユーザー権限で動き、**ポートを待ち受けません**。通信は SSH の exec チャネルの標準入出力だけなので、同じホストの他のユーザーから接続される余地がありません（VS Code Server が過去にローカルポートの扱いで問題になった点を避ける）。
- 1 接続につき 1 プロセスで、チャネルが閉じたら（標準入力が EOF になったら）終了します。編集中の状態はすべて端末が持つので、常駐させる必要はありません（再接続の扱いは 8 章）。

### 6.2 配置と起動

```
1. exec: uname -sm; echo "$HOME"; id -u
   → OS・アーキテクチャを判定（Linux の x86_64 / aarch64。aarch64 は M9.2 から）。それ以外は「対応していない接続先です」と表示して終了
2. exec: test -x <agent_dir>/<版>-<ハッシュ>/yy-agent && <そのパス> --version
   → 同じ版があれば 4 へ
3. 端末が持つエージェントのバイナリを送る（curl・wget・sftp-server・インターネット接続は不要）
   exec: sh -c 'umask 077; mkdir -p "$D" && cat > "$D/.yy-agent.tmp" && chmod 700 "$D/.yy-agent.tmp"
                && mv "$D/.yy-agent.tmp" "$D/yy-agent"'   （標準入力にバイナリを流す）
   → 起動して自分の SHA-256 を答えさせ、端末が持つ期待値と照合。不一致なら削除して中止
4. exec: exec <パス>/yy-agent serve --stdio
   → 出力の先頭に現れるマジック文字列 "\0YYAGENT1" と、端末が渡した乱数を待つ
```

- 配置先は `~/.yyeditor/agent/<版>-<ハッシュ>/`。ホームが `noexec` の場合や容量が厳しい場合は、接続設定の `agent_dir` で変えられます。古い版は、エージェントの起動時に 30 日使われていないものを削除します。
- ログインシェルの `.bashrc` などが標準出力に文字を出すとプロトコルが壊れるため、**マジック文字列より前の出力は読み捨て**ます（VS Code で頻繁に問題になる点への対策）。
- **エージェントのバイナリの持ち方**: exe には埋め込まず、exe と同じフォルダの **別ファイル `agents\yy-agent-x86_64-linux`**（M9.2 から `agents\yy-agent-aarch64-linux` も）として配布します（16 で決定。exe 本体の 10 MB 目標を保つため）。端末は手元のエージェントのファイルの SHA-256 を求め、配置したエージェントが自分自身について答える SHA-256（`yy-agent --sha256`）と照合します（17）。ファイルが見つからない・ハッシュが合わない場合は、リモート編集の接続時に「エージェントのファイルがありません（再インストールしてください）」と表示して接続を終えます。

### 6.3 接続先でのファイルの開き方

Linux には Windows の共有モード（書き込み共有の拒否）がないため、02 章 4 の「開いている間は内容が変わらない」前提を別の方法で守ります。

- エージェントは **mmap を使わず `pread` で読みます**。他のプロセスがファイルを切り詰めたときに mmap では `SIGBUS` でエージェントが落ちますが、`pread` なら読み出しエラーで済みます。
- 開いた時点の (デバイス, inode, サイズ, 更新時刻 ns) を「ファイル識別子」として記録し、`inotify` で監視します。
- 多くのエディタや `git checkout` のように「別ファイルに書いて rename で差し替える」更新では、エージェントが開いている fd は**古い inode を指したまま**なので、表示中の内容は壊れません。端末には「外部で変更された」と通知し、再読み込みを提案します。
- 同じファイルを書き換える更新（ログの追記、`>` によるリダイレクトなど）を検知したら、そのソースを「不安定」として端末に通知し、文書を読み取り専用にして再読み込みを提案します。追記だけの場合は追記分の取り込み（tail）を提案します（02 章 6 と同じ扱い）。
- 開くときの安全策として、ファイルシステムが対応していれば `ioctl(FICLONE)`（btrfs・XFS の reflink）で瞬時に複製を作ってそれを読みます。対応しない場合でも 256 MiB 以下なら、接続先の一時領域に複製してから読みます。

### 6.4 エージェントで実行するジョブ

01 章 4.2 のジョブのうち、入力がスナップショットで出力が小さいものは、文書がリモートの場合に**エージェントで実行**します（`JobPlacement::Agent`）。ジョブの中身は既存のクレートの関数をそのまま使います。

| ジョブ | 端末に返すもの | 備考 |
|--------|--------------|------|
| ファイルを開く | ファイル情報・識別子・先頭 64 KiB・文字コードの判別結果 | **1 往復で最初の画面を出せる** |
| 行数のカウント（Indexer） | ピースの切れ目と改行数 `(開始, 長さ, 改行数)` の並び | ピースの切り方（1 MiB・UTF-8 の文字境界）もエージェントが決め、端末はその並びでツリーを作る |
| 文字コード変換（Transcoder） | 変換済みの長さの進捗と、変換結果のソース ID | 変換結果は接続先の `~/.cache/yyeditor/tmp/`（0600）に置き、端末は必要な範囲だけ取り寄せる。不正バイトのロスレス保持（03 章）もそのまま |
| 検索・すべて置換 | 一致位置の並び／置換結果のソース ID と改行数 | 置換結果は接続先の一時ファイル。端末のツリーはそれを参照する 1 ピースに差し替え（1 回の Undo） |
| Grep | 一致行（ファイル・行番号・行の内容）をストリーミング | フォルダの走査・文字コード判別・検索をすべて接続先で行う |
| CSV のレコードインデックス、ハイライトのチェックポイント | チェックポイントの並び | ハイライトの利用者定義（`syntax\*.toml`）は接続時に送る |
| 保存 | 結果（成功・競合・変換できない文字の位置） | 7.1 |

「行へ移動」で行数が確定していない範囲に入る場合は、エージェントに該当ピースの改行数を優先して数えさせます。

## 7. 保存とファイル操作

### 7.1 保存

06 章 3.3 の保存パイプライン（区切り文字変換 → 改行コード変換 → エンコーダー）を**エージェントで実行**し、06 章 3.4 の差し替え手順を POSIX 向けに置き換えます。

```
端末:   保存開始時のスナップショットのピースの並び ＋ 未送信の Add チャンクを送る
エージェント:
  1. 再構成したスナップショットを、保存先と同じディレクトリの .<name>.yytmp-XXXX に書き出す
     （変換できない文字が見つかったら中断して位置を返す。06 章 3.3 の 3 と同じ）
  2. fsync
  3. 元ファイルのパーミッション・所有者（可能な範囲）・拡張属性を引き継ぐ
  4. 競合の確認: 保存先の現在の識別子が、開いた時点（または前回保存時）と一致するか
     → 不一致なら差し替えずに「競合」を返す（上書き／比較／中止を利用者が選ぶ）
  5. rename(一時ファイル → 保存先)、ディレクトリを fsync
  6. 新しい識別子を返す
```

- **シンボリックリンク**はリンク先の実ファイルを差し替えます（リンク自体は残す）。
- **ハードリンク**（リンク数 2 以上）は rename で切れてしまうため、確認のうえ「一時ファイルの内容を元ファイルへ上書きコピー」する方式に切り替えます。
- 保存後の端末側は 06 章 3.4 の 4 と同じ扱いで、現在のツリーをそのまま使います。エージェントは差し替え前の fd を開いたままにするので、Undo 履歴が参照する古い内容も読めます。UTF-8 で保存した場合は、アイドル時に「新ファイル全体を参照するピース列」に付け替え、端末側のキャッシュは古いソースのキャッシュから新しいソースへ写して再利用します（再接続すると古い inode は参照できなくなるため、付け替えておく）。
- 書き込み権限がない場合は「別名で保存」を提案します。**`sudo` などによる権限の昇格は行いません**（16 で決定）。エージェントは常に接続したユーザーの権限だけで動きます。

### 7.2 開く・名前を付けて保存のダイアログ

Windows のファイルダイアログは SSH 先を参照できないため、**リモート用のファイル選択ダイアログ**を用意します。

- 上部にパス入力欄（Tab で補完）、下にフォルダの一覧（名前・サイズ・更新日時、絞り込み可）。一覧はエージェントの `readdir` で取得し、数万項目のフォルダでも先頭から順に表示します。
- 文字コードの指定（「開く」ダイアログの文字コード欄と同じ）を持ちます。
- 「ファイル」メニューに「リモートに接続…」「リモートのファイルを開く…」を追加し、最近使ったファイル（Ctrl+E）からは `ssh://` の項目を選ぶだけで接続して開けるようにします。

### 7.3 既存機能の対応状況（リモートの文書）

| 機能 | 対応 |
|------|------|
| 表示・編集・Undo・矩形選択・マルチカーソル・IME | そのまま（すべて端末側で処理） |
| 文字コード・BOM・改行コードの判別と変換、ロスレス往復 | エージェントで変換（6.4） |
| 検索・置換・すべて置換・Grep・タグジャンプ | エージェントで実行（6.4） |
| CSV モード・シンタックスハイライト | チェックポイントをエージェントで作り、表示は端末側 |
| 16 進数表示・固定長表示・コード値表示 | そのまま（表示範囲だけを読む） |
| 比較 | 両方の文書の合計が 256 MiB 以下なら端末に取り寄せて比較。両方が同じ接続先にあれば行ハッシュの計算をエージェントで行う（M9.4） |
| Markdown・HTML のプレビュー | 本文はそのまま。相対パスの画像・CSS・スクリプトは、WebView2 の `https://yy-doc.local/` への要求を横取りしてエージェントから取り寄せ、遅延（deferral）で答える（実装済み。1 ファイル 32 MiB まで） |
| 他のアプリが使用中のファイルの読み取り専用表示 | 6.3 の「不安定」扱いと複製で代替 |

## 8. プロトコル（`yy-proto`）

### 8.1 フレーム

```
| 長さ u32 LE | 種類 u8 | 優先度 u8 | 要求 ID u32 LE | 本体（serde ＋ postcard） |
```

- 1 フレームの本体は最大 256 KiB。大きなデータは分割し、**優先度の高いフレーム（表示に必要な取得、カーソル周辺）を、バルク転送（Add チャンクの送信、先読み、Grep の結果）の間に割り込ませます**。SSH のチャネルは 1 本で、多重化と優先度はこの層で行います。
- データ本体は 64 KiB ブロックごとに deflate（レベル 1、`miniz_oxide`）で圧縮し、縮まないブロックは無圧縮で送ります。SSH の圧縮は使いません（暗号化前に一律にかかり、圧縮済みデータで無駄になるため）。

### 8.2 主なメッセージ

| 方向 | メッセージ | 内容 |
|------|-----------|------|
| 端末→ | `Hello` | プロトコル版、端末の版、乱数（マジック確認用） |
| ←エージェント | `HelloOk` | エージェントの版、OS、ホーム、対応機能 |
| 端末→ | `Stat` / `ReadDir` / `Watch` | ファイル情報、一覧（分割して返す）、変更監視 |
| 端末→ | `Open` | パス、文字コードの指定、バイナリとして開くか |
| ←エージェント | `Opened` | ソース ID、識別子、先頭 64 KiB、判別結果 |
| 端末→ | `Read` | ソース ID と範囲の並び（優先度付き） |
| ←エージェント | `Data` | ソース ID、オフセット、ブロック |
| ←エージェント | `Pieces` | 行数カウント・変換の進捗に伴うピースの並び（随時） |
| 端末→ | `PutChunk` | Add チャンクの複製（チャンク ID、内容） |
| 端末→ | `Run` / `Cancel` | ジョブの開始（種類、ピースの並び、オプション）／中止 |
| ←エージェント | `Progress` / `Result` | ジョブの進捗・結果 |
| 端末→ | `Save` | ピースの並び、保存先、保存形式、期待する識別子 |
| ←エージェント | `Saved` / `Conflict` / `Unmappable` | 7.1 |
| ←エージェント | `Changed` | 監視中のファイルの変更 |
| 双方向 | `Close` / `Ping` | ソースの解放、死活確認 |

- 版の互換性: `Hello` でプロトコル版が一致しなければ、端末が持つ版のエージェントを配置し直します（6.2）。端末とエージェントは同じ版を組で使う前提とし、異なる版の間の互換性は持たせません。

## 9. 切断と再接続

- SSH の keepalive（`keepalive@openssh.com`）を 15 秒ごとに送り、応答が 3 回途絶えたら切断とみなします。
- **切断中も文書は開いたまま編集できます**（ピースツリーと Add は端末にある）。取得済みの範囲は表示・編集でき、未取得の範囲は「読み込み中」のまま、保存と接続先でのジョブは再接続まで保留します。ステータスバーに「再接続中…」と表示し、間隔を延ばしながら自動で再接続します（手動の「再接続」も用意）。
- 再接続したら、開いていた各ファイルを開き直し、**識別子（デバイス・inode・サイズ・更新時刻）が一致すれば**そのまま続行します。端末のキャッシュも再利用し、Add チャンクは改めて複製します。
- 識別子が一致しない（切断中に外部で変更された）場合は、その文書を読み取り専用にして「再読み込み」「別名で保存」「比較」を提案します。手元の編集内容（Add とツリー）は失いません。
- 接続先の一時ファイル（変換結果・置換結果）は、エージェントの終了後も 24 時間は残し、再接続後に同じ内容であることを確認して引き継ぎます。接続先から消えていて引き継げない場合は、変換をやり直します。古い一時ファイルは、エージェントの起動時に `flock` で使用中でないことを確かめてから削除します。

## 10. セキュリティ

| 項目 | 対策 |
|------|------|
| 中間者攻撃 | ホスト鍵の検証を必須とし、不一致なら接続しない（4.3） |
| エージェントの改ざん | 配置後に、手元のエージェントのファイルの SHA-256 と照合し、配置先は 0700。リリースではエージェントを CI でビルドしてハッシュを公開 |
| 他のユーザーからの接続 | エージェントはポートを待ち受けず、SSH チャネルの標準入出力だけで通信 |
| 接続先の一時ファイル | `~/.cache/yyeditor/`（0700）、ファイルは 0600 |
| 端末側のキャッシュ | `%LOCALAPPDATA%\yyeditor\remote-cache\`。文書を閉じるとき、および起動時に古いものを削除。接続設定で「キャッシュを残さない」を選べる |
| 資格情報 | パスワード・パスフレーズは既定で保存しない。保存する場合は Windows 資格情報マネージャー |
| 権限の昇格 | 行わない。エージェントは接続ユーザーの権限だけで動き、`sudo` を呼ばない（16） |
| 依存ライブラリ | `russh`・`ring` の版を `Cargo.lock` で固定し、`cargo audit` を CI で実行 |

## 11. クレート構成の変更

```
crates/
├─ yy-proto/     # 新規: メッセージ定義、フレーム、圧縮。OS・async に依存しない（端末とエージェントで共有）
├─ yy-remote/    # 新規: 端末側（OS・async・暗号処理に依存しない）。エージェントの配置、RPC、
│                #       known_hosts・~/.ssh/config の読み取り、Connector / Transport の trait、RemoteSource（疎キャッシュ）
├─ yy-ssh/       # 新規: 組み込みの SSH クライアント（russh + ring + tokio を閉じ込める）。接続・認証・ホスト鍵の照合
├─ yy-buffer/    # 変更: ByteSource::missing、Snapshot::missing_ranges、ピースの並びの直列化
├─ yy-io/        # 変更: スパースファイルのキャッシュ（Windows）。Linux 側の pread ソース・保存処理（エージェント用）
├─ yy-core/      # 変更: Location、ジョブの実行場所の切り替え、リモートの開く・保存
├─ yy-config/    # 変更: [remote] 設定、~/.ssh/config の読み取り、ssh:// の履歴
└─ yy-win/       # 変更: 接続ダイアログ、リモートのファイル選択、ホスト鍵の確認、状態表示
apps/
└─ yy-agent/     # 新規: エージェント（x86_64-unknown-linux-musl。M9.2 から aarch64-unknown-linux-musl も）
```

依存関係では、`yy-remote` は `yy-core` の下（`yy-io` と同じ層）に置き、`yy-core` からは「リモートのファイルシステム」の trait として見えるようにします。`yy-agent` は `yy-win` と `yy-remote` に依存しません。

CI の変更:

- Linux ジョブに `yy-agent` の musl ビルド（x86_64）を追加し、成果物として保存。M9.2 で aarch64 のクロスビルドを加え、aarch64 の Linux ランナー（GitHub の `ubuntu-24.04-arm`）でエージェントの結合テスト（12）を実行する。
- Windows ジョブは、エージェントのジョブの成果物を受け取り、exe と `agents\` 以下のエージェント（x86_64、M9.2 から aarch64 も）を一緒に成果物にする（インストーラも同じ構成で配置）。

## 15. リスクと対策

| リスク | 影響 | 対策 |
|-------|------|------|
| `russh` の不具合・相互接続性の問題（古い sshd、特殊な鍵交換方式） | 一部のサーバーに接続できない | 実 `sshd` との相互接続試験を CI に置く。`ssh2`（libssh2）に置き換えられるよう、SSH 層を `yy-remote` 内の trait に閉じ込める |
| 暗号ライブラリの脆弱性 | 通信の安全性 | 版の固定と `cargo audit`、更新を速やかにリリース |
| 接続先の `.bashrc` の出力、`noexec`、ディスク容量不足 | エージェントが起動しない | マジック文字列での同期、`agent_dir` の設定（ホーム以外の実行できる場所へ配置）。それでも起動できない場合は原因（`noexec`・容量・実行の禁止）を表示して接続を終える |
| Linux では書き込み共有を拒否できない | 表示中の内容が外部から変わる | `pread`＋識別子＋`inotify`、reflink・小さいファイルの複製（6.3） |
| 未取得の範囲を 0 のまま読んでしまう読み出し経路の見落とし | 表示や保存の内容が壊れる | 保存・検索は必ずエージェントで行う設計にし、端末側の読み出しは 5.2 に限定。デバッグビルドでは `missing` を確認せずに読んだら panic させる |
| 端末側の exe サイズ・起動時間の増加 | 軽量さの目標 | tokio・russh は接続時まで初期化しない。M9.1 でサイズと起動時間を計測 |
| aarch64 でだけ起きる不具合（メモリ順序、アラインメント、依存クレートの対応漏れ） | ARM のサーバーで動作しない・結果が食い違う | `unsafe` を使わずに書き、aarch64 のランナーで結合テストと「リモート保存とローカル保存のバイト一致」試験を毎回実行する |

## 17. M9.1 の実装で変えた点（2026-10-05）

| 項目 | 提案時 | 実装 | 理由 |
|------|--------|------|------|
| SSH の実装の置き場所 | `yy-remote` に russh・tokio を閉じ込める | `yy-ssh` に分け、UI には実行ファイルが起動時に渡す（4.1） | `ring` の C コードのため、Linux から Windows 向けの型検査ができなくなるのを避ける |
| エージェントのハッシュ | 期待値を exe に埋め込む | 手元のエージェントのファイルから実行時に求める（6.2） | Windows のビルドが Linux のビルドの成果物に依存しないようにする。配布物は同じフォルダにあり、インストール先の改ざんへの強さは変わらない |
| M9.1 で開けるファイル | UTF-8 の 256 MiB 以下 | 全文字コード。全体を手元の一時ファイルに取り寄せ、手元のファイルと同じ処理で開く（256 MiB を超えるときは確かめる） | 文字コードの判別・変換・CSV・ハイライトを最初からそのまま使える |
| M9.1 の保存 | ピースの並びと Add を送り、接続先で書き出す | 手元で保存の形式（文字コード・BOM）に書き出してから送り、接続先で置き換える | ピースの並びによる保存は M9.2（疎キャッシュ）と合わせて入れる |
| `known_hosts` の照合 | russh の機能を使う想定 | `yy-remote` で実装（ハッシュ化されたホスト名・ワイルドカード・`@revoked` に対応） | russh の照合は、読めない鍵の行が 1 行あると全体が失敗するため |

テスト（12）は次のとおり実装した。

- `yy-proto`・`yy-remote`・`yy-agent` の単体テスト（フレーム、圧縮、`known_hosts`、`~/.ssh/config`、URI、保存の置き換え・権限・リンク・競合）。
- SSH を使わずに手元の `sh` でエージェントを配置・起動する結合テスト（`apps/yy-agent/tests/remote.rs`）。
- russh のサーバーを同じプロセスで立てた SSH の結合テスト（`apps/yy-agent/tests/ssh.rs`。ホスト鍵の承認・拒否・不一致、暗号化された秘密鍵、パスワードの再入力、エージェント経由の取り寄せと保存）。OpenSSH は使わない。

### 17.1 ワークスペースへのリモートのフォルダの登録（2026-10-05 追加）

ワークスペース（`*.yyworkspace`）の起点のフォルダに、SSH 接続先のフォルダ（`ssh://接続先/パス`）も
登録できるようにした。

- 登録はリモートのファイル選択ダイアログ（7.2）をフォルダを選ぶ形で使う。ワークスペースのファイルには
  `ssh://…` を書いたとおりに保存する（相対パスへの変換・正規化はしない）。
- サイドバーでリモートのフォルダを開くと、エージェントの `ReadDir` で中身を読む（接続していなければ
  接続する）。ツリーの展開の通知の中では接続・取得をせず、通知を一度断ってから読み、読み終えたら展開する
  （接続中のパスワードなどのダイアログが通知の処理の中で出ないようにするため）。
- リモートの項目では、手元のプログラムで開く操作（ターミナル・エクスプローラー）と Grep は出さない
  （接続先での Grep は M9.3）。

### 17.2 ワークスペースでのファイル・フォルダの操作（2026-10-05 追加）

サイドバーで、作成・名前の変更・削除・移動を手元とリモートの両方でできるようにした。

- プロトコル（版 2）に `MakeDir`・`Rename`・`Remove` を加えた。`Rename` は上書きせず（移動先があればエラー）、
  フォルダをその中へは移さない。別のファイルシステムへの移動は、エージェントがコピーしてから元を消す。
  `Remove` はごみ箱がないので、UI で「元に戻せない」ことを確かめてから送る。
- 移動は同じ場所（同じパソコン、または同じ接続先）の中だけ。パソコンとリモートの間の移動（コピーして消す）は扱わない。
- 名前を変えた・移動したファイルを開いているタブは、文書の場所を付け替える（`Document::relocate`）。手元のファイルは
  マップ中のファイルの名前も直し、上書き保存の退避が正しく働くようにする。削除するときは、変更のないタブを閉じてから消す
  （変更のあるタブがあれば消さない）。

### 17.3 ワークスペースでのコピー（手元とリモートの間を含む。2026-10-06 追加）

- コピー・貼り付け（Ctrl+C / Ctrl+V）とドラッグ＆ドロップで、手元・リモート・別の接続先のどの組み合わせでもコピーできる。
  ドラッグ＆ドロップは、別の場所へはコピー、同じ場所の中は移動（Ctrl でコピー）。
- コピーの処理は `yy_remote::transfer`（コピー元・コピー先をそれぞれ手元のパスか接続先のパスで表す）。
  手元とリモートの間はエージェントの `Open`/`Read` と `BeginUpload`/`Write`/`Commit` を使い、同じ接続先の中は
  プロトコル（版 3）の `Copy` でエージェントが接続先でコピーする（転送しない）。別の接続先の間は手元の一時ファイルを経由する。
- 上書きしない（同じ名前があれば「名前 - コピー」にする）。途中で失敗・中止したら、作りかけのコピーを消す。
  フォルダを指すシンボリックリンクは循環を避けるためたどらない。
- 中止は専用のエラーで伝える（`ErrorKind::Interrupted` は `io::copy` などが「やり直し」とみなして読み続けるため使わない）。
- コピーの前に量を数え（`transfer::measure`）、10 MiB 以上なら確かめる。手元とリモートの間（別の接続先の間を含む。
  `transfer::crosses_network`）では 50 MiB 以上はコピーしない。数えたあとで増えた場合に備え、転送中にも上限で止める。
