# 18. ファイル管理（yyfilemanager）

エディタ・ターミナル・ファイル転送とは別のアプリとして、同じクレートを使ったファイル管理 **yyfilemanager**
を作ります（2026-10-08 提案、同日に方針が決まりました。14 節。実装の状況は 15 節）。共有フォルダ（Windows のファイル共有・NAS）との間のフォルダ単位の同期と、
たまったファイルの検索・整理（同じファイル・古い版の見つけ出しと一括削除）を 1 つのアプリで行います。

## 1. 要求

| # | 要求 | 対応 |
|---|------|------|
| F1 | エディタなどと別のアプリ（`yyfilemanager.exe`）。基本の仕組み（設定・フォント・ダイアログ・記録）は共通 | 2 |
| F2 | 指定したファイル・フォルダを共有フォルダへ、rsync のようにフォルダ単位で同期する（変わったものだけ送る） | 4 |
| F3 | 同期の途中で切れても（回線・アプリの終了・電源断）、続きから送る（レジューム） | 4.4・4.5 |
| F4 | ファイル名の似ている度合いと、更新日時・大きさから、「同じファイルの別の版」を見つけ、どれが新しいかを判定する | 5 |
| F5 | 中身が完全に同じファイル（重複）を見つける | 6 |
| F6 | 人が確かめて「古い」「過去の版」と決めたファイルを、まとめて削除する（取り消せる形で） | 7 |
| F7 | 数百万ファイル・数 TB の共有フォルダでも使える速さ | 3・10 |
| F8 | ファイルの検索（名前・大きさ・日時・種類・中身。手元と共有フォルダの複数の場所をまとめて） | 8 |

対象外（この提案では）: 双方向の同期（両側の変更をまとめる）、SSH の接続先との同期（yysftp の役目。
将来は共通の部品で足せるようにする）、ファイルの中身の差分の表示。

## 2. 全体構成

```
apps/yyfilemanager ──► yy-win::run_filemanager ──┬─ fm/mod.rs      フレーム・タブ・メニュー・状態表示
                                                 ├─ fm/sync.rs     同期の設定・計画の一覧・進み
                                                 ├─ fm/similar.rs  似た名前のグループと「新しい版」の判定
                                                 ├─ fm/dupes.rs    重複のグループ
                                                 ├─ fm/search.rs   検索の条件・結果の一覧
                                                 └─ fm/review.rs   削除の確認（チェック）・実行・取り消し
                   │
                   ├─ yy-files（新規・OS に依存しない中核）
                   │    scan     フォルダの走査・ファイルの目録（索引のキャッシュ）
                   │    sync     比べる → 計画 → 実行（ジャーナル・レジューム・途中のファイル）
                   │    similar  名前の正規化・似ている度合い・グループ化・版の順位付け
                   │    dupes    大きさ → 先頭と末尾のハッシュ → 全体のハッシュ
                   │    purge    削除の計画・実行前の確認・隔離フォルダ・取り消し・記録
                   │    search   名前・属性の検索（目録から）、中身の検索（yy-core の grep を並列に）
                   │    fs       ファイル操作の口（Windows の実装と、試験用の故障を起こせる実装）
                   ├─ yy-core / yy-search / yy-encoding  中身の検索（文字コードの判別・正規表現。エディタの Grep と共通）
                   ├─ yy-config  設定（[filemanager]）
                   └─ yy-win の部品（ダイアログ、仮想リスト、同梱フォント、異常終了の記録、記録のタブ）
```

- 中核（`yy-files`）は OS に依存させず、Linux の CI で、途中で切れる・遅い・時刻の粗いファイルシステムを
  まねた試験用の実装（`fs::Faulty`）を使って試験する。Windows 固有の部分（共有フォルダでのサーバー側コピー、
  ごみ箱、長いパス、ファイル ID）は `fs::Windows` に閉じ込める。
- 共有フォルダは UNC（`\\server\share\…`）とドライブ文字の割り当ての両方を受け付ける。パスは内部で
  `\\?\UNC\…`・`\\?\C:\…` にして、260 文字を超えるパスも扱う。資格情報は Windows に任せる（接続済みの
  共有を使う。必要なら「ネットワーク ドライブの割り当て」と同じ `WNetAddConnection2` のダイアログを出す）。
- 画面・実行・記録の作りは yysftp（13 章）にそろえる（転送の一覧・記録のタブ・ジャーナルの置き場所・
  起動中の印）。

## 3. 走査と目録（`yy_files::scan`）

すべての機能の土台。フォルダの中のファイルを集め、1 ファイル 1 行の目録にする。

- 集めるもの: 相対パス、大きさ、更新日時（100 ns 単位）、作成日時、属性（読み取り専用・隠し・システム・
  再解析点）、ファイル ID（ボリュームのシリアル番号＋ファイル番号。ハードリンクとリネームの検出に使う）。
- Windows では `FindFirstFileExW`（`FindExInfoBasic`・`FIND_FIRST_EX_LARGE_FETCH`）で、フォルダ単位に
  並列に読む（共有フォルダは 1 回の往復が遅いので、並べて読むほど速い。既定 16 本）。再解析点（ジャンクション・
  シンボリック リンク）はたどらない（循環と、別のボリュームへのはみ出しを避ける）。
- 除外: 名前のパターン（`Thumbs.db`・`desktop.ini`・`~$*`・`*.tmp`・`.yypart` など。設定で足せる）と、
  フォルダのパターン（`$RECYCLE.BIN`・`System Volume Information`・`.git` など）。
- **索引のキャッシュ**: 走査の結果とハッシュを、設定のフォルダの `filemanager\index\<ルートの名前>.idx` に
  残す（postcard で詰め、ブロックごとに miniz で圧縮。書き換えは一時ファイルから置き換える）。次に走査するとき、
  大きさ・更新日時・ファイル ID が同じファイルは、前のハッシュをそのまま使う（読み直さない）。
- 目録は列ごとに持つ（パスの文字列は 1 つの大きな領域にまとめ、行は番号で指す）。300 万ファイルで
  数百 MB に収める（見積もりは 10 節）。

## 4. 同期（`yy_files::sync`）

### 4.1 同期の設定（同期ジョブ）

- 「送り元（手元のフォルダ、またはファイルの一覧）」「送り先（共有フォルダ）」「やり方」を名前を付けて
  保存する（`filemanager\jobs.toml`）。手元のファイルを個別に選んだときは、その一覧を保存する。
- やり方:
  - **更新**（既定）: 新しいファイルと変わったファイルを送る。送り先にだけあるファイルはそのまま。
  - **ミラー**: それに加えて、送り元にないファイルを送り先から消す（消す前に一覧で確かめ、消したものは
    隔離フォルダ（7.3）に移す。すぐには消さない）。
- 比べ方: 既定は rsync と同じく **大きさと更新日時**（時刻の誤差の許し幅を設定。既定 2 秒。FAT・一部の NAS は
  2 秒単位、ほかの OS の共有は 1 秒単位のため）。「中身で比べる」を選ぶと、大きさが同じで日時が違うものを
  ハッシュで比べる（日時だけ変わったファイルは送らず、送り先の日時を合わせる）。

### 4.2 比べる → 計画 → 確かめる → 実行

1. 両側を走査して（3 章。送り先も索引のキャッシュを使う）、相対パスで突き合わせる。大文字・小文字の違いは
   同じファイルとみなす（Windows の共有）。Unicode の正規化（NFC・NFD）の違いも同じとみなす（macOS から
   置いたファイル）。
2. 計画: ファイルごとに「新規」「更新」「日時だけ合わせる」「消す（ミラー）」「衝突」「飛ばす」を決める。
   **衝突**: 送り先のファイルが、前回の同期のあとで変わっている（前回の同期の記録と、大きさ・日時が違う）。
   上書きせずに一覧で知らせ、どちらを残すかを人が決める（送り先を `名前 (衝突 2026-10-08).拡張子` にして
   残すこともできる）。
3. 計画の一覧を見せる（件数・大きさの合計・推定時間。種類ごとに絞り込める）。人が「実行」を押してから送る
   （ドライ ランが既定）。設定で「確かめずに実行」もできる（定期実行のため）。
4. 実行: ファイルを並べて送る（既定 4 本。大きなファイル 1 本と小さなファイル多数が混ざっても詰まらない
   よう、大きさで 2 つの列に分ける）。小さなファイルが多い同期では、往復の遅さが効くので本数を増やせる。

### 4.3 1 ファイルの送り方

- 送り先には `<名前>.yypart` に書き、終わったら大きさ（と、選べば中身のハッシュ）を確かめてから、本来の名前に
  置き換える（`MoveFileExW(MOVEFILE_REPLACE_EXISTING)`）。途中のファイルが本物と取り違えられない。
- 書いた後で、更新日時・作成日時・属性（読み取り専用など）を送り元に合わせる。ACL は合わせない（共有フォルダの
  既定の権限に従う。設定で「ACL も写す」を足せるようにしておく）。
- 読み書きは 1 MiB ずつ、読む・書くを別のスレッドで重ねる（共有フォルダへの書き込みの待ちを隠す）。
- **大きなファイルの差分の送り方**（任意。既定は 64 MiB 以上で使う）:
  - rsync はつなぎ先のマシンで計算するが、共有フォルダでは送り先を読むと送るのと同じだけ回線を使う。
    そこで、**前回送ったときに、送り先の内容のブロックごとのハッシュ（1 MiB ごと）を手元の索引に残しておく**。
  - 次の同期で、送り先が前回のまま（大きさ・日時が記録と同じ）なら、送り先を
    `<名前>.yypart` に**サーバー側でコピー**し（同じ共有の中の `CopyFile2` は SMB のサーバー側コピーになり、
    回線を使わない）、手元で計算したハッシュが違うブロックだけを書き込んでから置き換える。
  - 送り先が前回と違う・記録がない・サーバー側コピーが使えないときは、ファイル全体を送る。
  - ブロックは位置で比べる（rsync の「ずれ」の検出はしない）。データベースのファイル・仮想ディスク・
    追記されるログなど、中が書き換わる大きなファイルで効く。

### 4.4 レジューム（ファイルの途中から）

13 章のジャーナルの作りを使う。

- 同期の 1 回（実行）ごとに、計画と進みをジャーナル（`filemanager\runs\<番号>.run`）に書きながら進める。
  ファイルごとに「済み」「送っている（確かな位置）」「まだ」を持つ。書き換えは一時ファイルに書いて
  ディスクに書き出し（`fsync`）、置き換える。前の内容か新しい内容のどちらかが必ず残る。
- 送っているファイルは、約 1 秒ごとに、送り先の途中のファイルをディスクに書き出して（`FlushFileBuffers`）から
  確かな位置を進める。続けるときは「ジャーナルの位置」と「途中のファイルの大きさ」の小さい方から、
  その直前の 64 KiB を送り先から読んで手元と比べ、違えば最初から送る。
- 送り元のファイルが、始めたときと大きさ・更新日時が変わっていたら、続けずに最初から送り直す。
- 接続が切れたら（`ERROR_NETNAME_DELETED`・`ERROR_UNEXP_NET_ERR`・`ERROR_BAD_NETPATH` など）、2・5・10・20・
  30・60 秒と間を空けて続ける。進みがないまま続けて失敗した回数が上限（既定 10）を超えたら中断にする。
  アクセス拒否・空きがない は待っても直らないので、そのファイルを失敗にして次へ進む。

### 4.5 レジューム（同期の途中から）

- 一時停止・アプリの終了・異常終了・電源断のあとで起動すると、終わっていない実行を一覧に出し、
  「続ける」で残りのファイルから送る（済みのファイルは送り直さない。送り先の大きさ・日時を確かめるだけ）。
- 名前を置き換えた直後、ジャーナルに「済み」と書く前に落ちたときは、送り先の大きさ・日時が送り元と同じで
  途中のファイルがなければ済みとする（13 章 5.1 と同じ）。
- 起動中はジャーナルのフォルダの `yyfilemanager.lock` を開いておき、2 つのアプリが同じ実行を同時に続けない
  ようにする。
- 前回から時間がたっていれば、続ける前に計画を作り直すかを尋ねる（その間に変わったファイルを拾う）。

### 4.6 定期実行

- 同期ジョブをコマンドラインから実行できる（`yyfilemanager.exe --sync <名前> [--yes]`。画面を出さずに
  実行し、記録に書いて終わる）。Windows のタスク スケジューラに登録するのは人が行う（アプリは登録しない）。
- 衝突があれば送らずに残し、次に画面で開いたときに知らせる。

## 5. 似たファイルと新しい版の判定（`yy_files::similar`）

「報告書_v2.docx」「報告書_v3_最終.docx」「報告書 - コピー.docx」「20260901_報告書.docx」のような、同じ
文書の別の版を見つけ、グループの中でどれが最新かを判定します。判定は**提案**で、決めるのは人です（7 章）。

### 5.1 名前の正規化

ファイル名（拡張子を除く）から、版や写しを表す飾りを取り除いて「元の名前」を作り、取り除いた飾りは
版の手がかりとして残す。

| 種類 | 例 | 手がかり |
|---|---|---|
| 版の番号 | `_v2`・`v1.3`・`ver3`・`rev.4`・`R5`・`第2版`・`(2)`・`_02` | 番号（大きいほど新しい） |
| 日付・時刻 | `20260901`・`2026-09-01`・`260901`・`2026年9月1日`・`_1530` | 日時（新しいほど新しい） |
| 新しさの言葉 | `最新`・`最終`・`確定`・`final`・`latest`・`new`・`修正`・`改`・`差替` | 新しさ（強さを付ける） |
| 古さの言葉 | `旧`・`old`・`bak`・`backup`・`古い`・`draft`・`下書き`・`案` | 古さ |
| 写し | `- コピー`・`- Copy`・`のコピー`・`(1)`・`copy of` | 写し（版ではない） |
| 人の名前・注記 | `_田中確認`・`_rev_yamada` | 注記（版の順には使わない） |

- 全角・半角、大文字・小文字、区切り（空白・`_`・`-`・`.`）の違いはそろえてから比べる（NFKC）。
- 規則は設定ファイルで足せる（言葉の一覧と正規表現）。既定の規則は日本語と英語の一般的な付け方を入れる。

### 5.2 似ている度合いとグループ化

- 同じ拡張子の仲間（`.doc`・`.docx`、`.xls`・`.xlsx`・`.xlsm`、`.jpg`・`.jpeg` などは仲間）で、元の名前どうしの
  似ている度合いを求める: 文字の 2-gram の重なり（Dice 係数）と、編集距離（Jaro-Winkler）の重み付きの和。
  既定のしきい値は 0.85（設定で変えられる）。元の名前がまったく同じなら 1.0。
- 数百万ファイルで総当たり（n²）はできないので、**ブロック分け**してから比べる: 拡張子の仲間 × 元の名前の
  先頭の 2-gram の組（MinHash の LSH）で候補の組だけを作り、似ている組を Union-Find でグループにまとめる。
  同じフォルダ・近いフォルダにあるものは度合いを少し上げる（同じ文書の版は近くに置かれやすい）。
- 大きさが極端に違うもの（10 倍以上）は、名前が似ていても別のグループにする（設定で変えられる）。
- 中身が同じものは 6 章の重複として扱い、版のグループの中では 1 つにまとめて見せる。

### 5.3 新しい版の順位付け

グループの中を、次の手がかりを上から順に使って並べ、いちばん上を「最新（提案）」にする。

1. 名前の版の番号（同じ書き方どうし）・名前の日付
2. 新しさ・古さの言葉
3. 更新日時（ファイルの日時は写すと変わることがあるので、名前の手がかりより弱くする）
4. 大きさ（ほかが同じなら、大きい方を新しいとみなす。追記されてきた文書を想定）
5. 写し（`- コピー` など）は、元と中身が違うときだけ版として扱う（同じなら重複）

- 手がかりどうしが食い違うとき（名前は v3 なのに日時は v2 より古い、など）は「判定に自信がない」印を付け、
  理由を一覧に出す（例: 「名前の版 v3 > v2、ただし更新日時は v2 の方が 3 日新しい」）。
- 結果は、グループ・最新の提案・それぞれの理由と自信の度合い（高・中・低）。

## 6. 完全に同じファイル（`yy_files::dupes`）

- 3 段で絞る: (1) 大きさが同じもの → (2) 先頭と末尾の 64 KiB と大きさのハッシュが同じもの → (3) ファイル全体の
  ハッシュが同じもの。多くのファイルは (1)(2) で外れるので、読むのはごく一部で済む。
- ハッシュは BLAKE3（新しい依存。SHA-256 の 3〜5 倍速く、並列にもできる。14 節の 1）。
  結果は索引のキャッシュに残し、変わっていないファイルは読み直さない。
- 同じファイル ID（ハードリンク）は重複に数えない。大きさ 0 のファイルは別に数える（既定は対象外）。
- 「(3) のあとで中身を 1 バイトずつ比べる」を選べる（ハッシュの衝突を心配する場合。既定は使わない）。
- 対象は 1 つのフォルダの中、複数のフォルダの間（手元と共有フォルダの間も）のどちらでもよい。
- 結果: グループごとに、残す 1 つの提案（既定は「いちばん古い作成日時」。「いちばん浅いフォルダ」「指定した
  フォルダの中のもの」も選べる）と、それ以外の写し。

## 7. 確かめて一括で削除する（`yy_files::purge`）

### 7.1 削除の候補とチェック

- 削除の候補は 5 章（古い版）と 6 章（重複の写し）から作る。最初からチェックを付けるのは「判定に自信が高い」
  ものだけで、それ以外は人がチェックする。
- 一覧は仮想リスト（数十万行でも軽い）。列は パス・大きさ・更新日時・理由・自信・グループ。グループごとに
  まとめて開閉でき、グループの中で「これを残す」を選び直せる（残すものはチェックできない）。
- 絞り込み（フォルダ・拡張子・理由・自信・日付の範囲）と、絞り込んだものにまとめてチェック・チェックを外す。
- ファイルの中身を確かめられる: 既定のアプリで開く・エクスプローラーで場所を開く・テキストなら yyeditor で開く・
  同じグループの 2 つを並べて比べる（テキストは yyeditor の比較、それ以外は大きさ・日時・ハッシュを並べる）。
- チェックの状態は保存して、あとで続けられる（`filemanager\reviews\<番号>.review`）。

### 7.2 削除の実行と、実行前の確かめ

- 「削除」を押すと、件数・大きさの合計・グループごとの「残すもの」を見せて、もう一度確かめる。
- 消す直前に、ファイルごとに走査したときと大きさ・更新日時が同じことを確かめる（変わっていたら消さずに
  一覧に戻す）。重複の写しは、残すファイルがまだあり、中身が同じこと（ハッシュ）も確かめる。
- **グループの最後の 1 つは消さない**（全部にチェックが付いていたら止める）。
- 守るフォルダ（設定。システムのフォルダ・指定したフォルダ）の中は候補にしない。

### 7.3 消し方と取り消し

- 手元のドライブ: ごみ箱へ（`IFileOperation` の `FOFX_RECYCLEONDELETE`）。
- 共有フォルダ: ごみ箱がないので、**隔離フォルダ**（同じ共有の `\.yyfm-trash\<日時>\<元の相対パス>`）へ名前の
  変更で移す（同じ共有の中なので、大きさによらずすぐ終わる）。隔離フォルダを作れない共有（権限がない など）では、
  確認を 2 回したうえで、すぐに消す（14 節の 3）。設定で「いつもすぐに消す」も選べる（既定は使わない）。
- 消した記録（`filemanager\purges\<日時>.csv`: 元のパス・移した先・大きさ・更新日時・ハッシュ・理由）を残し、
  「取り消し」で元の場所に戻せる（元の場所に同じ名前があれば尋ねる）。
- 隔離フォルダは、設定の日数（既定 30 日）を過ぎたものを、次に開いたときに一覧で確かめてから消す。
- **隔離フォルダの場所は作業ごとに人が選ぶ**（2026-10-09 の変更）。削除の実行・ミラーの同期の実行のたびに
  「既定の場所（それぞれの共有・送り先）に作る／場所を選ぶ／やめる」を尋ねる。選んだ場所には
  `<場所>\.yyfm-trash\<日時>\<元のルートの名前>\<元の相対パス>` に移す。別のボリュームなら、写して大きさを
  確かめ、日時を合わせてから元を消す（途中で止まって残った写しは次に置き換える）。ミラーの同期ジョブは
  保存するときに選んだ場所を覚え、定期実行で使う。実行のジャーナルにも場所を書く（前の形は送り先として読む）。

## 8. ファイルの検索（`yy_files::search`）

手元のフォルダと共有フォルダ（複数をまとめて）から、名前・属性・中身でファイルを探します。見つけたファイルは、
開く・場所を開く・同期や削除の候補に加える、といったほかの機能にそのまま渡せます。

### 8.1 条件

| 条件 | 書き方・例 |
|---|---|
| 名前 | 部分一致（既定。`見積`）、ワイルドカード（`見積*.xlsx`）、正規表現（`/^\d{8}_.*\.pdf$/`）。全角・半角、大文字・小文字、ひらがな・カタカナの違いを無視するかを選べる（既定は無視） |
| パス | フォルダの名前を含む（`案件A\見積`）、除くフォルダ |
| 種類 | 拡張子（`xlsx;xls;csv`）、仲間でまとめた種類（文書・表計算・画像・動画・圧縮・テキスト） |
| 大きさ | `> 100MB`・`1KB..10KB`・空（0 バイト） |
| 日時 | 更新日時・作成日時の範囲（`2026-09-01..2026-09-30`・「今日」「今週」「30 日より前」） |
| 属性 | 読み取り専用・隠し・システム |
| 中身 | 文字列か正規表現（大文字・小文字の区別、単語単位）。エディタの Grep と同じ指定 |
| 整理の結果 | 「重複がある」「古い版と判定された」「新しい版がほかにある」（5・6 章の結果を使う） |

- 条件は AND で組み合わせる。1 行の検索欄にまとめて書くこともできる（`見積 ext:xlsx size:>1MB modified:>=2026-09-01 content:"税込"`。
  欄で指定したものと同じ条件になる）。
- 条件に名前を付けて保存できる（「保存した検索」。左の一覧から 1 クリックで実行）。

### 8.2 名前・属性の検索（目録から）

- 目録（3 章）があれば、走査し直さずに目録から探す（100 万ファイルで 1 秒未満。パスの文字列の領域を
  まとめて走査し、条件は列ごとに当てる）。目録が古ければ（設定の時間を過ぎた、または「最新にする」）、
  走査し直しながら見つかった順に結果を足していく。
- 目録がない場所は、その場で走査しながら探す（走査の結果は目録として残すので、次からは速い）。
- Windows Search のインデックス（エクスプローラーの検索）は使わない。共有フォルダでは使えないことが多く、
  結果の範囲も分かりにくいため。

### 8.3 中身の検索

- 名前・属性の条件で絞ってから、残ったファイルの中身を読む（中身だけの検索でも、種類や大きさで絞ると速い）。
- エディタの Grep（`yy_core::grep`）と同じ部品を使い、ファイルごとに文字コード（UTF-8・Shift_JIS・EUC-JP・
  UTF-16 など）を判別して探す。ファイルの単位で並列に読む（手元は CPU の数、共有フォルダは既定 8 本）。
- バイナリのファイル（先頭に NUL が多いなど）は飛ばす。大きなファイル（既定 1 GB 超）は飛ばすか尋ねる。
- **Office の文書**（`docx`・`xlsx`・`pptx`）の中の文字列も探す（14 節の 6）。ZIP の中の XML から文字列を
  取り出す（`miniz_oxide` で展開。新しい依存は要らない）。PDF は対象外（文字列の取り出しに別の部品が要るため、
  将来の拡張）。
- 中身の索引（全文検索のインデックス）は作らない（毎回読む）。共有フォルダの大きな木では遅いので、
  将来の拡張として、目録と同じ置き場所に単語の索引を持てるようにしておく。

### 8.4 結果

- 一覧（仮想リスト）: 名前・フォルダ・大きさ・更新日時・種類、中身で探したときは一致した行（前後を少し）と
  行番号・一致の数。見つかった順に足していき、並べ替え（列の見出し）と絞り込みができる。
- 操作: 開く（既定のアプリ）・エクスプローラーで場所を開く・yyeditor でその行を開く・パスをコピー・
  CSV に書き出す（yysheet で開ける）・同期ジョブの送り元に加える・削除の確認（7 章）に加える・
  「このファイルの別の版を探す」（5 章の判定をこのファイルのグループだけで行う）・「同じ中身のファイルを探す」。
- 中止（Esc）しても、そこまでの結果は残す。

## 11. 設定（`[filemanager]`）

```toml
[filemanager]
scan_threads = 16          # 走査の並列数
copy_threads = 4           # 同期で同時に送るファイルの数
time_tolerance_sec = 2     # 更新日時の誤差の許し幅
delta_min_mb = 64          # この大きさ以上は差分の送り方（0 で使わない）
verify = "size"            # 送った後の確かめ（"size" / "hash"）
similar_threshold = 0.85   # 似ている度合いのしきい値
trash_days = 30            # 隔離フォルダに残す日数
search_threads = 8         # 共有フォルダの中身の検索の並列数（手元は CPU の数）
search_max_mb = 1024       # これより大きなファイルの中身は探さない（尋ねる）
index_max_age_min = 60     # 目録がこれより古ければ、検索のときに走査し直す
exclude = ["Thumbs.db", "desktop.ini", "~$*", "*.tmp"]
protect = []               # 削除の候補にしないフォルダ
```

## 12. テスト

- `yy-files` は OS に依存しないので Linux の CI で試験する。
  - 同期: 新規・更新・日時だけ・ミラーの削除・衝突の判定、大文字・小文字と NFC・NFD の突き合わせ、時刻の誤差。
  - レジューム: 試験用のファイルシステム（`fs::Faulty`）で、書き込みの途中・名前の置き換えの前後・ジャーナルの
    書き換えの途中で切る・落とす（プロセスを止める代わりに、その時点の状態から新しく始める）を何通りも繰り返し、
    最後に送り先が送り元と同じで、途中のファイルが残らないことを確かめる（プロパティ テスト）。
  - 差分の送り方: ブロックの一部だけ変えたファイルで、書き込んだ量と結果の中身を確かめる。
  - 似たファイル: 名前の正規化の表（5.1 の例をすべて）、グループ化、順位付けと「自信がない」判定の例。
    ブロック分けの結果が総当たりと同じになることを小さな集合で確かめる。
  - 重複: ハードリンク・大きさ 0・先頭と末尾だけ同じファイル。
  - 削除: 走査後に変わったファイルを消さない、グループの最後の 1 つを消さない、取り消しで元に戻る。
  - 検索: 1 行の検索欄の読み取り（条件の組み合わせ・日付の言葉・大きさの単位）、全角・半角・かなの違いを
    無視する比べ方、目録からの検索と走査しながらの検索が同じ結果になること、文字コードの違うファイルの中身、
    バイナリを飛ばすこと、Office の文書の中の文字列。
- Windows の CI: 長いパス、ごみ箱、`CopyFile2` のサーバー側コピー（手元の `\\localhost\C$` の共有で）、
  属性と日時の写し、ファイル ID。
- 性能: 100 万ファイルの合成した木で、走査・似た名前・重複の時間を測る（ベンチマーク）。

## 14. 決まったこと（2026-10-08。すべて提案どおり）

1. **ハッシュ**: BLAKE3 を依存に加える（重複の (3) と索引のキャッシュのハッシュ）。
2. **アプリの名前**: `yyfilemanager.exe`（`apps/yyfilemanager`）。
3. **共有フォルダでの削除**: 共有の中の隔離フォルダ（`.yyfm-trash`）へ移す。隔離フォルダを作れない共有

4. **同期の向き**: 当面は「手元 → 共有フォルダ」の片方向。「共有フォルダ → 手元」は同じ部品で後から足す。
   両方向の同期は対象外。
5. **新しい版の判定**: 名前の手がかり（版の番号・日付・新しさの言葉）を更新日時より優先する（5.3）。
   既定の規則は 5.1 の表のとおり（社内の付け方は、設定ファイルで後から足す）。
6. **中身の検索の範囲**: テキストのファイルと Office の文書（`docx`・`xlsx`・`pptx`。ZIP の中の XML から取り
   出す。新しい依存なし）。PDF は対象外（将来の拡張）。

## 15. 実装の状況（2026-10-09）

M1〜M6 を実装しました（中核は `crates/yy-files`、画面は `crates/yy-win/src/fm`、実行ファイルは
`apps/yyfilemanager`、利用ガイドは `crates/yy-win/help/filemanager.md`）。

- 走査（並列）・目録・索引のキャッシュ（BLAKE3。全体と先頭・末尾）、`fs` の口と、試験用に指定した回数で
  落ちる・切れる実装。
- 同期: 計画（更新・ミラー・日時だけ・衝突・両方残す）、`.yypart` への書き込みと置き換え、ジャーナルと
  ファイルの途中からのレジューム、切断時の間隔を延ばした再試行、同期ジョブの保存、`--sync <名前>` の画面なしの
  実行。どこで落ちても続きから正しく終わることを、落ちる位置を変えて試験する。
- 差分の送り方（4.3）: 送ったときに送り先の内容のブロック（1 MiB）ごとのハッシュ（BLAKE3 の先頭 16 バイト）を
  前回の同期の状態に残す（そのときの大きさ・日時と一緒に。違えば使わない）。送り先が前回のままなら
  `Fs::copy_file`（Windows の `CopyFileEx`。同じ共有の中では SMB のサーバー側コピー）で `.yypart` に写し、
  違うブロックだけを書いてから置き換える。サーバー側のコピーができなければ全体を送る。途中で止まったときは
  差分の送り方をやり直す。書いた量・結果・落ちたあとの続きを試験する。
- 「共有フォルダ → 手元」: 中核は向きに依存しないので、画面の「入れ替え」で送り元・送り先を入れ替える。
  送り元が共有フォルダのときは差分の送り方を使わない（送り元を読むのに回線を使うため）。
- 重複（3 段）、似たファイル（名前の正規化・Dice と Jaro-Winkler・MinHash の LSH・順位付けと自信）、
  削除の確認（実行前の確かめ・ごみ箱・隔離フォルダ・確認 2 回の直接削除・CSV の記録・取り消し）、
  隔離フォルダの期限切れの削除（「整理」メニュー）。
- 検索: 1 行の検索欄、中身の並列の検索（エディタの Grep の部品）と Office の文書の文字列の取り出し、
  CSV への書き出し、保存した検索（`searches.toml`）、目録の保存と再利用（`index_max_age_min` より新しければ
  走査し直さない。重複は毎回走査する）、結果からの「このファイルの別の版を探す」「同じ中身のファイルを探す」。
- 画面: 6 つのタブ・仮想リスト・作業スレッドと中止・記録（`logs\filemanager.log`）・ヘルプ（F1）。

- 検索の追加（2026-10-09）: 整理の結果の条件（`dupe:yes|no`・`version:old|newest|any`。その場で重複・版の判定を
  行う）、結果からの「削除の確認に加える」（1 件ずつの候補。残す相手がないので「グループの最後の 1 つ」の決まりは
  使わない）・「このフォルダを同期の送り元にする」、古い目録で見つかったものを走査し直す前に先に出す表示、
  PDF の中身（`yy_files::pdf`。オブジェクト ストリーム・FlateDecode・ToUnicode の CMap。新しい依存なし。
  スキャンした画像・暗号化されたものは対象外）。
- Windows の CI で、手元の管理共有（`\\localhost\C$`）を送り先にしたサーバー側コピーと差分の送り方の試験
  （共有を使えない環境では飛ばす）。

- ACL を写す設定（`copy_acl`。Windows は DACL の明示的な項目と継承の止め方を `GetNamedSecurityInfoW`・
  `SetNamedSecurityInfoW` で写す。所有者・SACL は特権が要るので写さない。ほかの OS は属性のモード）。写せなくても
  送ったことは済みにして記録に残す。Windows の CI で、継承を止めた DACL が写ることを確かめる。
- 走査しながら見つかった順に検索の結果を足していく表示（前回の目録がない場所。`scan_with` の `found`）。
- Windows の CI の管理共有の試験は `YY_REQUIRE_SMB_SHARE=1` で必須にした（共有を使えなければ失敗）。

- 中身の索引（`yy_files::fulltext`）: 隣り合う 2 文字（大文字・小文字をそろえる）を 65,536 の区分けに丸めた転置索引を
  ルートごとに `filemanager\fulltext\` に置く。探す文字列の区分けをすべて含むファイルだけを読み、候補は
  実際に読んで確かめる（余計な候補は出るが見落としはない。索引なしの検索と同じ結果になることをランダムな
  文字列で試験する）。索引にない・変わったファイルは検索のついでに読んで足し、消えたものは消したにして、
  多くなったら詰め直す。正規表現・1 文字の検索では使わない。

- 中身を読む対象の絞り込み（2026-10-09 の変更）: 中身の検索と中身の索引は、設定の `content_patterns` で名指しした
  ファイル名のパターン（拡張子）に合うファイルだけにする（既定はテキスト・ソース・COBOL・Office・PDF の主な
  拡張子）。合わないファイルは読まず、索引にも入れない。索引のバキューム（「整理」メニュー）で、パターンに
  合わなくなった・消えた・変わったファイルの記録を除いて詰め直し、場所がなくなった索引は消す。

これで 13 節の段階と 14 節で決めたことは、すべて実装しました。
