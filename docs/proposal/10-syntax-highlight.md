# 10. ファイル種類別シンタックスハイライト

## 1. 要求

- ファイルの種類（拡張子・ファイル名・先頭行など）に応じて、キーワード・文字列・コメント・数値などを色分け表示する。
- 主要なプログラミング言語・設定ファイル・マークアップに加え、業務データ（ログ、COBOL/JCL などのメインフレーム系）にも対応する。
- 利用者が定義ファイルを追加・編集して、独自のファイル種類を定義できる。
- **軽量さと巨大ファイル対応を損なわない**: 起動・ファイルオープンを遅くせず、数 GB のファイルでも表示範囲の色付けは即座に行う。
- 入力のたびに全体を再解析しない（差分更新）。
- ライト / ダークのカラーテーマに対応する。

## 2. 方式の比較

| 方式 | 利点 | 欠点 | 評価 |
|------|------|------|------|
| **独自の宣言的定義＋状態機械（`yy-syntax`）** | 軽量・高速。状態のチェックポイント化で巨大ファイルに対応できる。定義ファイルが単純で利用者が書きやすい（EmEditor・秀丸の強調定義に近い） | 構文木レベルの正確さはない | **採用（標準エンジン）** |
| TextMate / Sublime 文法（`syntect`） | 既存の文法資産が豊富で高精度 | 文法の読み込み・正規表現のコンパイルが重い。1 行ずつ状態を引き継ぐため、任意位置から始めるには先頭からの走査が必要。巨大ファイルに不向き | 定義の **取り込み（変換）** のみ検討 |
| tree-sitter | 構文木ベースで最も正確。差分パースが得意 | 全文をパースする前提でメモリがファイルサイズに比例。文法ごとに C のパーサーが必要でバイナリが肥大化 | 将来の拡張候補（小さいファイルでのアウトライン・折りたたみ用） |

エディタの主目的（巨大ファイル・業務データの編集）と「軽量」の要求を優先し、**独自エンジンを標準** とします。構文ハイライトは見た目の補助であり、多少の不正確さ（例: 複雑な言語構文の一部）は許容します。

## 3. ファイル種類の判定

ファイルを開いたとき、次の優先順位でファイル種類（= ハイライト定義）を決めます。

| 優先 | 判定方法 | 例 |
|------|---------|----|
| 1 | ユーザーが手動で指定（ステータスバーから選択）。ファイルごとに履歴として記憶 | |
| 2 | モードライン | `# vim: ft=python`、`-*- mode: ruby -*-` |
| 3 | ファイル名の完全一致 | `Makefile`、`Dockerfile`、`.gitignore`、`CMakeLists.txt` |
| 4 | 拡張子（複合拡張子を優先） | `.d.ts` → TypeScript 宣言、`.rs` → Rust、`.cbl` → COBOL |
| 5 | 先頭行のパターン | `#!/usr/bin/env python`、`<?xml`、`<!DOCTYPE html>` |
| 6 | パス規則（設定） | `**/logs/*.txt` → ログ |
| 7 | 該当なし | プレーンテキスト |

ファイル種類の定義は 01 章 4.4 の `[filetype.*]` 設定と統合し、1 つのファイル種類に「編集モード（テキスト / 区切り文字）」「既定の文字コード・改行コード」「ハイライト定義」「インデント設定」をまとめて持たせます。

```toml
[filetype.python]
extensions = ["py", "pyw"]
first_line = '^#!.*\bpython[0-9.]*\b'
syntax = "python"
indent = { style = "spaces", width = 4 }

[filetype.cobol]
extensions = ["cbl", "cob", "cpy"]
syntax = "cobol-fixed"
encoding = "IBM-930"      # 保存時の既定。開くときは判別結果を優先
```

## 4. 定義ファイルの形式

### 4.1 構成要素

定義は TOML で書きます。**コンテキスト（状態）** の集まりとして記述し、各コンテキストは「そのコンテキスト内で探すルール」を持ちます。

```toml
# syntax/c.toml
name = "C"
scope = "source.c"

[keywords]
keyword = ["if", "else", "for", "while", "do", "switch", "case", "default",
           "break", "continue", "return", "goto", "sizeof", "typedef"]
type    = ["int", "char", "short", "long", "float", "double", "void",
           "signed", "unsigned", "struct", "union", "enum", "const", "static"]
constant = ["NULL", "true", "false"]
case_sensitive = true

[[context.main]]
match = '//.*$'
token = "comment"

[[context.main]]
begin = '/\*'
end   = '\*/'
token = "comment"            # 複数行コメント → 行をまたぐ状態になる

[[context.main]]
begin = '"'
end   = '"'
skip  = '\\.'                # エスケープ文字は終端として扱わない
token = "string"

[[context.main]]
match = '^\s*#\s*\w+'
token = "preprocessor"

[[context.main]]
match = '\b(0[xX][0-9a-fA-F]+|\d+(\.\d+)?([eE][+-]?\d+)?)[uUlLfF]*\b'
token = "number"

[[context.main]]
match = '\b([A-Za-z_]\w*)\s*\('
captures = { 1 = "function" }  # 先読みは使えない（regex クレート）ため、キャプチャで一部だけ色付け
```

| 要素 | 意味 |
|------|------|
| `keywords` | 単語の一覧。トークン種別ごとに列挙。大量のキーワードでも高速（下記 5.2） |
| `match` | 1 行内で完結するパターン（`regex` 構文。先読み・後方参照は使えないため、`captures` でグループ単位に色を付ける） |
| `begin` / `end` | 範囲。`end` が同じ行で見つからなければ次の行へ状態を引き継ぐ |
| `skip` | 範囲内で `end` と見なさないパターン（エスケープ） |
| `contains` | 範囲内で有効にする別コンテキスト（文字列内の埋め込み式など） |
| `embed` | 範囲内を別言語の定義で色付け（HTML 内の `<script>` → JavaScript、Markdown のコードブロック） |
| `columns` | 固定桁の領域指定（COBOL 等、下記 4.2） |
| `line_start` | 行頭でのみ有効なルール（Markdown の見出し、diff の `+` `-` 等） |

### 4.2 固定桁形式（メインフレーム向け）

COBOL（固定形式）や JCL のように、**桁位置で意味が決まる** 言語のために桁指定を用意します。桁は表示桁（09 章の VCol）で数えます。

```toml
# syntax/cobol-fixed.toml
[[columns]]
range = [1, 6]          # 一連番号領域
token = "line-number"

[[columns]]
range = [7, 7]          # 標識領域: '*' '/' ならその行全体がコメント
match = '[*/]'
line_token = "comment"

[[columns]]
range = [73, 80]        # 見出し領域
token = "comment"

[[columns]]
range = [8, 72]         # A 領域・B 領域はキーワード・文字列ルールを適用
context = "main"
```

### 4.3 他形式の取り込み

- `tools/import-syntax` で、TextMate / Sublime の文法（`.tmLanguage` / `.sublime-syntax`）のうち、本エンジンで表現できる部分（`match` / `begin`-`end` / キーワード）を変換する。変換できないルールは一覧で報告し、手作業での補完を前提とする。
- EmEditor の強調表示定義（キーワードの一覧＋正規表現）も同様に変換対象とする。

## 5. ハイライトエンジン（`yy-syntax`）

### 5.1 状態と行単位処理

- エンジンは **1 行（論理行）ずつ** 処理する。入力は「行の開始状態」と「行のテキスト」、出力は「トークン範囲の列」と「行の終了状態」。
- 状態は「コンテキストのスタック」で、`begin` で積み、`end` で降ろす。状態は小さな値（コンテキスト ID の短い配列）で、ハッシュで比較できる。

```rust
pub struct LineState(SmallVec<[ContextId; 4]>);   // 大半の行は深さ 0〜2

pub trait Highlighter {
    fn highlight_line(&self, start: &LineState, line: &[u8],
                      out: &mut Vec<TokenSpan>) -> LineState;
}

pub struct TokenSpan { pub range: Range<u32>, pub token: TokenKind }
```

### 5.2 高速化

- 各コンテキストのルールは **1 つの複数パターン DFA**（`regex-automata` の `meta::Regex` の多パターン機能）にまとめてコンパイルし、1 回の走査で「最も左で一致するルール」を求める。ルール数に比例して遅くならない。
- キーワードは正規表現に展開せず、識別子として切り出した単語をハッシュ表（完全ハッシュ、`phf`）で引く。
- 定義ファイルは初回使用時にのみ読み込み・コンパイルし（遅延ロード）、起動時間に影響させない。コンパイル済みの DFA は `%LOCALAPPDATA%\yyeditor\cache` にキャッシュする。
- 組み込み定義は exe にテキストで埋め込む（数十言語で数百 KB 程度）。

### 5.3 巨大ファイル対応: 状態チェックポイント

行をまたぐ状態（ブロックコメント・複数行文字列）があるため、任意の位置から正しく色付けするには **その行の開始状態** が必要です。先頭から全行を処理すると巨大ファイルでは間に合わないため、CSV の引用符状態（04 章 3.2）と同じ方式を使います。

```rust
pub struct SyntaxIndex {
    generation: u64,
    /// ピースツリーのピース（≤1 MiB）先頭、およびピース内 1,000 行ごとの行開始状態
    checkpoints: PieceMap<Vec<(u64 /*line*/, LineState)>>,
    scanned_until: u64,
}
```

| 状況 | 動作 |
|------|------|
| 通常サイズ（既定 16 MB 未満） | 開いた直後にバックグラウンドで全体を走査し、チェックポイントを作る（数十 ms） |
| 巨大ファイル | 表示範囲の直前のチェックポイントから表示範囲までを処理。チェックポイントが未作成の範囲は、表示位置から最大 N 行（既定 5,000 行）遡った位置から「初期状態」と仮定して処理し、暫定表示する。バックグラウンドの走査が追いついたら正しい状態で再描画 |
| 同期点を持つ言語 | 定義に `sync = '^\S'` のような「この行頭では必ず初期状態」というパターンを書けば、遡りをそこで止められる（COBOL・INI・ログなど多くの業務データは 1 行で完結） |
| 行単位で完結する定義（複数行ルールなし） | チェックポイント不要。表示範囲だけを処理（ファイルサイズに完全に非依存） |

- バックグラウンド走査は低優先度のジョブとし、検索・保存などを優先する。
- 巨大ファイル（既定 1 GB 以上）では、背景での全体走査を既定で行わず、表示範囲周辺のみ処理する（設定で変更可能）。

### 5.4 編集時の差分更新

1. 編集された行から再処理を開始する（その行の開始状態はチェックポイントまたは直前行のキャッシュから得る）。
2. 各行の終了状態を旧結果と比べ、**同じ状態に戻った行で再処理を打ち切る**（状態の収束判定）。
3. `/*` の入力のように以降の全行に影響する場合は、表示範囲だけを同期的に処理し、それより後ろはバックグラウンドで再走査する。

入力のたびに処理するのは通常 1〜数行で済みます。

### 5.5 長大行・性能の上限

- 1 行が既定 10,000 バイトを超える場合、その行は表示セグメント（02 章 3.5）単位で処理し、行全体は処理しない（状態は近似）。
- 1 行の処理時間に上限を設け、超えたらその行以降をプレーン表示に切り替えて警告を表示する（異常なデータでの UI の固まりを防ぐ）。
- ハイライト結果は `(スナップショット世代, 行開始オフセット) → Vec<TokenSpan>` の LRU キャッシュに保持し、スクロールで再計算しない。

## 6. 描画との統合

- `yy-layout` は行ごとに「トークン範囲」「選択範囲」「検索マッチ」「矩形・マルチカーソル」「不正バイト」の属性範囲を重ね合わせ、1 つの属性スパン列にまとめて描画層に渡す。優先順位は 選択 ＞ 検索マッチ ＞ シンタックス。
- 描画層（`yy-win`）は属性スパンごとに文字色・背景色・太字・斜体・下線を設定する（DirectWrite の `SetDrawingEffect` / 高速パスでは `DrawGlyphRun` の色切替）。太字・斜体は幅が変わる場合があるため、等幅の高速パスでは既定で無効（色のみ）。
- 区切り文字モードでは、ファイル種類の定義ではなく **列ごとの色分け** を使う（04 章）。任意で、各セル内に「数値」「日付」「空」などの型別の色を付ける簡易ハイライトを用意する。

## 7. カラーテーマ

トークン種別（`comment`, `string`, `keyword` など、TextMate のスコープ名に近い階層名）を色に対応付けたテーマファイルを用意します。

```toml
# themes/default-dark.toml
[colors]
background   = "#1E1E1E"
foreground   = "#D4D4D4"
comment      = { fg = "#6A9955", italic = true }
string       = "#CE9178"
keyword      = { fg = "#569CD6", bold = true }
"keyword.control" = "#C586C0"      # 未定義の細分類は親（keyword）を継承
number       = "#B5CEA8"
invalid      = { fg = "#FFFFFF", bg = "#F44747" }
```

- Windows のライト / ダークモードに追従して自動で切り替え（07 章 4）。
- 組み込みテーマ: ライト、ダーク、ハイコントラスト（Windows のハイコントラスト設定時は OS の配色を使用）。
- 設定画面で色を変更でき、変更は即座に反映される。

## 8. 組み込み定義（初期リリース）

| 分類 | ファイル種類 |
|------|-------------|
| プログラミング言語 | C / C++、C#、Java、Rust、Go、Python、JavaScript / TypeScript、PHP、Ruby、Perl、Visual Basic / VBA、Kotlin、Swift |
| スクリプト | バッチ（.bat / .cmd）、PowerShell、シェルスクリプト |
| マークアップ・データ | HTML（JavaScript・CSS を埋め込み）、XML、CSS、JSON、YAML、TOML、INI、Markdown（コードブロックを埋め込み）、SQL |
| 業務・メインフレーム | COBOL（固定形式 / 自由形式）、JCL、PL/I、RPG（固定桁）、Rhai（3270 のマクロ。14 章 13） |
| ログ・差分 | ログ（日時・ERROR / WARN / INFO の色分け、IP アドレス、URL）、diff / patch |
| その他 | Makefile、Dockerfile、.gitignore、正規表現（検索バー内での色付け） |

## 9. ハイライト以外への利用

同じ定義とトークン結果を次の機能でも使います。

| 機能 | 使い方 |
|------|--------|
| 括弧の対応表示・ジャンプ | コメント・文字列内の括弧を除外して対応を探す |
| 単語単位の選択・検索 | 言語ごとの識別子の定義を使う |
| コメント化 / 解除（Ctrl+/） | 定義の `line_comment` / `block_comment` を使う |
| 検索範囲の限定 | 「コメントを除いて検索」「文字列内のみ検索」（05 章の検索範囲の拡張） |
| 簡易アウトライン | 定義に `outline = '^\s*(fn|def|class)\s+(\w+)'` のような見出しパターンを書けば、関数一覧を表示 |

## 10. 実装の置き場所とテスト

| 機能 | クレート |
|------|---------|
| 定義の読み込み・コンパイル、ハイライトエンジン、チェックポイント、差分更新 | `yy-syntax`（新規、OS 非依存） |
| ファイル種類の判定、テーマ | `yy-config` |
| 属性スパンの重ね合わせ | `yy-layout` |
| 色・書式の描画 | `yy-win` |

テスト:

- 定義ごとのスナップショットテスト: `tests/fixtures/syntax/<言語>/` のサンプルに対するトークン列を期待値ファイルと比較する（定義変更時の差分確認）。
- 差分更新の検証: ランダムな編集を加え、差分更新の結果と「全体を最初から処理した結果」が一致することを `proptest` で確認する。
- チェックポイントからの処理結果が、先頭からの処理結果と一致することを確認する。
- 性能: 1 GB のソースコード風ファイルで、任意位置へのジャンプ後の初回描画が 16 ms 以内であることをベンチマークで確認する。
