# 04. 区切り文字編集モードと RFC 4180 CSV

## 1. 概要

区切り文字編集モードは、テキストを「レコード × フィールド」として解釈し、**ファイル内容は変えずに**列を揃えて表示・編集するモードです。

- 区切り文字: カンマ、タブ、セミコロン、パイプ、スペース（連続を 1 つとみなすか選択可）、任意の文字列（複数文字も可、例 `||`）
- 固定長（列位置・バイト数指定）もこのモードの一形態として扱う（メインフレームデータ向け）
- **RFC 4180 モード**（CSV 既定）: 引用符付きフィールド、フィールド内の区切り文字・改行・`""` エスケープを正しく扱う
- **単純モード**（TSV 既定）: 引用符を解釈しない。改行 = レコード区切り

## 2. 解析仕様（`yy-delimited`）

### 2.1 方言（Dialect）設定

```rust
pub struct Dialect {
    pub delimiter: Delimiter,          // Char(',') | Str("||") | Whitespace { collapse: bool } | Fixed(Vec<ColumnSpec>)
    pub quote: Option<char>,           // Some('"') で RFC 4180 モード
    pub escape: QuoteEscape,           // Doubled ("") | Backslash (\") | Both
    pub record_terminator: Terminator, // Any(CRLF/LF/CR) | CrLfOnly | Byte(0x15) | FixedLength(n)
    pub header: HeaderMode,            // None | FirstRecord | Auto
    pub trim_spaces: bool,             // 引用符外の前後空白
    pub comment: Option<char>,         // '#' 行をコメントとして扱う（非 RFC）
    pub lenient: bool,                 // 不正な引用符を許容（既定 true、エラー箇所は警告表示）
}
```

### 2.2 RFC 4180 状態機械

フィールドの境界判定は次の 4 状態で行います（`memchr3` で区切り文字・引用符・改行を SIMD 探索しつつ遷移）。

```
            ┌───────── delimiter ─────────┐
            ▼                             │
   ┌─► FieldStart ── quote ──► InQuoted ──┼── quote ──► QuoteInQuoted
   │        │                     ▲       │                 │  │
   │        │ other               │       │   quote("")     │  │ delimiter / EOL
   │        ▼                     └───────┼─────────────────┘  │
   │    Unquoted ── delimiter ────────────┘                    │
   │        │                                                  │
   └─ EOL ──┴──────────────────────────────────────────────────┘
       （InQuoted 中の EOL はフィールド内改行としてレコード継続）
```

- `lenient` の場合、引用符で始まらないフィールド中の `"` は通常文字として扱い、閉じ引用符の後に区切り以外が来た場合はそのまま連結して警告マークを付ける（Excel 互換の挙動）。
- RFC 4180 が規定しない事項（空行、末尾の改行有無、レコードごとのフィールド数の不一致）はすべて許容し、フィールド数不一致のレコードは行頭にマークを表示。

## 3. 巨大ファイルでの課題と解決策

### 3.1 課題: 「行」と「レコード」が一致しない

RFC 4180 ではフィールド内に改行を含められるため、ファイルの任意位置から読み始めたとき、その位置が **引用符の中か外かは先頭から走査しないと分からない**。数 GB のファイルでスクロールバーを中央にドラッグしたとき、先頭から全走査していては間に合わない。

### 3.2 解決策: レコードインデックス（チェックポイント）

Indexer（02 章）と同じくバックグラウンドで CSV Scanner ジョブを走らせ、**ピースツリーの各ピース（≤1 MiB）の先頭における解析状態** を記録します。

```rust
pub struct Checkpoint {
    pub state: ScanState,     // FieldStart | InQuoted | QuoteInQuoted | Unquoted
    pub record_index: u64,    // このピース先頭時点のレコード番号
    pub field_index: u32,     // レコード内のフィールド番号
}

pub struct RecordIndex {
    generation: u64,                 // どのスナップショットに対する解析か
    checkpoints: PieceMap<Checkpoint>,  // ピース ID → Checkpoint（ツリーと同構造の永続マップ）
    scanned_until: u64,              // 解析済みバイト位置
    max_fields: u32,
}
```

- 任意位置の表示: 最寄りの上流チェックポイントから最大 1 MiB だけ走査すれば正しいレコード境界が分かる。
- レコード番号 ⇔ 位置の変換: 行番号と同じく、ピース単位の集約値（レコード数）で木を降りる。
- 走査速度は SIMD 探索で 1〜2 GB/s 程度を見込む。未解析範囲に飛んだ場合は「引用符外である」と仮定して暫定表示し（大半の CSV で正しい）、解析が追いついたら補正する。
- **ヒューリスティックによる並列走査**: 各チャンクを「引用符外から開始」「引用符内から開始」の 2 通りで並列に仮走査しておき、前のチャンクの終了状態が確定した時点で正しい方を採用する（投機的並列化）。これによりマルチコアで数 GB/s に到達可能。

### 3.3 編集時の差分再解析（収束判定）

1 文字の `"` の挿入・削除は、それ以降の **ファイル全体の引用符の内外を反転** させる可能性がある。そこで:

1. 編集されたピースの直前のチェックポイントから再走査を開始。
2. 各ピース境界で、新しい状態が **旧チェックポイントの状態と一致したら** 以降は変化なしとして打ち切る（レコード番号のずれは集約値の差分として一括補正）。
3. 一致しないまま続く場合（引用符の対応が崩れた）、バックグラウンドで再走査を継続し、UI には「引用符の対応が崩れています（行 N 付近）」と警告を表示。

通常のセル編集では 1 ピース以内で収束するため、編集コストは O(1 MiB) 程度に抑えられます。

## 4. 列揃え表示

### 4.1 列幅の決定

全レコードの全フィールド幅を正確に求めると巨大ファイルでは全走査が必要になるため、段階的に決めます。

1. **初期表示**: 先頭 1,000 レコード＋表示中のレコードから各列の幅を計算（東アジア文字幅を考慮した表示幅、`unicode-width` ＋ DirectWrite 計測）。
2. **スクロール時**: 新たに表示されたレコードがより広ければ列幅を拡張（縮めない＝ちらつき防止）。
3. **バックグラウンド全走査（任意）**: 「全体で列幅を最適化」コマンドで全走査して最大幅を確定。
4. 列幅の上限（既定 60 表示桁）を設け、超える部分は省略記号 `…` 表示。ユーザーは列境界ドラッグで幅を変更可能。

### 4.2 表示仕様

- 区切り文字は表示上は縦罫線に置き換え、実際の区切り文字は薄く表示（設定で切替）。
- フィールド内改行は `↵` グリフで 1 行に畳んで表示し、セル内編集時に展開する（または「複数行表示」設定で行の高さを可変にする）。
- 引用符は既定で非表示（値のみ表示）、「生テキスト表示」切替で原文を表示。
- 見出し行（ヘッダー）を固定表示、列番号・列名をルーラーに表示。
- 奇数/偶数レコードの背景色、列ごとの色分け、選択列のハイライト。
- 通常のテキストモードとワンキーで切替可能（ファイル内容は変わらない）。

### 4.3 レイアウトの実装

`yy-layout` は区切り文字モードでは各レコードを「セル列」として受け取り、セル i の x 座標 = Σ列幅[0..i] としてレイアウトします。カーソル位置はバッファ上のバイトオフセットで保持し、表示上の (レコード, フィールド, フィールド内オフセット) との相互変換を `yy-delimited` が提供します。

## 5. 編集操作

| 操作 | 実装 |
|------|------|
| セル内編集 | 通常の文字挿入。挿入文字に区切り文字・引用符・改行が含まれ、フィールドが引用符で囲まれていなければ、**自動で引用符を付与し `"` を `""` にエスケープ**（RFC 4180 モード） |
| Tab / Shift+Tab | 次/前のセルへ移動 |
| 列選択（矩形選択の列版） | ヘッダークリックで列全体を選択。コピーは値の列として出力 |
| セル範囲の矩形選択・同時入力 | Alt+ドラッグでセル範囲を選択し、全セルに同時入力（[09 章](09-multi-cursor-rectangle.md) 6） |
| 列の挿入・削除・入れ替え | 全レコードに対する一括編集。巨大ファイルでは全置換と同様にストリーミングで新しい一時ファイルを生成して 1 つの Undo 単位にする（05 章 4.2） |
| 並べ替え | 列を指定して安定ソート。メモリに収まらない場合は外部マージソート（一時ファイル） |
| フィルタ（抽出表示） | 条件（正規表現・数値比較）に一致するレコードのみ表示。表示用のレコード番号リストを作るだけで内容は変更しない |
| 列単位の検索・置換 | 検索範囲を特定列に限定（05 章） |
| 区切り文字の変換 | CSV ⇔ TSV 等。フィールド値を取り出し、新しい方言で必要な引用符付けを行って再出力 |
| 貼り付け | 表形式（TSV）のクリップボードデータを選択セル位置に展開 |

## 6. 方言の自動判別

`.csv` / `.tsv` 以外の拡張子や設定のないファイルでは、先頭 64 KB をサンプリングし、候補区切り文字（`,` `\t` `;` `|`）ごとに「各行のフィールド数の一致度」を評価して区切り文字・引用符有無・ヘッダー有無を推定します（Python `csv.Sniffer` と同様の手法）。推定結果はステータスバーに表示し、ワンクリックで区切り文字モードに入れるようにします。
