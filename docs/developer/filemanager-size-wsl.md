# yyfilemanagerのサイズ表示とWSL

操作説明は[フォルダサイズとWSL](../user/yyfilemanager-folders-wsl.md)、同梱説明は[filemanagerヘルプ](../../crates/yy-win/help/filemanager.md)を参照。

## 集計と一覧

`yy-files::folder_size`はローカル／共有フォルダの論理サイズを、ファイルの中身を読まずに集計する。`Fs::read_dir_with_errors`は取得できた項目とメタデータ未取得件数を返し、Localでは項目単位で中止を検査する。子フォルダの完了値と、直下の計算中フォルダ・起点の途中値を通知する。リンクはたどらず、ハードリンクは名前ごとに数える。読み取り失敗・加算オーバーフローを不完全な集計として保持する。

`fm/browse_sizes.rs`が独立したワーカーとチャンネルを持つ。一覧のロードとは別に開始し、結果を最大128件または100ms単位でまとめ、待ち行列は8バッチに制限する。送信待ちでも中止を検査する。画面の世代が変わった結果は無視し、完了済みの子フォルダ値は30秒のメモリ内キャッシュで再利用する。直下の行は常に保持し、任意の子孫キャッシュは5万件に制限する。移動時に中止し、終了したワーカーは回収する。サイズ順・割合順・絞り込み以外では全件を並べ替えず、表示部分だけ再描画する。

「合計サイズ」「占有率」は名前の次に配置し、サイズ・割合でソートできる。割合はフィルター前の起点合計を分母とする。NMLVCUSTOMDRAWの占有率サブアイテムをGDIで描画し、システムの選択色・文字色を使う。小さい画面では一覧領域を確保して先頭3カラムの幅を調整する。概算は`≈`、読み取り不完全は`≥`、未取得は計算中として表示し、未知を0バイトと断定しない。

再帰的なWindowsの変更通知を監視し、サイズ計算中の変更はdirtyフラグにまとめ、終了後に再読込する。通知により進行中の長い集計を繰り返し中止しない。変更通知を提供しない共有先はF5で更新する。WSLの再帰集計では仮想領域`/proc`・`/sys`・`/dev`・`/run`を除外するが、明示して開いた起点は除外しない。`/mnt`・Windowsドライブは対象に含む。

## WSL

`yy-files::wsl`はUNCの別名・verbatim UNC、Linuxの大文字小文字を保つパス、statのNUL区切りデータ、ID・モードを検証する。`fm/wsl.rs`は非表示の`wsl.exe`を使ってディストリビューションを取得し、PCとツリーへ追加する。実ファイル操作はWindowsのWSL UNCプロバイダーと既存のシェル操作を使う。選択パスのキーはディストリビューションを正規化し、Linux部分を小文字に変換しない。

`/mnt`もUNCのまま扱い、Windowsのドライブパスへ読み替えるフォールバックは実装しない。WSLプロバイダーがマウント配下の読み取りを拒否した場合は、未取得・不完全な集計として表示する。この範囲では合計・占有率が不正確になることを許容する。

`wsl_dialog.rs`はネイティブの所有者・グループ・rwx／特殊ビット・8進数・sudoの画面。読み取り／適用はワーカーで行い、GUIはタイマーで結果を確認する。テキストやチェックの再入通知は状態を借用せず処理する。閉じると中止フラグを立て、プロセスとパイプの処理を終了・回収する。読み取り専用の結果欄はスクロール可能で、長い診断文も確認できる。

操作はディストリビューションの既定ユーザーを読み取ってそのユーザーへ固定し、オーナー入力を実行ユーザーへ流用しない。sudoは`-S -k -p ''`で標準入力だけからパスワードを渡す。動的なパス・名前・モードは固定スクリプトの位置引数とし、シェルのコードへ連結しない。数値IDはGNU chownの`+ID`表記で名前との曖昧さを避ける。

変更時に対象をFDで開き、取得済みのデバイス・inodeと照合した後、保持した`/proc/self/fd/3`へchown/chmodを実行する。リンク・特殊ファイルは拒否し、名前を差し替えても別のinodeへ権限を適用しない。変更不要のchownは呼ばず、モードだけの変更でファイルケーパビリティを不必要に失わせない。chown後は選択されたモードを復元し、実際のUID/GID/モードを読み直す。操作全体はトランザクションではないため、失敗後は再読込で状態を確認する。

資格情報は既存のWindowsCredentialsを使い、`yyeditor/wsl-sudo/<ディストリビューション>/<ユーザー>`に相当する長さ付きキーで分離する。保存は適用成功後。認証・操作に失敗した保存値は削除し、GUIに再入力を案内する。秘密は引数・設定・ログ・一時ファイルへ出さず、プロセス出力はメモリ内で64KiBに制限し、生のstderrを診断へコピーしない。Windows側30秒、WSL側timeout 20秒＋kill-after 2秒で処理を制限する。

## 検証

ルートのfmt・全ターゲットlocked ClippyをWindows/Linuxで行い、`cargo test -p yy-files --locked`と`cargo test -p yy-win --lib --locked fm:: -- --test-threads=1`を実行する。サイズのUI試験は専用の設定・データフォルダを作り、モデルの完了・件数・サイズを期限付きで待つ。640/1100pxの配置、バーの実GDI画素、ソート、履歴、古い世代の排除、子孫変更後の更新を確認する。

実WSLと資格情報マネージャーは環境を必要とする明示的な試験として、`cargo test -p yy-win --lib --locked fm::wsl::tests::real_ -- --ignored --test-threads=1 --nocapture`を使う。一時フォルダ・専用キーだけを作り、終了時に削除する。利用者のパスワードやファイルを試験へ流用しない。
