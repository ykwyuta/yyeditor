# yyfilemanagerの容量整理とアプリ起動

利用方法は[容量整理](../user/yyfilemanager-cleanup.md)を参照。

## 容量整理

`yy-files/src/cleanup.rs` が読み取り専用の探索、集計、CSV出力とエンジン照会のモデルを提供する。追加分類は `cleanup/expanded.rs` に置く。`Ecosystem` は18分類、`Location` はフォルダー・ファイル・コンテナーイメージ・ビルドキャッシュを区別する。分類追加時は `yy-win/src/fm/cleanup.rs` の選択肢・値の対応と、一覧・概要の件数も更新する。

探索には利用者の最小容量・成果物の経過日数・分類を適用する。一般のデータセット・モデルは100 MiB、未分類のファイルは1 GiBの下限も持つ。通常のフォルダー再帰ではバージョン管理、隔離領域、コンテナー内部ストレージを除外し、リンクをたどらない。共通フォルダーとして明示した既知のDocker/Podman管理ルートは全体を読み取り集計し、内部レイヤーを個々の不要候補にはしない。重複・入れ子は一度だけ数え、読み取り不能なら不完全な集計として表示する。

VM・バックアップ・DB・メディア等は所有アプリでの整理・圧縮を案内する管理データで、不要性や実回収量は判定しない。CSVには理由と助言を出力する。ファイル候補を開く操作は親フォルダーを表示し、そのファイルを実行・マウントしない。通常の削除機能や圧縮操作は探索から呼び出さない。

`yy-win/src/fm/cleanup.rs` は既存のジョブ基盤で探索を実行し、進捗と完了結果をUIへ渡す。Docker/PodmanのCLI照会は読み取りコマンドのみ、時間・出力上限付き。エンジンの失敗は通常のフォルダー探索を失敗させず、警告として残す。

## アプリ起動

`yy-win/src/fm/launch.rs` が通常のファイル表示とアーカイブ展開後の起動を担当する。EXE/COMは正規化した絶対パスのファイルを `FILE_SHARE_READ` で開いて書き換え・削除を拒否し、そのハンドルを `WinVerifyTrust` へ渡す。署名検査はオフラインキャッシュを使用し、状態を閉じる。非成功の結果では正確なパス・検査結果を示す既定Noの確認を要求する。

承認後または署名検証成功後はファイルハンドルを保持して `Command` でプロセスを作成する。引数をシェル文字列に連結しない。管理者権限要求（740）は `ShellExecuteExW` の `runas` でOSのUACへ進む。通常ファイルは `open` を使い、失敗を表示する。OSのアプリ制御や信頼ストア、Zone.Identifierは変更しない。

## 検証

ルートの書式・全ターゲットClippyに加え、`cargo test -p yy-files --locked`、`cargo test -p yy-win --lib --locked fm::cleanup::tests -- --test-threads=1`、`cargo test -p yy-win --lib --locked fm::launch::tests -- --test-threads=1` を実行する。Linuxのファイル探索も検査する。実Docker試験は利用可能なエンジンを必要とし、既定では実行しない。

起動試験は一時フォルダーへ専用の未署名アプリを生成し、拒否・承認・承認中の差し替え拒否を確認する。起動したプロセスは終了を待って回収する。利用者の実行ファイルを試験用に起動しない。
