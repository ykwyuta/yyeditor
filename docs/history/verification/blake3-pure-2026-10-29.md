# BLAKE3のPure Rust化検証（2026-10-29）

変更前コミット: `7ec737683560f5e36b696d9108aade86dacc58ae`。BLAKE3の版は1.8.7のまま、ルートの共有依存とyymergeの直接依存で`features = ["pure"]`を指定した。

yydbmanagerは共有yy-draw経由でこの設定を引き継ぐ。YY3Designerの解決済み依存にはBLAKE3がなく、追加していない。旧`yy-files/blake3-pure`フラグは互換用に保持する。LinuxからWindows UIを型検査するCI・開発手順では、このフラグを付けずに通常の依存設定を使うようにした。

## ハッシュと保存形式

Windows x64 / Rust 1.99.0で、独立した検証用パッケージから同じ版の既定バックエンドとpureバックエンドを別々にビルドして照合した。製品全体の依存グラフによる機能統合で両方がpureにならないように分離した。

- 空文字列と`abc`の既知ハッシュ値を確認。
- 0、1、2、3、63、64、65、127、128、129、1023、1024、1025、2047、2048、2049、16384、1048576、1048593バイトの19入力で一致。入力は`i % 251`で生成。
- 通常ハッシュ、鍵付きハッシュ、鍵導出、64バイトのXOF出力を照合。
- 1、63、64、1023、4096バイトずつの分割入力と一括入力が一致。
- Linux x64 / Rust 1.99.0のpureバックエンドも、Windowsの上記出力とすべて一致。
- yy-drawの旧形式ファイル、任意チャンク、素材パックの不変性を含む既存結合試験がWindows/Linuxで成功。

## Cコンパイラーなしのビルド

Windows/Linuxの検証パッケージで、`CC`、`CXX`、`AR`を存在しないパスにしてpureのビルドと実行が成功した。Windowsのpure出力には`blake3_sse2_rust`、`blake3_sse41_rust`、`blake3_avx2_rust`が設定され、BLAKE3のネイティブオブジェクト・静的ライブラリの生成とリンク指定はなかった。比較用の既定ビルドにはFFI実装の設定とアセンブリのオブジェクト・静的ライブラリがあった。

`cc`は上流クレートのRust製ビルド依存に残る。上流build.rsにはpureでもCコンパイラーの対応フラグを調べる処理があり、コンパイラーが存在する環境では検出用の小さいCファイルをコンパイルする場合がある。これはハッシュ処理のC/アセンブリ実装をリンクすることとは異なり、コンパイラーがなければpureビルド自体は成功する。Rustのリンカー・OS ABIを不要にしたわけではない。

## 回帰検証

Windowsで、ルート・yymerge・yydbmanagerの各ワークスペースの`cargo fmt --all -- --check`と`cargo clippy --workspace --all-targets --locked -- -D warnings`が成功。独立ワークスペースには`--manifest-path`を付けた。

- ルートの影響する部品: yy-files、yy-draw、yytoolboxのライブラリ試験99件、yy-drawの追加結合試験39件、yytoolboxの結合試験7件が成功。
- yymerge: 独立ワークスペースの通常試験133件が成功。
- yydbmanager: 独立ワークスペースの通常試験61件が成功。外部5DBへの接続を必要とする既定でignoredの試験は今回の対象外。

Linuxは既存のRust 1.99.0検証イメージを使い、ソース・取得済みCargo registry/gitを読み取り専用にし、ビルド先をDockerボリュームに分離した。ルート全対象Clippyと上記の影響する部品の試験が成功。yymergeの全対象Clippy・通常試験は`--no-default-features`付きで実行した。初回の環境にはSFTPサーバーがなく実転送試験が早期returnすることを確認したため、openssh-sftp-serverを一時コンテナーへ導入し、`YYMERGE_REQUIRE_SFTP=1`で対象試験を明示実行して成功を確認した。

yydbmanagerもLinuxの全対象Clippy・通常試験51件が成功。Linuxのルートのライブラリ試験は100件が成功した。現在の変更は未プッシュで、この変更に対するCIは未実行。

## 性能比較

Windows 11 / Ryzen 7 5700X / Rust 1.99.0、通常のrelease最適化で測定した。ビルド終了後、メモリ上の64 MiBを16回処理する標本を、既定版とpure版で順序を交互にして各9回採取した。単一スレッド・ディスクI/Oなし。中央値は既定版4,725.6 MiB/s、pure版3,800.9 MiB/sで、pure版のスループットは19.6%低下した。アプリ全体の処理時間やCIの短縮率を示す数値ではない。
