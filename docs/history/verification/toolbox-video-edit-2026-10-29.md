# yytoolbox 簡易動画編集の検証

2026-10-29、基点 `2b28a0266d8778d2bc4e40e5520dafcc85f289b2` に対する未コミットの変更。前段の録画操作バー・容量整理・起動承認の変更を保持した状態で追加した。現行仕様は[同梱ヘルプ](../../../apps/yytoolbox/help/help.md)と[開発者向け文書](../../developer/yytoolbox.md)を参照。

## 実装

23番目のツールとして動画編集を追加。開始-終了を秒または時刻で指定し、複数範囲のクリップ（残す）とカット（取り除く）を行う。重複範囲は統合し、元の時間順に出力する。映像フレームの端の表示時間とPCM音声のサンプル境界を調整して範囲を処理する。元動画の先頭映像・音声のみをWindows Media Foundationでデコードし、H.264/AAC MP4へ再エンコードする。外部CLI・FFmpeg依存は追加していない。

元動画・既存ファイルは上書きせず、一時出力を確定後に `persist_noclobber` で保存する。中止・失敗では出力を破棄。保存先選択は実行時の一度だけで、結果保存ボタンは表示しない。正方画素・回転情報なし・偶数寸法・3200万画素以下・240fps以下という初期対応範囲を明示する。

## 試験

- Windows（Rust 1.99.0）でルート全ターゲットのlocked Clippy（warnings拒否）に成功。
- 実Media Foundationの試験2件で、3秒・3シーンの色分けした動画と440/880/1320Hzの音声を生成。1秒のクリップ、中央1秒のカット、複数区間の連結を再デコードし、フレームごとのシーン順序・上下方向・時刻の連続性・長さ・音声の周波数を検査。フレーム境界に一致しない100msのクリップも、元の10fpsに従う1フレーム・連続時刻・正しい長さで保存されることを確認。無音声動画、開始前中止、範囲超過、元動画・既存出力の保護、一時ファイルの片付けも検査。
- 初回の実コーデック試験では、正規化した `\\?\` パスをMFのURL resolverがネットワークパスとして解釈し、0x80070040/35で失敗した。同一ファイルのDOS/UNC表記を渡す修正後、日本語・空白付きパスを含めて成功。
- 200%表示検査で時間範囲ラベルと操作名の欠けを検出。ラベル・操作名を短縮し、範囲の説明は本文へ残して再検証した。
- Windowsのライブラリ16件・バイナリー8件の計24件が成功（実デバイス収録6件は既定どおり未実行）。全体のUI回帰試験は271.86秒で成功。検査には全23ツールの倍率75/100/125/150/200%、96/120/144/192 DPI、480/640/1100論理px幅の配置検査を含む。録画のEsc廃止の回帰も維持する。
- Linuxの現行stable（Rust 1.99.1）でルートの書式検査・全ターゲットClippyと、yytoolboxコア16件・結合7件に成功。Windows専用のコーデック/UIはLinuxで検証済みとは扱わない。

ログ: `target/video-edit-native-tests.log`、`target/video-edit-regression-windows.log`、`target/video-edit-clippy-windows.log`、`target/video-edit-linux.log`。

## 範囲と実行環境

実デスクトップ・利用者の動画・マイクはこの編集試験で収録していない。回転メタデータ・追加トラック・字幕・途中の形式変更は初期実装の対象外。不可逆再エンコードの画質評価や長時間の性能測定、すべてのOSコーデックの検証は行っていない。

Windowsで通常の `cargo test -p yytoolbox` は、起動中の `target/debug/yytoolbox.exe` の置換に失敗した。利用者のアプリは終了せず、Windowsは `--lib --bin yytoolbox` に限定し、通常の結合試験はLinuxで検証した。通常EXE自体の新しいリンク生成物は `target/debug/deps/yytoolbox.exe` にあり、確認用の `target/feature-preview/yytoolbox.exe` へ配置した。コミット・プッシュ・リリースは未実施。
