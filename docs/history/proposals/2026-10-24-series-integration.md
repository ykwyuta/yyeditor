# YYシリーズ連携の追加候補（2026-10-24）

## 今回の範囲

yydbmanager・yymergeの検証を共通CIへ統合し、共通Windows成果物に同梱する。
Cargoワークスペースは分離したまま、DuckDBのVS 2022固定と各アプリの既存試験を維持する。
yyeditorのタブ比較・Git差分はyymergeへ渡す。未保存の内容を比較できるよう、
不変スナップショットをUTF-8で一時出力し、元の名前・版を別引数で表示する。

## 追加候補（提案・未実装）

| 優先度 | 連携 | 利用場面と実装方針 | 注意点 |
| --- | --- | --- | --- |
| 高 | yyfilemanager → yymerge | 2つの選択ファイル、左右ペインのファイル・フォルダーを右クリックから比較。既存のyyeditor起動と同じく隣接exeを安全な引数で起動する | フォルダー同期は既存のyyfilemanager機能と区別し、比較起動時に変更・削除しない |
| 高 | yysftp → yymerge | ローカル対リモート、または2つのリモートファイルを比較。既存のyyeditor向け一時ダウンロードを共用する | 秘密情報は渡さず、転送完了後に起動。原本へのアップロードは別の明示操作。一時データの寿命・削除を管理 |
| 中 | yydbmanager → yysheet | SQL結果を表計算で分析。CSV/TSV等の既存出力を通じて開く | NULLと空文字、64bit整数、小数、日時の意味を保持する形式・付帯情報を定義してから直接連携 |
| 中 | yydbmanager → yymerge | SQLテキスト・DDL・テーブル設計書の変更前後を比較するメニュー | 実行結果の行順が不定ならそのまま比較しない。比較のためのDB更新・SQL実行はしない |
| 中 | yydbmanager → yydraw | 既存の「図をyydrawで保存」を、保存後にyydrawで開く操作につなぐ | 汎用図形としての編集とERモデルの意味を区別し、ERへの完全な往復変換を約束しない |
| 低 | yyeditor → yydbmanager | SQLタブをyydbmanagerの新規クエリとして開く | 接続・資格情報をエディタから渡さず、yydbmanager側で選択。自動実行しない |

まずファイル管理・SFTPからの比較を進めると、今回同梱するyymergeの再利用効果が高い。
共通の起動・一時ファイル管理を部品化する場合も、認証情報と保存先の所有権を各アプリに残す。
コマンドラインへSQL本文や資格情報を直接載せず、必要なデータを適切な権限の一時ファイルで渡す。

現行仕様は[内部構成](../../developer/architecture.md)、操作は[yyeditorヘルプ](../../../crates/yy-win/help/help.md)を参照。
