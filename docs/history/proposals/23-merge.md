# yymerge：高機能な差分比較・マージツールの提案

> 検討・作業記録です。現在の操作・内部仕様は[文書案内](../../README.md)を参照してください。

作成日：2026-10-21。状態：提案（この文書の作成時点では未実装）。

## 1. 目的と設計方針

独立アプリ **yymerge** を追加する。WinMerge、Beyond Compare、Araxis Mergeを機能と操作性の目標とし、ソースコード、設定、業務データ、フォルダーを比較し、変更の確認から競合解決、成果物の保存まで扱う。単純な左右の差分表示にとどめず、祖先を使う3方向マージ、フォルダー全体の比較・統合、用途別の比較規則、バッチ処理を製品の中核にする。

- WindowsのネイティブGUIと、GUIを必要としないCLIを用意する。比較・マージの判定エンジンは共通にする。
- yydbmanagerと同じく、ルートとは別のCargoワークスペース・ロックファイル・CI・配布成果物を持つ。共通クレートは既存リポジトリーを参照する。
- フォント、編集、IME、描画、文字コード、保存、検索、ファイル操作、Markdownヘルプ、アイコン生成の既存資産を流用する。
- 表示上の整列、比較規則による同値、元バイトの一致、自動マージ可能性を区別する。近似比較を根拠に自動で上書きしない。
- 高機能化は段階的に進める。各段階でGUI・CLI・ヘルプ・実ファイルによる検証をそろえ、未対応を対応済みとは表示しない。

### 1.1 参照製品との関係

公式資料で確認した機能のうち、yymergeで重視する領域を整理する。製品ごとの版・エディションの違いを含む完全な互換性表ではない。

| 参照先 | 確認した領域 | yymergeの方針 |
|---|---|---|
| [WinMerge公式](https://winmerge.org/?lang=en) | ファイル・フォルダーの2／3方向比較、行内差分、移動行、画像、CSV／TSV、パッチ | コード比較から業務データ比較まで一つの比較セッションで扱う |
| [Beyond Compare公式](https://www.scootersoftware.com/) | ファイル・フォルダー・表・画像の比較、統合、同期、比較規則、コマンドラインによる自動化 | 比較対象に合う表示と、確認可能な同期計画、繰り返し使える規則を重視する |
| [Araxis Merge公式](https://www.araxis.com/merge/index.en) | 2／3方向マージ、フォルダー同期、画像・バイナリー、文書の抽出テキスト比較 | 祖先と結果が明確な競合解決、フォルダーからファイルへの移動、レビュー出力を重視する |

## 3. GUIと基本操作

### 3.1 主画面

セッションをタブで管理する。開始画面から「ファイル比較」「3方向マージ」「フォルダー比較」「保存した比較」を選べる。入力先は役割のラベル付きで表示し、ドラッグ＆ドロップ、ファイル／フォルダー選択、最近使った組み合わせを利用できる。

主要ツールバーは、開く、再比較、前／次の差分、前／次の競合、選択の取り込み、保存に絞る。比較規則、レポート、同期、文字コード、詳細設定はメニューへ収める。単独の曖昧な「更新」ではなく「比較を再実行」など対象を明示する。

- 2方向は左右ペインと統合表示を切り替える。行番号・変更記号・差分ミニマップ・対応線を備える。
- 3方向は祖先を折り畳み可能にし、左右の変更元と独立した結果エディターを表示する。左右両方からの変更と未解決を区別する。
- フォルダーはツリーと一覧を併用し、ファイルを開いても一覧の選択・フィルター・スクロール位置を保持する。
- ステータスには入力の役割、比較規則、文字コード、処理中／完了／途中、差分・競合・未確認件数を表示する。

同期スクロールは対応する論理範囲に基づき、挿入された空行を実データに混ぜない。折り返し・フォント・DPIが異なっても対応を維持し、同期解除、任意位置での再同期、手動の整列アンカーを利用できる。キーボードだけで差分・ペイン・取り込み・競合解決を操作できるようにする。

### 3.2 編集・取り込み

左右の原本は既定で読み取り専用、結果を編集可能にする。2方向の相互編集は明示的に有効化する。選択行、差分ブロック、ファイル全体の採用を区別し、操作名に「左を結果へ」「右を結果へ」など方向を表示する。

取り込み、手編集、競合解決、規則の変更はUndo／Redoを扱う。選択した差分は行番号だけで追跡せず、入力スナップショットと範囲・文脈に結び付ける。再計算中に古い差分へ操作が入った場合は保留し、新しい版へ無条件に適用しない。

日本語IME、検索・置換、矩形選択、コピー＆ペースト、構文色分け、不可視文字表示を共通エディターから利用する。差分は色だけに頼らず、記号と説明でも識別する。ツールチップは操作の方向と対象、比較規則の影響を説明する。

## 4. 比較エンジン

### 4.1 判定モデル

次の状態を独立して持つ。

1. **元バイトが一致**：文字コード・BOM・改行を含めて一致する。
2. **規則適用後に同値**：空白無視などの指定により同値だが、元バイトは異なる。
3. **差分あり**：その規則でも異なることを確認した。
4. **未比較／判定不能**：読み取り失敗、取消、上限、未対応形式などで判断を完了していない。

日時・サイズだけによる高速判定は「メタデータ上の一致」と表示し、内容一致へ昇格させない。CLIの厳密な一致判定と、自動マージ・削除・同期の根拠には、必要な内容確認を行う。ハッシュは候補の絞り込みに用い、厳密モードでは一致候補をバイトでも確認できるようにする。

### 4.2 アルゴリズムと精度

行単位の共通アンカーとMyers系の差分を基本とし、Patience／Histogram系のアンカー選択を比較プロファイルとして検討する。行内は単語・書記素単位で精細化する。移動行・類似ブロックは位置の対応候補として扱い、編集の意図を自動で断定しない。

入力の先頭・末尾の一致を除き、行の指紋と原文確認で範囲を分割する。最悪計算量、巨大な1行、同一行の大量反復、全面変更、ハッシュ衝突をテストする。予算を超えたら部分結果・理由・未処理範囲を示す。完全な差分出力を要求されたCLIは未完了を終了コード2で返し、近似結果を完成したパッチや自動マージに使わない。

`--brief`のように一致／不一致だけを求めるモードでは、最初の不一致で「異なる」と確定できる。これは差分全体を計算できたこととは区別する。

### 4.3 比較規則

空白、末尾空白、大文字小文字、改行、BOM、空行、指定行、正規表現による置換、数値許容差、時刻等の揺れの無視を用意する。既定では無視を適用しない。ファイル種別ごとにプロファイルを保存し、GUIとCLIで同じものを指定できる。

Unicode正規化や大文字小文字変換も明示設定とし、原文と比較キーを分離する。無視対象だけが違う場合も、その件数と原文を確認できる。正規化済み文字列を原本へ書き戻さず、取り込む内容・出力の文字コードと改行は別に決める。

### 4.4 3方向マージの判定

BASEは共通祖先、LEFT／RIGHTはそこから変更された入力、RESULTは出力とする。位置だけを並べる3ファイル比較と、祖先を用いる自動マージは別モードにする。

| BASEから見た変更 | 既定の処理 |
|---|---|
| 片側だけの変更 | その変更を自動採用できる |
| 両側で同じ変更 | 一度だけ採用できる |
| 独立した範囲の変更 | 範囲と挿入位置の干渉がない場合に統合できる |
| 同じ位置への異なる挿入、重なる変更 | 競合として残す |
| 削除と変更、異なるリネーム、移動と重なる編集 | 競合、または確認が必要な候補として残す |
| 祖先なし | 共通祖先があると仮定しない。両側一致等の確定可能な場合以外は人が選ぶ |

「両方を採用」は並び順も選べるようにし、順序が不明な変更を勝手に連結しない。比較で無視した範囲も、マージ時に重要な変更を落とさないよう原文で検証する。テキストが競合なく統合できても、コードや業務上の意味が正しいことまでは保証しない。

競合は安定したID、元範囲、選択履歴、解決状態を持つ。画面上で競合記号が見つからないことだけで解決済みと判定しない。GUIの「解決を確定」は未解決0件かつ出力の保存成功を必要とする。

## 5. フォルダー比較・統合・同期

2方向と、祖先フォルダーを含む3方向に対応する。相対パス、種別、サイズ、更新日時、比較状態、内容差分、操作予定を表示する。拡張子、パス、glob／正規表現、サイズ、同一・片側・競合等で絞り込める。

大文字小文字の違い、Unicodeの異なる表現、長いパス、UNC、隠しファイル、アクセス拒否、途中で削除されたファイルを区別する。読めなかったファイルを「同一」「片側に存在しない」にしない。シンボリックリンク・ジャンクションは既定で追跡せず、リンク自体を比較する。追跡を有効にしても循環を検知し、走査範囲を表示する。

リネーム・移動は内容や類似度から候補を推薦し、曖昧な同一内容ファイルを勝手に1対1対応させない。祖先がある場合は変更／削除／追加と結び付けて競合判定する。

同期は「比較 → 操作計画 → 実行」の3段階にする。コピー、置換、削除、リネームの方向・対象・根拠を計画で確認し、実行直前に入力と出力の同一性を再検証する。計画作成後に変わったファイルへ古い操作を適用しない。削除を伴うミラーと、追加・更新だけの同期を明確に分ける。

複数ファイルの同期をファイルシステム全体の原子的操作とは呼ばない。ファイル単位で一時出力・置換を行い、実行記録と再開可能な状態を残す。中断後の再開は完了済みを再検証し、削除や置換を無条件に繰り返さない。

## 6. 用途別の比較と統合

| 種別 | 比較・表示 | マージ方針・制限 |
|---|---|---|
| CSV／TSV／任意区切り | RFC 4180の引用符・項目内改行を保持。行番号または単一／複合キーで対応付け、列移動・型・セル差分を表示 | 重複キーを無理に一意化しない。NULL・空文字・欠落列を区別し、原形式へ出力する |
| COBOL系固定長 | コピー句、文字コード、レコード長、複数レイアウトを選択。桁・項目・レコード単位の比較 | レコード長とレイアウトを確定してから項目マージする。未判定レコードは原バイト差分で残す |
| JSON／XML／YAML | パス・ノード単位の追加削除、対応する原文範囲の差分 | 配列順序、重複キー、XML名前空間、コメント・書式の扱いを指定する。XML外部実体は解決しない |
| バイナリー | オフセット、16進、文字表現、差分ブロック、挿入によるずれの表示 | 選択範囲の取り込みを主体とし、任意バイナリーの意味的自動マージは行わない |
| 画像 | 元画像、差分、重ね合わせ、点滅、ズーム、位置合わせ、閾値を表示 | サイズ・色空間・アルファ等の規則を示す。任意画像の自動合成は別の明示操作にする |
| ZIP等のアーカイブ | 最初はZIP内を仮想フォルダーとして読み取り比較 | 展開量・件数・深さを制限する。原アーカイブを直接更新せず、書き出し対応は別段階とする |
| SFTP／共有フォルダー | 接続先と資格情報の既存基盤、必要範囲の取得、取消・再接続 | 同期は接続先の置換能力を確認。ローカルと同じ原子性を仮定しない |
| Office／PDF | 既存抽出器によるテキスト比較。Excel等の表比較は対応形式を個別に判定 | 抽出できない画像・レイアウト・書式は欠測と表示。元のOffice／PDFへマージして戻す機能は初期拡張に含めない |

構造化比較は「解析できた内容」「原文上の差分」「保存できる範囲」を分ける。重複キーや未対応構文があるファイルで、解析時に落とした情報を消して再保存しない。形式ごとに原文を維持する編集経路を整備するまでは、読み取り比較として提供する。

画像の画素数、展開後の文書量、正規表現の実行量、抽出器の時間・メモリーにも上限を設ける。追加変換器は別プロセス・明示指定で実行し、比較対象に含まれるコマンドを自動実行しない。

## 7. CLI

### 7.1 実行ファイルと基本契約

`yymerge.exe`はコンソール用、`yymergew.exe`はWindows GUI用とする。GUIショートカットは後者を起動し、CLIの標準出力・標準エラー・終了コードは前者が担当する。同一アプリパッケージ内の2エントリーポイントとし、`yymerge gui`からGUIを起動できるようにする。

CLIの比較・マージはヘッドレスで動作し、Win32 UIやWebView2をロードしない構成にする。Windows版を製品の主対象とし、OS非依存のコアとCLIはLinux CIでも試験する。

以下は採用予定のインターフェース例であり、現時点では実行できない。

```powershell
yymerge diff left.txt right.txt
yymerge diff left.txt right.txt --format unified --report changes.patch
yymerge diff left.csv right.csv --profile rules.toml --format json --report result.json
yymerge merge --base base.txt --left ours.txt --right theirs.txt --output merged.txt
yymerge folders before after --recursive --format html --report folders.html
yymerge sync plan --left before --right after --mode update-right --output sync-plan.json
yymerge sync apply sync-plan.json --execute
yymerge gui --left left.txt --right right.txt --wait
yymerge gui --base base.txt --left ours.txt --right theirs.txt --output merged.txt --wait
yymerge --help
yymerge help merge
```

ファイル名に空白・日本語・先頭のハイフンがある場合の引用と`--`を扱う。パスと標準入力は明示的に区別し、`--stdin-left`と入力名の指定等を用意する。CLIは暗黙にGUIや入力プロンプトを開かず、必要情報がなければ使用法エラーを返す。

`diff`は既定で人向け差分をstdoutへ出力する。`--report`指定時は指定先へ出力し、ログ・進捗はstderrへ分離する。JSONはUTF-8とし、成功・差分・競合・エラー・中断・未完了、適用規則、入力の識別情報を版付きスキーマで表す。機密値を含む本文の有無は出力設定で選べる。

### 7.2 終了コードと書き込み

| コード | 比較 | マージ／同期 |
|---|---|---|
| 0 | 指定規則で同値、かつ要求された比較が完了 | マージ結果の保存成功・未解決なし、または同期の要求操作が全件完了 |
| 1 | 差分あり | 未解決の競合あり。既定では結果ファイルを置き換えない |
| 2 | I/O・形式・予算超過・不完全な走査等 | 処理失敗または完了を確認できない |
| 64 | 引数・規則の指定が不正 | 同左 |
| 130 | 利用者による取消・割り込み | 同左 |

`--format json`では0と1の理由を`byte_equal`／`equivalent`／`different`等でも区別する。正常な取消や未完了を差分なしと返さない。`gui`の待機なしの0は起動成功だけを表し、比較・マージの結果ではない。

入力は読み取り専用が既定。CLIは出力先を必須にし、既存ファイルへの上書きと入力ファイルを出力にする操作は明示オプションを必要とする。既存出力の置換は、入力の再確認・変換検証・一時ファイルの書き込みが終わってから行う。失敗・取消時は既存出力を残す。

競合が残った場合にマーカー付きファイルを作る機能は、`--write-conflicts`等の明示指定に限定し、終了コード1を保つ。これを自動マージ成功とは扱わない。同期は計画作成だけではコピー・削除せず、`sync apply ... --execute`で実行する。計画の入力指紋・ルート・規則が変わっていれば作り直す。

### 7.3 Git連携

専用の`git-tool diff`／`git-tool merge`アダプターを提供する。Gitから渡されるBASE／LOCAL／REMOTE／MERGEDを明示的に対応させ、GUIは必ず終了を待つ。祖先や片側のファイルが存在しない競合と、空ファイルを区別する。アクセス失敗を「祖先なし」に変換しない。

設定例と登録／解除の手順をヘルプに記載する。アプリ起動だけでユーザーのGit設定を書き換えない。マージアダプターはRESULTが保存され、未解決0件と確認できた場合だけ0を返す。Git側のstage・commit・pushは行わない。

参照：[git-difftool](https://git-scm.com/docs/git-difftool)、[git-mergetool](https://git-scm.com/docs/git-mergetool)。既存`yy-git`はGit実行ファイルを呼ぶ方式なので、リポジトリー連携には導入済みGitを使用する。通常のファイル比較・マージにはGitを不要とする。

## 8. 保存・セッション・出力

入力ファイルの長さ・識別情報・必要なハッシュを記録し、外部変更時は再読込・別名保存・再比較を選べるようにする。保存は`yy-io`の既存処理を基盤にし、符号化不能文字、BOM、混在改行、終端改行の扱いを保存前に確認できるようにする。

比較定義と作業状態を分ける。比較定義は版付きの設定としてパス、役割、比較規則、除外、表示モードを保存する。手動保存する作業セッションは未解決ID、採用履歴、結果の編集差分、入力指紋を保持し、大きな編集データは付属の状態ファイルに分離する。GB単位の入力全文を毎回JSONへ複製しない。

再開時に元入力が変わっていたら、保存した行番号や判断をそのまま適用しない。原本から再比較して対応を確認する。Undo履歴が復元できるか、作業結果だけの復元かを仕様で区別する。セッション保存を「マージ解決完了」とは扱わない。

レビュー用にHTML、JSON、unified diffを提供する。HTMLは本文をエスケープし、コードをスクリプトとして実行しない。レポートには比較規則、除外、未処理・エラー件数を含める。パッチは生テキストの変更用であり、空白無視等の表示結果からそのまま適用可能なパッチを作らない。パッチ適用は対象と文脈の検証、dry-run、失敗時の原本保持を行う。

unified diffは、指定した出力文字コード・改行で対象へ適用できる場合に生成する。入力間の文字コード変換やバイナリー変更を含む場合は通常のテキストパッチで完全再現できると扱わず、変換を含む結果ファイル、対応する別形式、または未対応の診断を返す。比較規則と出力形式の都合で原バイトを失わないようにする。

## 10. 構成とデータモデル

```text
apps/yymerge/
  Cargo.toml / Cargo.lock        # 独立ワークスペース
  app/                          # package: yymerge
    src/bin/yymerge.rs           # コンソール用
    src/bin/yymergew.rs          # Windows GUI用
    res/yymerge.ico / yymerge.manifest
  crates/
    yy-merge-core/              # 入力、規則、差分、3方向マージ、フォルダー計画
    yy-merge-cli/               # 引数、終了コード、JSON／パッチ／レポート
    yy-merge-ui/                # Win32シェル、共通エディター、格子と比較画面
  help/help.md                 # 実行ファイルへ埋め込む原稿
  tests/fixtures/              # 正常・競合・巨大行・多文字コードの入力と期待値
demo/yymerge/                  # 利用者向け比較例・説明・期待結果
.github/workflows/yymerge.yml
```

ルート`Cargo.toml`の`exclude`に`apps/yymerge`を追加する。CLIとコアはOS非依存、UIはWindowsのみとする。GUI依存はfeatureとtargetで分け、CLIだけを`--no-default-features --bin yymerge`でビルドできるようにする。GUI側は共通リソース埋め込みを利用する。

主要モデルは`InputSnapshot`、`ComparisonRules`、`DiffHunk`、`AlignmentMap`、`MergeConflict`、`MergeDecision`、`FolderPlan`、`Diagnostic`とする。生バイトのオフセット、デコード後の位置、表示位置を同じ整数として混ぜない。範囲は64bitで扱い、UIへの変換時にオーバーフローを検査する。

ワーカーは不変スナップショットを処理し、ジョブ世代付きで結果を返す。編集や規則変更後に古い計算が完了しても現在の画面を置き換えない。GUIとCLIが別々の競合判定・規則実装を持たない。

## 11. ヘルプ・フォント・アイコン

### 11.1 ヘルプ

yydbmanagerと同じ方式を使う。Markdown原稿を`include_str!`で埋め込み、[`yy-ui-win::help`](../../../crates/yy-ui-win/src/help.rs)と[`yy-preview`](../../../crates/yy-preview/src/help.rs)で表示する。F1、ヘルプメニュー、目次・見出しへの移動、コピー、オフライン表示、WebView2が利用できない場合のテキスト表示を共通化する。

最低限、開始手順、2方向と3方向の違い、入力の役割、競合解決、比較規則、文字コード、フォルダー同期、CLI・終了コード、Git登録／解除、セッション、対応形式と上限、エラーの対処を掲載する。CLI例・終了コード・設定スキーマはCLIの定義や試験例と照合する。機能追加時はヘルプとfixtureを同時に更新する。

リリースにはREADMEとライセンスも同梱する。GUIを開かなくても`--help`とサブコマンド別ヘルプで使用法を確認できるようにする。

### 11.2 フォントとアイコン

フォントは[`yy-ui-win::font`](../../../crates/yy-ui-win/src/font.rs)の同梱UDEV Gothicを使い、yyシリーズと同じ文字計測を利用する。日本語・全角半角・タブ・結合文字・絵文字で差分とカーソル位置がずれないようにする。

[`tools/gen-icon/gen_icon.py`](../../../tools/gen-icon/gen_icon.py)にyymergeの種類を追加し、既存の角丸背景、白いYY、下部の機能記号を流用する。記号は「左右の2本の流れが1本の結果へ合流する」形とし、色だけで識別させない。16／20／24／32／40／48／64／128／256pxを生成し、16pxでも合流が分かるか検証する。

[`apps/yyeditor/build.rs`](../../../apps/yyeditor/build.rs)のアイコン・manifest埋め込みを使い、ウィンドウ、タスクバー、Explorer、ショートカットで同じアイコンを表示する。新しい絵柄は既存の図形描画方式で作成する。同梱フォントと共通ヘルプ素材のライセンス・例外条項は既存アプリと同様に配布物へ含める。

## 12. 性能設計と評価

メモリーマップ、共有スナップショット、ストリーミング変換、疎な行索引、差分の範囲圧縮を用いる。全入力を`String`へコピーしたり、左右の全表示行をオブジェクト化したりしない。行内差分、画像の精細比較、構文色分けは表示範囲や選択範囲を優先して遅延計算する。

比較途中もペインを操作でき、取消はワーカーへ伝播する。メモリー予算、一時領域の上限、並列数、最大展開量を設定可能にする。予算を超えても結果を偽らず、正確な低速モード・範囲限定・中止を選べるようにする。

以下は実装前の目標で、測定値ではない。Windows 11 x64、8コア以上、32GB RAM、NVMe SSDを基準機とし、CPU・ストレージ・cold／warm・キャッシュ条件と入力分布を記録する。

| 項目 | 初期目標・測定方法 |
|---|---|
| 空のGUIの最初の表示 | warm p95 300ms以内。ヘルプ初期化は遅延させる |
| 100MiB×2、1%行変更の比較 | warm p95 5秒以内を目標。完了までと最初の差分までを別計測 |
| 1GiB×2のUTF-8比較 | 入力サイズに比例する全文複製を避け、比較用メモリー512MiBを既定予算とする |
| 数GBの入力・反復行・巨大な1行 | 正確な完了、または理由付きの未完了。上限超過を誤った同一判定にしない |
| スクロール・選択・分割位置変更 | 計算中もp95 33ms以内を目標。描画時間と入力待ちを計測 |
| 取消 | 通常I/Oでp95 200ms以内の反映を目標。OSのブロック中は取消要求済み状態を表示 |
| フォルダー10万ファイル | 確認済み件数を随時表示。走査・ハッシュ・差分の時間を分けて測定 |

同一条件で各段階の前後を比較し、速度と正確性の両方を評価する。既存エディター提案書の性能目標を、そのまま2／3入力の比較処理の実績として引用しない。

## 13. 独立CIと配布

yydbmanagerの分離方式に合わせて`.github/workflows/yymerge.yml`を設ける。`apps/yymerge/**`、`demo/yymerge/**`、専用workflowと、使用する共有クレート・共通build.rs・アイコン生成・ルートmanifest／lockの変更で起動する。

ルートの既存CIにはyymerge専用パスの`paths-ignore`を追加する。yydbmanagerの専用CIもyymerge専用パスだけでは起動させない。一方、共通クレートの変更では既存シリーズとyymergeの必要なCIを両方起動する。独立CIを理由に共有部品の回帰検証を省かない。変更対象外のPRに専用チェックの完了待ちを強制しないよう、必須チェックの設定も確認する。

| ジョブ | 主な検証 |
|---|---|
| Windows | fmt、clippy、コア・CLI・UI試験、両exeのreleaseビルド、配布物の起動 |
| Linux core／CLI | GUIなしビルド、同じfixtureの比較・マージ、stdin／stdout／終了コード |
| Windows shell | パス選択、複数ペイン、IME、差分・競合操作、リサイズ・DPI、保存と取消 |
| Git integration | 一時リポジトリーでdiff／merge、祖先なし、削除・変更、空白を含むパス、取消と終了待機 |
| Help／icon | F1、見出し、コピー、テキストフォールバック、各サイズのアイコン埋め込み |
| Performance | 固定seedデータ、nightlyまたは手動、大きなファイル・多数ファイル・画像、前回比 |

通常CIは外部サーバーを必須にしない。SFTP等はP2で専用の任意実行ジョブに分ける。共有cacheを他アプリの成果物で上書きせず、ワークスペース・OS・toolchainを含むキーにする。

配布物は`yymerge-windows-x64`として、コンソールexe、GUI exe、README、必要な共通ライセンスをまとめる。ヘルプとフォントは埋め込む。Gitや任意変換器の導入が必要な機能はREADME・ヘルプに示し、通常比較の起動条件に混ぜない。

## 14. 正確性・回帰テスト

- 2方向の等値、追加、削除、変更、空入力、終端改行、混在改行、バイナリー、不正バイトを網羅する。
- 3方向は片側変更、同じ変更、同位置への異なる挿入、削除対変更、移動・リネーム、祖先なし、空と欠落の違いを網羅する。
- 変更なしのマージが入力を保持すること、片側が祖先と同じなら他方を保持すること、差分の適用で対象を再構成できることを性質ベースで確認する。
- 小規模入力は独立した厳密比較実装と照合する。既存ツールやGitとの差は調査に使い、表示行の並べ方が異なるだけで不正と断定しない。
- 復元された原バイトと、規則適用後の同値を別々に試験する。非UTF-8、EBCDIC、全角、結合文字、NUL、巨大な1行を含める。
- フォルダーは大小文字衝突、リンク循環、読み取り不能、比較中の更新、失敗注入、一時領域不足、同期の中断・再開を検証する。
- CSVの項目内改行・引用符、複合／重複キー、数値精度、固定長の複数レイアウト、構造化データの未対応構文を検証する。
- GUIとCLIの同一入力・同一規則で判定が一致すること、CLIのstdoutに進捗が混ざらないこと、GUI終了待機と取消が正しく返ることを確認する。
- 保存失敗・取消・未解決で既存出力が変わらないことを、ファイル内容とハッシュで検証する。

## 15. 実装順序と完了判定

1. **基盤**：独立ワークスペース・専用CI・コアモデル・CLIの契約、共通UIとヘルプ・フォント・アイコンの接続。まだ高度な比較対応済みとはしない。
2. **P0テキスト**：厳密な2方向比較、仮想表示、行内差分、結果編集、符号化、保存、レポート、巨大入力の予算と取消。
3. **P0マージ／フォルダー**：祖先付き3方向、競合解決、2／3方向フォルダー、確認可能な同期計画、Gitアダプター、CLIのヘッドレス実行。ここまでを最初の実用版とする。
4. **P1高機能版**：移動・手動整列・詳細規則、表・固定長・構造化データ、バイナリー・画像、セッションの再開と拡張レポート。
5. **P2対象拡張**：ZIP、SFTP、Office／PDF、追加変換器。各形式の能力表と制限をヘルプへ反映する。
6. **各段階の性能再評価**：正確性、応答時間、メモリー、一時領域、取消、保存を測定し、既存yyシリーズの共有部品も回帰確認する。

最初の実用版の完了条件は、ファイルを開けることだけではなく、GUIとCLIで同じ判断をし、競合を解決して保存でき、未解決・未完了を正しく返し、ヘルプを参照して第三者が一連の操作を再現できることとする。
