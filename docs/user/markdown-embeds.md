# Markdownのインライン埋め込みと展開保存

Markdown文書の右側プレビュー（Ctrl+Shift+V）では、Wikiリンクの前に `!` を付けると、別のMarkdownの内容をその位置に表示します。
本文、表、箇条書き、コード、数式やMermaidなどは通常のMarkdownと同様に描画されます。
通常保存（Ctrl+S）は `![[...]]` を含む原文を保存します。

## 記法

| 記法 | 表示する範囲 |
| --- | --- |
| `![[共通ヘッダー]]` | 共通ヘッダー.mdの全文 |
| `![[parts/要件定義.md]]` | 指定した相対パスのMarkdown全文 |
| `![[要件定義#非機能要件]]` | 見出し自身から、次の同じか上位の見出しの直前まで。下位見出しも含む |
| `![[要件定義#^performance]]` | 明示したブロックIDの段落・リスト項目など |
| `![[#共通事項]]` | 現在の保存済みノート内の見出し。現在編集中の本文を使う |

ブロックIDは対象段落の末尾に、空白を挟んで付けます。

```markdown
応答時間は2秒以内とする。
同時接続数は1000以上とする。 ^performance
```

リストや表の後に空行を入れ、`^block-id` だけの行を置いて、その直前のブロックを参照することもできます。
同一ファイル内の見出し名・ブロックIDは一意にしてください。見出しの `{#id}` 属性でも指定できます。
コードブロック、インラインコード、HTMLブロック内の記法や、`\![[...]]` とエスケープした記法は展開しません。
埋め込み先からのさらに別の埋め込みも展開します。

## 探索するフォルダ

- 現在の文書の保存先フォルダと、そのサブフォルダ。
- yyeditor専用の `%APPDATA%\yyeditor\snippets` と、そのサブフォルダ。

「ファイル → Markdownスニペットフォルダーを開く」で専用フォルダを作成して開けます。
未保存のMarkdown文書ではスニペットフォルダのみ利用できます。文書を保存すると、その保存先フォルダも探索します。
埋め込み元はUTF-8（BOMあり・なし）のMarkdownで保存してください。拡張子を省略すると `.md` を補います。
`.markdown` などを使う場合は拡張子まで指定してください。

まず埋め込み記法を書いたファイルの隣、次に現在のノートの保存フォルダ、次にスニペットフォルダの指定パスを確認します。
その場所にない単純なファイル名は、両フォルダ以下を再帰探索します。同名候補が複数あれば自動選択せず、フォルダを含む指定を求めるエラーを表示します。
絶対パス、URL、親フォルダを指定する埋め込みや、許可範囲外を指すリンクは読み込みません。

埋め込み元は保存済みファイルから読みます。現在のノートを編集するか、他のアプリからyyeditorへ戻るか、プレビューを開き直すと再展開します。
ローカルのMarkdown文書が対象です。SSH文書からの埋め込みには対応していません。
ライブ編集の段落表示は原文を扱い、埋め込み結果の確認には右側プレビューを使います。

## インライン展開保存

「ファイル → インライン展開保存」で、すべての埋め込みを本文に置き換えたUTF-8の `.md` を別名保存します。
初期ファイル名は `元の名前-expanded.md` です。元のノート、参照元ファイル、現在のタブやUndo履歴を維持します。
元のノート・参照元への上書きは拒否します。未解決の参照・循環・制限超過があれば、保存を中止して理由を表示します。

プレビューでは埋め込み元の相対画像・通常リンクをそのファイルのフォルダを基準に解決します。
展開保存では、存在する許可範囲内の相対画像・通常リンクを元のファイルへの `file:` URLに直します。
画像本体などはコピーしないため、別のPCへ渡す場合は画像なども別途配布・パス調整してください。
未解決の画像・通常リンク、コード中やHTML中に直接書いたパスは変換しません。

## 上限とエラー

プレビューに埋め込みエラーを表示します。循環参照はファイルと見出し・ブロックの組合せで検出します。
埋め込みの深さは16、個数は256、参照元の読み込み合計・展開結果は各8 MiBまでです。
省略名の探索は合計20000項目、フォルダ深さ32までです。大きなフォルダでは相対パスを明示してください。
プレビューのスクロール同期では、埋め込んだ内容は原文の埋め込み記法の行に対応します。
