# フォルダサイズとWSL

「フォルダ」タブの詳細表示では、名前の隣に**合計サイズ**と**占有率バー**を常に表示します。フォルダを開くと一覧を先に表示し、サブフォルダをバックグラウンドで読み、結果を順次反映します。フォルダ内を操作したり、ほかの場所へ移動したりするために計算終了を待つ必要はありません。

## サイズと占有率

- 合計サイズはサブフォルダを含むファイルの論理サイズです。隠しファイルも集計します。ディスクの実使用量・圧縮後の量とは異なり、ハードリンクは名前ごとに数えます。
- 占有率は、今開いているフォルダ全体の集計量に対する割合です。絞り込み・隠しファイルの表示設定で分母は変えません。フラットビューでフォルダも出す場合、入れ子のフォルダの割合は重複するため、行の割合の合計が100%になるとは限りません。
- `計算中…` は未取得、`≈` は計算途中・前回のキャッシュ、`≥` は読めない部分を含む下限です。読めなかった項目は0バイトの完全な集計として扱いません。
- シンボリックリンク・ジャンクションはたどらず、合計に加えません。サイズ欄は「リンク」、占有率は「—」になります。
- 名前・サイズ・占有率を小さい画面でも表示できるよう、カラム幅を調整します。列の見出しでサイズ・割合順に並べ替えられます。
- メモリ内の短いキャッシュを使い、移動後も再確認します。フォルダの変更通知が利用できる場所ではサブフォルダの変更後にも再計算します。大量のファイル・ネットワーク・WSL上では完了に時間がかかります。Escで中止、F5で再計算できます。共有先が変更通知を提供しない場合はF5で更新してください。

## WSLへ移動する

左の「WSL」ツリー、または「PC」に表示される `Ubuntu（WSL）` などを開きます。登録されたディストリビューションを表示し、実際にその場所へアクセスしたときにWSLが起動します。PC画面でF5を押すとディストリビューション一覧も更新します。

アドレスバーには `\\wsl.localhost\Ubuntu\home\user` や `\\wsl$\Ubuntu\home\user` を入力できます。戻る・進む・上へ、ピン留め、絞り込み、コピー・貼り付け、移動、名前の変更、削除はWindowsのフォルダと同じ操作です。Linux側の名前の大文字・小文字を区別して選択します。WSLの権限やWindowsから扱える名前など、WSLの共有機能自体の制限は適用されます。

**`/mnt`とその配下のWindowsドライブも集計対象です。** Windows側のパスへ読み替えず、WSL共有経由で読み取り・操作します。WSL側から読めない部分は未集計となり、合計・占有率が不正確になる場合があります。ルートから全体を集計する場合、走査量が大きくなることがあります。`/proc`・`/sys`・`/dev`・`/run` は仮想領域としてルートの再帰集計から除外し「集計外」と表示します。その場所を明示して開いた場合は、その場所を起点に計算します。

## オーナーとパーミッションを変更する

1. WSL内のファイル・フォルダを1つ選び、右クリックの「WSLのオーナー・パーミッション」、またはAlt+Enterを開きます。フォルダ内の空白部分のメニューでは、そのフォルダが対象です。
2. オーナーとグループを、ユーザー名／グループ名または数値のUID／GIDで指定します。
3. 所有者・グループ・その他の読み取り／書き込み／実行をチェックします。8進数の欄と連動します。setuid・setgid・stickyも指定できます。
4. 必要なら「sudoで変更」を選び、sudoパスワードを入力して「適用」を押します。保存済みなら空欄のまま使えます。パスワード不要のsudo設定では空欄でも適用できます。通常権限で変更する場合はsudoのチェックを外します。
5. 変更後のLinux側の値を読み直し、実際に反映されたことを確認します。対象1件への変更で、配下への再帰的な変更は行いません。リンクや特殊ファイルの変更は対象外です。

sudoにはそのディストリビューションの既定ユーザーを使い、対象のオーナーにrootを指定しても実行ユーザーをrootへ切り替えません。適用中に対象の名前が別ファイルへ差し替わった場合は変更を拒否します。

必要なsudoパスワードは、適用成功後に**Windows資格情報マネージャー**へ、ディストリビューション・WSLユーザー別に保存します。Windowsユーザーごとの汎用資格情報 `yyeditor/wsl-sudo/...` です。引数・設定ファイル・操作ログには保存しません。「保存済みPWを削除」、またはWindowsの資格情報マネージャーから削除できます。

WSL側には`sudo`とGNU coreutils（`stat`・`chown`・`chmod`・`timeout`）が必要です。変更に失敗した場合は「再読込」で現在の値を確認してください。一部だけ変更されている場合があります。`/mnt/c`などのWindowsファイルでは、WSLのmetadataマウント設定とWindows側の権限も影響します。要求した値が反映されない場合、成功として扱わず案内します。

参考：[Microsoft WSLのファイル連携](https://learn.microsoft.com/en-us/windows/dev-environment/wsl-interop)、[WSLのファイル権限](https://learn.microsoft.com/en-us/windows/wsl/file-permissions)。
